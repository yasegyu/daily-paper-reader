## 摘要
传统大语言模型（LLM）局限于单个用户会话，其知识仅限于单一对话，无法学习用户随时间演变的偏好。现有的代理内存系统弥补了这一局限，但通常仅在单个用户层面运行，限制了可跨用户共享以改善下游响应的公共知识。我们提出AIM（代理互操作内存），一个统一的、隐私感知的内存框架，使多代理、多用户LLM系统能够持久管理私有和共享内存。AIM动态地将信息分类为私有（限于单个用户，其他用户不可访问）或公共（所有用户可访问）。它执行索引级访问控制，使得私有记忆仅能由其所有者检索，保护敏感数据，同时允许有益的共享知识改善协调和一致性。我们还引入了MUMBench（多用户内存基准），这是一个包含四个领域内私密和可共享信息的多用户交互数据集。据我们所知，MUMBench是第一个旨在多用户环境中评估多种内存操作（包括检索、创建、更新和删除）的公共数据集。在MUMBench上的三次独立运行中，AIM实现了96.0%的可见性分类准确率、58.8%的严格操作准确率和70.5%的状态感知操作准确率。

## Abstract
Traditional large language models (LLMs) are scoped to individual user sessions, limiting their knowledge to a single conversation and preventing them from learning user preferences that evolve over time. Existing agentic memory systems address this limitation but generally operate at the individual-user level, restricting the public knowledge that could be shared across users to improve downstream responses. We introduce AIM (Agentic Interoperable Memory), a unified, privacy-aware memory framework that enables multi-agent, multi-user LLM systems to persistently manage private and shared memory. AIM dynamically classifies information as private, scoped to one user and inaccessible to others, or public, accessible to all users. It enforces index-level access controls so that private memories are retrievable only by their owner, protecting sensitive data while allowing beneficial shared knowledge to improve coordination and consistency. We also introduce MUMBench (Multi-User Memory Benchmark), a dataset of multi-user interactions containing private and shareable information across four domains. To our knowledge, MUMBench is the first public dataset designed to evaluate multiple memory operations, including retrieval, creation, update, and deletion, in a multi-user environment. Across three independent runs on MUMBench, AIM achieves 96.0% visibility classification accuracy, 58.8% strict operation accuracy, and 70.5% state-aware operation accuracy.

## 2. 论文提出的方法论

### 2.1 核心思想
AIM（Agentic Interoperable Memory）是一个模块化、系统无关的统一记忆框架，核心思想为：
- 将记忆区分为私有（PRIVATE）与公共（PUBLIC）两类。
- 在索引层面（而非模型输出层面）强制执行访问控制，确保私有记忆对非所有者结构性不可见。
- 通过多标签意图检测支持单条消息同时触发多个记忆操作。

### 2.2 形式化定义
每条记忆 mi 包含：内容 ci、稠密向量 ei、所属用户 ui、所属代理 ai、可见性 vi ∈ {PUBLIC, PRIVATE}、标签集 τi、时间戳 ti 及元数据 μi。

**可见性谓词 V(u, m)：** 用户 u 可访问记忆 m 当且仅当 m 是公共记忆，或 m 是私有且属于用户 u：

```
V(u, m) = (v = PUBLIC) ∨ (v = PRIVATE ∧ u = m.owner)
```

更新和删除操作仅限创建用户（或创建代理）执行，实现多租户隔离。

### 2.3 技术流程（记忆生命周期算法）
AIM 将记忆管理分解为两条推理路径：

**（1）写路径：**
1. **多标签意图检测**：分类消息映射到 {CREATE, READ, UPDATE, DELETE} 子集或 NONE（支持多标签，如“我刚搬到旧金山，能给推荐晚餐地点吗”映射为 {C, R}）。
2. **结构化记忆提取**：LLM 以 JSON 模式解码提取内容、标签和元数据。
3. **隐私感知可见性分类**：LLM 根据显式规则（公共信号：集体事件、组织公告；私有信号：个人偏好、健康/财务数据）判定 PUBLIC/PRIVATE。
4. **上下文语义去重**：三分类判定（CREATE / UPDATE / NO-OP），比较集按可见性范围限定（公共记忆与所有公共记忆比较，私有记忆仅与同用户私有记忆比较），防止跨用户信息泄露。
5. **持久化存储**：存储时采用标签增强嵌入（内容与标签拼接后编码），使用 HNSW 图算法进行 ANN 检索。

**（2）读路径（三级级联检索）：**
- **Stage 1——可见性约束稠密检索**：将可见性谓词下推到向量索引层（服务端过滤），返回 top-k 候选，O(log|M|) 复杂度。
- **Stage 2——标签级语义重打分**：计算查询与标签的余弦相似度，需同时超过内容阈值和标签阈值，作为精度门控，激进剪枝候选集。
- **Stage 3——LLM 重排序+时间融合**：点式 LLM 评估相关性（0-1），采用保守评分原则（>0.7 须直接具体相关，不确定默认 ≤0.4），与归一化新近度分数算术平均得到最终排序。

**LLM 调用预算：** 仅 Stage 3 调用 LLM，且经过 Stage 2 剪枝后通常远少于 k 次调用。

### 2.4 模块化设计
所有组件（fop、fext、fcls、fdedup、嵌入模型、重排序器、向量索引）均通过抽象接口定义、配置驱动工厂实例化，可独立替换或禁用，便于消融研究。

## 3. 实验设计

### 3.1 MUMBench 基准（自建）
- **定位**：首个公开的、面向多用户环境下评估代理记忆系统多操作性能（检索、创建、更新、删除）的基准。
- **规模**：672 条经人工验证的按时间排序交互，涵盖 93 个用户。
- **领域分布**：编码（150 条）、客户支持（218 条）、教育（160 条）、旅行规划（144 条）。
- **操作分布**：205 次 CREATE、152 次 READ、117 次 UPDATE、77 次 DELETE、131 次 NOOP。
- **隐私分布**：150 条私有记忆、56 条公共记忆、60 条对抗性查询（试图访问他人私有信息）。
- **生成方式**：使用 GPT-4o 合成生成，并由人类研究者按验证清单逐步人工校验（保证时序、去重、操作/载荷正确性、隐私边界等）。
- **关键特性**：后续交互依赖先前写入的记忆，测试真实的有状态生命周期管理。

### 3.2 对比方法与数据集
- **MUMBench 上**：与其他代理记忆系统（如 LOCOMO、MemoryAgentBench）对比（这些为单用户基准）。
- **LOCOMO 数据集**：额外在单用户基准上对比 Mem0（以 GPT-4o-mini 为客户端，B1/F1/LLM Judge 为指标）。

### 3.3 评估指标（三层级）
- **严格准确率**：规范化后操作多重集合需完全匹配。
- **状态感知准确率**：考虑级联错误，根据预测系统实际状态，将期望操作放宽（如期望 UPDATE 但目标未创建则放宽为 CREATE）。
- **判定决策准确率**：全上下文 LLM 法官判定（exact/defensible/wrong），为非确定性操作提供容差。

### 3.4 内容与隐私指标
内容保真度（嵌入余弦相似度）、可见性匹配、标签重叠（Jaccard）、检索相关性（LLM 判定）。

## 6. 论文的主要结论与发现

1. **AIM 在多用户记忆管理上是有效的**：在 MUMBench 上，GPT-5.4-mini 取得最佳成绩——严格操作准确率 58.8%、状态感知 70.5%、判定决策 89.5%。
2. **隐私分类是 AIM 的最强能力**：所有模型可达 ~90% 以上，Travel 领域 3 个模型达到 100% 准确率。
3. **内容提取质量高**：最佳模型 Content Quality 91.6%，Content Fidelity 81.7%。
4. **较小模型可保持竞争力**：GPT-5.4-mini 在许多指标上最佳或接近最优，表明高质量记忆系统不必然依赖最大/最贵模型。
5. **级联失败效应明显**：严格 vs 状态感知准确率差距 ~12 个百分点，表明早期操作失误会传导至后续步骤。
6. **检索是当前瓶颈**：Retrieval Relevance 仅 45.0%，标签重叠 35.5%，这两个维度是最大短板。

## 7. 优点

1. **首次系统性解决多用户隐私感知记忆管理问题**：论文填补了一个明确的学术空白——既有多用户记忆系统（如 Collaborative Memory）已识别需求但未提供实现与基准，AIM 提供了完整端到端方案。
2. **索引级访问控制设计巧妙**：将隐私从“希望模型不输出”提升到“结构上不可检索”，比以往方法更可靠。
3. **多标签操作检测**：识别一条消息可同时触发写和读，更贴近真实交互。
4. **隐私保护与共享兼顾**：可见性分类同时指导去重范围、检索过滤和操作权限，一体化设计周到。
5. **MUMBench 贡献显著**：首个多用户多操作基准，包含对抗性查询，操作和隐私标注经人工三重验证，为社区提供标准化评估工具。
6. **模块化设计可扩展**：各组件接口化、配置化，可自由替换/消融。
7. **级联评估框架细致**：严格/状态感知/法官判断三层指标透明地暴露了错误传播效应。

## 8. 不足与局限

### 实验覆盖不足
- **无消融实验**：各组件贡献未经隔离验证，难以判断哪些模块是性能关键。
- **无多用户系统直接横向对比**：与 Collaborative Memory、INMS 等多用户记忆系统的定量比较缺失。
- **对抗性查询的隐私保护未见详细报告**：虽然数据里有 60 条对抗性查询，但未报告 AIM 在对抗性场景下的单独表现。

### 偏差风险
- **MUMBench 为合成数据**：尽管经人工验证，但交互模式、隐私边界可能与真实用户行为存在偏差，导致泛化性存疑。
- **标注主观性**：许多交互在公共/私有分类上真性模糊（论文自认），标注可能与实际期望不完全一致。
- **检索评估支撑样本极少**：部分领域仅 3 条匹配的读操作支撑 Retrieval Relevance，统计可靠性有限。

### 应用限制
- **LOCOMO 单用户场景表现弱**：AIM 在 LOCOMO 上大幅不及 Mem0（Judge 0.280 vs 0.671），说明其隐私分类与去重有过度合并问题，在单用户场景中是劣势。
- **公共记忆的完整性问题**：任何用户可创建/修改公共记忆，存在注入虚假信息的风险，目前尚未做事实校验。
- **标签提取策略需改进**：Tag Overlap 仅 35.5%，影响检索精度。
- **检索流程缺乏调优**：固定预过滤数量（5），未测试最优值。
- **更新/删除权限过于严格**：仅创建者可操作公共记忆，可能在需要协作更新公共知识时形成瓶颈。
- **未说明计算资源**：论文未报告 GPU 型号/数量/时长，影响可复现性和成本评估。
