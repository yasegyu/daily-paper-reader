## 摘要
视觉语言模型（VLM）智能体结合专门的感知、工具和推理来应对复杂的视觉任务。在多智能体环境中，不同智能体会检查不同的图像区域、视频帧或视觉表示，因此协作不仅扩展到分布式推理，还扩展到分布式感知。这使得共享视觉上下文成为 VLM 智能体协作的核心问题。在本文中，我们围绕协调不同解释和更新依赖推理的需求，构建记忆层次、跨智能体共享和一致性机制。有效的协作要求智能体基于其他智能体的贡献进行构建、恢复缺失的视觉上下文，并随着新证据的出现协调不同的解释。共享视觉记忆不仅保留图像或文本摘要，还保留观察、智能体解释与后续推理之间的依赖关系。这些设计考量共同决定了信息在 VLM 智能体之间如何流动与演化。所提出的框架为构建可靠且资源高效的智能体团队提供了基础。

## Abstract
Vision-language model (VLM) agents combine specialized perception, tools, and reasoning to address complex visual tasks. In multi-agent settings, different agents inspect different image regions, video frames, or visual representations, so collaboration extends beyond distributed reasoning to distributed perception. This makes shared visual context a central problem in VLM agent collaboration. In this paper, we frame memory hierarchy, cross-agent sharing, and consistency mechanisms around the need to reconcile interpretations and update dependent reasoning. Effective collaboration requires agents to build on contributions from other agents, recover missing visual context, and reconcile differing interpretations as new evidence emerges. Shared visual memory preserves not only images or textual summaries but also the dependencies among observations, agent interpretations, and subsequent reasoning. Together, these design considerations shape how information flows and evolves across VLM agents. The proposed framework provides a foundation for building reliable and resource-efficient agent teams.

## 1. 核心问题与整体含义（研究动机与背景）

### 问题定位
- **VLM 智能体的协作不只是分布式推理，更是分布式感知。** 不同智能体分别检查不同的图像区域、视频帧或视觉表征，因此"共享视觉上下文"成为 VLM 智能体协作的核心难题。
- 论文主张：这类协作引入了一个**独特的系统挑战**——中间的视觉观察与解释必须在跨智能体边界时保持**可访问（accessible）、可验证（verifiable）、可修订（revisable）**。
- 协作不只是交换答案：智能体需要发现别人观察到了什么、获取缺失证据、并在早先解释改变时回溯结论。

### 背景与驱动场景
- **流式视频**：需要及时响应的同时保持对早期上下文的访问。
- **病理切片审查**：需把千兆像素切片的局部细节与更大范围的组织上下文、相关报告结合。
- **航天器热真空测试（论文主用案例）**：单次测试处理 TB 级原始数据，温度历史、仪器图与需求表可能超出单个智能体的上下文窗口；异常调查有硬性截止时间而新测量持续到达。论文引用 JWST 综合科学仪器模块的低温真空测试（Kimble et al., 2016）作为现实依据。
- **图表/信息图任务**：需要把图形元素与标签、版式一起解释；一个智能体可高效处理小区域，但该区域可能缺少协作者所需的图例。

### 核心张力
- **专业化 vs. 共享理解**：局部工作所需的信息，可能不足以让协作者使用或核验其贡献。
- **视觉任务特有的一致性难题**：重新修订"柱-标签关联"会让另一智能体的比较结论失效，而**像素本身并未改变**。

### 与既有工作的关系
- 单智能体记忆研究关注上下文管理与结构化记忆记录（MemGPT、A-Mem 等）；近期工作开始研究跨智能体、跨模型的选择性记忆共享（INMS、G-Memory、DecentMem、MAGE、MemCollab 等）。
- 论文认为，对 VLM 团队而言还有**额外要求**：观察与解释必须与其视觉上下文保持链接，以便他人复用、验证并修订。

## 2. 方法论：核心思想与关键技术设计

论文不给出算法伪代码或形式化定义，而是提出一个**围绕"观察—解释—后续推理"依赖关系组织共享视觉记忆**的设计框架，包含三大支柱。

### 2.1 记忆层级（Memory Hierarchy）
- **三级结构**：
  - **智能体本地缓存（Agent-Local Cache）**：近期观察 + 模型特定特征。
  - **共享工作记忆（Shared Working Memory）**：证据、claims（论断）、未决请求（outstanding requests）；可读可写。
  - **持久化存储（Persistent Storage）**：可复用证据与团队经验；跨任务保留，支持 retain/retrieve。
- **关键设计原则**：**访问范围（access scope）与保留时长（retention lifetime）是两个独立的维度**；持久记录也可以是私有的；三个存储层不必物理分离。
- **流式视频示例**：一个智能体缓存近期帧并发布事件描述，链接到可检索的带时间戳片段；其他智能体检查更早片段或整合共享发现。共享工作记忆还必须区分"已检查区间"与"待检查区间"，以免把**延迟处理误判为无事件**。

### 2.2 链接表示（Linking Representations）
- 记忆中的表示类型：
  - **源图像/裁剪（Images/Crops）**：保留可见证据，使团队不必完全依赖文本描述。
  - **视觉特征（Visual Features）**：视觉编码器产生的向量。
  - **结构化观察（Structured Observations）**：带边界框的识别文本、表格单元格、区域间关联。
  - **Claims**：智能体所作解释的摘要。
- **核心观点**：这些表示**保留不同信息，不构成保真度的普遍排序**——裁剪可能遗漏远处的图例，而一段简洁的结构化记录可能完整描述某个比较。链接这些表示，才能让智能体从紧凑的 claim 走到验证所需的上下文。
- **溯源（Provenance）**：记录来源区域、贡献智能体、该解释所引用的先前观察。例如"探测器峰值 38 K"这一 claim 必须同时链接到柱条与图例关联。
- **机制支撑**：稳定源标识符 + 坐标支持检索；解释之间的显式链接支持后续修订。

### 2.3 选择性共享（Selective Sharing）
- 共享上下文的**数量与形式取决于接收智能体被分配的工作**。
  - 例：D 依据 C 给出的上限检查温度时，需要组件、测试阶段、区间、峰值、单位、来源引用；而要检查关联本身，则需要 B 同时查看柱条与图例。
- **共享策略**依据当前操作、模型接口、可用工具、预算来选择相关证据与合适的表示。
- **访问接口**需标识：表示类型、来源、正在读取的解释版本，以及检索证据所需的权限。

### 2.4 跨模型共享（Sharing Across Models）
- 视觉交换与适配器（adapters）支持超出自然语言的通信；Vision Wormhole 通过编码器/解码器在不同 VLM 家族间传递潜在推理。
- 复用已编码视觉特征可减少重复视觉处理，但不同 VLM 在特征维度、位置编码、输入接口上各异。
- **可行方案**：用适配器把存储特征映射到接收模型的输入空间，同时保持共享表示固定；若接口不暴露特征输入，接收方只能使用图像或其他表示。
- **价值判据**：跨模型特征复用必须保留与视觉源的链接；其价值取决于**协作推理质量与总成本**（适配、编码、检索、重复检查之和），而非仅看兼容性或压缩率。

### 2.5 一致性与调和机制（Consistency and Reconciliation）
- **调和解释**：一致性取决于智能体解释是否基于**兼容的证据、源状态与上下文假设**。冲突可能源于检查了不同区域、帧或源版本，因此调和须先确认冲突是否真的条件于同一证据与上下文。
- **关键警告**：**"一致同意"不等于"独立确认"**——多个智能体可能继承同一个错误解释。共享记忆应保留每个智能体检查过的证据及其派生解释，通过**证据级调和 + 定向重检**解决冲突。
- **修订依赖推理**（以案例说明）：
  - B 起初把镜面峰值 47 K 误归给探测器 → D 标记违反 40 K 限值；
  - B 对照 A 的图例重检已保存的柱条，将探测器关联改为 38 K；
  - D 必须用 C 未变的限值**重算**比较（38 < 40）；
  - 若不重算，共享记忆会同时存在修订后的关联与基于旧版本得出的结论。
  - 论文借用**真理维护（Truth Maintenance, Doyle 1979）**的思想，提出把派生 claims 链接到支撑性解释，使贡献智能体可请求审查依赖结论；**但审查请求只标识"需审查的工作"，并不确立替代答案**。
- **共享修订**：若 D 已在基于早期解释推理，仅更新共享记录**不会更新 D 的本地上下文**；D 在发布结果前应检查所用 claims 是否仍与存储一致。并发冲突 claims 应保持可区分，而非静默覆盖。
- **可靠性与同步权衡**：等待所有观察验证会拖慢协作，使用未验证 claims 会传播错误；实用策略需在延迟与错误传播间平衡。记录依赖支持选择性审查，但**缺失链接会导致受影响结论未被检查**，此时需要更广泛的重检。此外，**记录下发给智能体的输入，并不等于模型实际使用了这些输入**；一组自洽的记录仍可能是错的，验证本身也可能引入错误。

## 6. 主要结论与发现

- VLM 智能体团队**同时分布感知与推理**，因此共享视觉上下文是协作的必要条件，而非附属功能。
- 应将**记忆层级、跨智能体共享、一致性机制三者联合设计**，以维持"观察 → 解释 → 下游推理"之间的依赖关系。
- 共享视觉记忆不能只保存图像或文本摘要，还必须保存**依赖关系、溯源信息与版本可区分性**。
- 修订可能发生在**像素不变**的情况下（如柱-标签关联改变），因此一致性机制必须能追踪关联变化并触发依赖结论的复核与重算。
- 一致同意不等于独立确认；记录输入不等于模型实际使用；记录自洽不等于记录正确。
- 该框架为构建**可靠且资源高效**的 VLM 智能体团队提供了基础，并强调共享视觉记忆对信息流动与协同推理演化的关键作用。

- **案例单一且示意性**：仅以航天器热真空测试一例（含 4 个智能体、单次温度比较）贯穿说明，该例规模小、结构简单，无法反映真实多智能体系统中可能出现的并发、级联修订、部分失效等复杂情形；对其他驱动场景（流式视频、病理切片、图表理解）仅一笔带过。
- **与既有工作的区分度有限**：第 5 节以文献罗列为主，未系统对比本框架与 INMS、G-Memory、DecentMem 等已有记忆共享方案在**机制层面**的具体差异，读者难以判断其新颖性的确切边界。
- **失败模式分析不足**：虽提及"缺失链接会导致受影响结论未被检查"，但未系统梳理共享记忆可能引入的失效模式（如错误传播的放大、调和死锁、版本爆炸），也未讨论缓解手段。
- **权限、隐私与安全未展开**：仅在访问接口处提到"权限"，未讨论多机构/多用户场景下的隐私隔离、访问控制、恶意贡献者等现实问题——而论文作者本身横跨多机构，这一缺失尤为明显。
- **评估路径缺位**：第 6 节虽提出"正确性 + 通信/处理成本"的联合反馈，但未给出可操作的评测设计、指标定义或基准构想，后续研究者仍面临"如何验证"的空缺。

## 9. 对读者的启示与适用性

- **适合读者**：多智能体系统、VLM 应用、长上下文/记忆架构、以及需要跨模型协作的工程与研究者。对希望从"堆叠智能体数量"转向"设计协作记忆基础设施"的团队尤具参考价值。
- **可借鉴的设计原则**：
  1. 把**访问范围**与**保留时长**视为正交维度，避免"持久=公开"的默认假设；
  2. 记忆条目须携带**溯源**（来源区域、贡献者、所引用的先前观察）；
  3. 共享工作记忆应区分"已检查区间"与"待检查区间"，防止**延迟处理被误判为无事件**；
  4. 派生结论须链接到支撑解释，以支持**定向重检与重算**；
  5. 并发冲突 claim 应**保持可区分**，而非静默覆盖。
- **使用建议**：将本文当作**设计空间地图与研究议程**阅读，而非可直接落地的技术方案。若需实现，需自行补充形式化定义、接口规范与成本模型，并设计实证验证。
- **后续研究方向**：①记忆与任务分配的联合学习（与固定角色+按需请求上下文的方案对比）；②从重复协作中提炼可复用经验，并明确其适用条件与维护成本边界；③建立能同时衡量正确性与通信/处理成本的评测方法。

## 10. 一句话总结

本文是一篇**立场/愿景论文**，主张 VLM 多智能体协作的本质是"分布式感知 + 分布式推理"，因而共享视觉记忆必须同时保存**依赖关系、溯源信息与版本可区分性**；它精准刻画了问题与设计空间，并以清晰的修订案例说明"像素不变而解释改变"所带来的一致性挑战，但**通篇无实验、无形式化、无成本量化**，其价值在于提出问题与组织议程，而非提供已验证的解决方案。
