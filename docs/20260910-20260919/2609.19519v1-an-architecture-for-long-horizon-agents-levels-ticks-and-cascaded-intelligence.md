## 摘要
语言模型智能体越来越常被要求执行跨越数天或数周的工作，例如运维修复或研究项目。这类任务超出了任何上下文窗口、任何进程以及任何人能够关注的时间间隔。在本文中，我们认为，长时程智能体必须在持续遗忘之前持续不间断地运行，才能进行持续学习。这种能力存在于模型周围的框架（harness）中，而非模型本身。我们从长时程场景中推导出七个瓶颈，并用由三部分组成的层次架构来应对这些瓶颈：（i）按时间尺度索引的层次，每一层维护一个有限的摘要文件，概括下一层的内容；（ii）一个时钟驱动的节拍（tick），作为自主行动的单位；以及（iii）级联智能，即只有在评审失败后，工作才会升级到更强大的模型。我们报告了一项为期十天的活动，在该活动中，基于此架构构建的智能体成功复现了一个已发表的强化学习结果，并且人类每天只参与一次。我们展示了（1）该智能体在活动的每次上下文重置和会话边界上都保持了任务主线；（2）早期写入的操作知识在不改变模型权重的情况下改变了后续行为；（3）学习组件将如何进入此类系统。总体而言，我们的经验表明，这类智能体的持续学习需要一个超越所有上下文和进程的支撑基座，而框架已经运行的检查正是学习者应归属之处。

## Abstract
Language-model agents are increasingly asked to carry out work spanning days or weeks, such as an operations remediation or a research programme. Such a task outlives any context window, any process and any interval at which a person can attend. In this paper, we argue that a long-horizon agent must run continually without forgetting before it can learn continually. This ability lies in the harness around the model rather than in the model itself. We derive seven bottlenecks from the long-horizon setting and answer them with a hierarchical architecture of three parts: (i) levels indexed by time scale, each keeping a bounded file summarising the level below; (ii) a clocked tick as the unit of autonomous action; and (iii) cascaded intelligence, where work is escalated to a more capable model only after failing review. We report on a ten-day campaign in which an agent built on this architecture reproduced a published reinforcement-learning result with a human attending once a day, and show (1) the agent kept the thread across every context reset and session boundary of the campaign, (2) operating knowledge written early changed later behaviour with no change to model weights, and (3) where learned components would enter such a system. Overall, our experience suggests continual learning for these agents needs a substrate outliving every context and process, and the checks the harness already runs are where a learner belongs.

## 2. 方法论：核心思想、关键技术细节

### 2.1 基本框架：两个轴与七个瓶颈

**两个轴**：
- **自主性（Autonomy）**：智能体无需人参与而自行做出的决策比例。高自主性意味着智能体持有目标、自行决定何时及如何行动、持续工作直至目标达成。
- **视界（Horizon H）**：智能体必须维持的轨迹长度，以动作数、token数或按动作速率折算的墙钟时间度量。

**四个阈值（沿视界轴）**：上下文窗口 C、进程生命周期 P、人的关注间隔 A、组件故障间隔 F。高自主性意味着无人能吸收这些阈值被穿越时的冲击，每个阈值都成为架构需求。

**七个瓶颈**：
| 瓶颈 | 来源 | 需求 |
|---|---|---|
| Autonomy（自主性） | A ≪ H | 自主时钟、目标、策略，在人的缺位期间持续运行 |
| Horizon（视界） | C ≪ H | 按时间尺度组织的压缩表示上进行操作 |
| State（状态） | P ≪ H | 任何状态不能只存在于上下文中；可从文件中重建 |
| Delegation（委派） | 工作量超出一个进程且在 A ≪ H 下无人交接 | 契约、运行中引导、向上决策 |
| Correctness（正确性） | 自主×视界：无人检查每步、错误累积且压缩掩盖证据 | 能经得起压缩的验证机制 |
| Resilience（韧性） | F ≪ H：所有组件在活动中都可能失败 | 失败在每一层预期并根据协议处理 |
| Cost（成本） | 自主×视界：顶级模型花费 ∝ H 且受预算 B 限制 | 有规则地在层级间迁移工作的级联智能 |

### 2.2 四个核心抽象

1. **Level（层级）**：按时间尺度索引的系统层，维护一个有界的压缩文件来概括下方层级，并向下发出稀疏指令。共七层：
   - L0（工具调用，秒级）、L1（劳动，分钟级）、L2（引导，30–60分钟）、L3（tick，约1小时）、L4（门审查，5 tick）、L5（人类，每天）、L6（目标，每周）。
2. **Tick（节拍）**：智能体在判断层自主行动的单位——驱动会话（driver session）的一次唤醒，从读取状态到写回状态的完整循环。AI 驱动的是判断层的会话，负责运行主循环。
3. **Protocol（协议）**：具有指定写入者、读取者、节奏和检查的命名文件。每个通道和每条持久状态都是一项协议。
4. **Tier（智能层级）**：判断层（judgment tier，即驱动所在的层）、劳动层（labor tier，routine 或 strong 子类，会话称为 worker）和确定性过程（deterministic processes）三个智能级别，级别随层级上升。

### 2.3 七大机制族

**① Autonomy（自主性）**：必须“制造”主动性。一个时钟启动新的驱动会话，在驱动退出前写入的下一个唤醒间隔期满后再次启动。tick 读取状态、应用所有预注册规则、决策、执行、写回状态。一个 hook 在 tick 级状态文件（checkpoint）写入前拒绝结束会话。主体的答案作为**standing decisions**保存，每次唤醒都要读取，从而使智能体在主缺席时仍能持续推进。

**② Horizon（视界）**：通过按时间尺度索引的抽象来处理数天的视界：每一层只看到下方层的有界压缩，按自身节奏行动；驱动从不直接读取原始输出。硬性规则：任何日志或源代码最多读 40 行，其余委派和处理。

**③ State（状态）**：所有状态必须以文件形式存在，不可只存在于上下文中。每层状态文件有界（以保证上层可读）、原地覆写（描述当前状态）、每个数字都标明来源文件。**恢复协议**：在每次会话开始和驱动上下文每次压缩后执行——先读 checkpoint，然后 standing decisions、计划、未解决问题、活跃实验卡；若 append-only 日志比 checkpoint 新，以日志为准。

**④ Delegation（委派）**：工作向下作为**合同**传递并以**证据**返回；决策向上传递，最终到主体。一个 brief 是一个文件，含：任务、目标、层级、要读的文件、约束、要返回的内容。开放型工作在 steered labor 模式下增加两个文件：worker 写 **PROGRESS**（每次试验前计划、试验后测量结果），驱动按引导节奏写 **DIRECTIVE**（数字支持哪个假设、下一步试什么），worker 在每次行动前都要重读。决策沿梯子（ladder）上升，每个梯级有明确的触发条件：routine labor → 驱动自身评估 → strong-tier 会话 → 主体（仅限特定决策类别）。

**⑤ Correctness（正确性）**：验证必须预先注册、可测量、结果不可丢失。每张实验卡包含：假设、成功标准、提前停止规则、资源配置上限、随机种子。驱动在每个 tick 应用停止规则，使“终止判定”是摘要中的一个比特。**对抗性评审者（adversarial reviewer）**：一个无对话历史的判断层会话，在每个 gate（预先注册的检查点，在计算或声明前执行）读取计划和证据，检查：哪些混淆变量仍然开放、代理指标是否测量了声明对象、应该终止什么。

**⑥ Resilience（韧性）**：任何组件在数天内都会失败，恢复不能依赖人的关注。每层有上一层的检测器和无判断的恢复流程：停滞的 worker 被重新简报，死掉的驱动从 checkpoint 在 watchdog 下恢复，反复重启则停止；探针作为被观察作业的步骤运行，而非独立登录。

**⑦ Cost（成本）**：最强模型只接触最压缩的状态。层级间移动工作的规则是**review-and-escalate（评审并升级）**：工作在最便宜且有可能完成的层级执行，上一层评审，失败则以反馈返回重试，再次失败则升一个层级，直到主体（图3）。强层级的分配依据是“出错代价”而非任务大小。梯子是对称的：强层级找到配方后，后续任务在 routine 层级以其 brief 中的配方执行。会话每几轮 tick 轮换，全新会话读取短 checkpoint；一个确定的 pre-tick digest 在无事项到期时跳过唤醒。

### 2.4 不遗忘性与积累

- **不遗忘**：模型不进行参数式的持续学习，但满足两个较弱属性。由于没有智能体需要的东西只存在于上下文中，压缩擦除的约束可以依赖于文件系统而重建。驱动在活动中被重置数十次（压缩、轮换或 watchdog），每次都从文件恢复。
- **积累**：操作知识在一层写入，改变下方各层在活动剩余期间的行为——主体的回答变为 standing decisions；评审发现变为后续卡片的预注册规则；强层级找到的配方下放到 routine brief；反复出现的 worker 失败成为所有 brief 中的规则并最终成为框架中的守护。这是积累而非学习，但恰恰指出了学习组件应放置的位置：在保持不变的 gate 内部。

  1. 环境搭建；
  2. 小规模下的稳定性对照（未修正 vs 修正，跨种子）；

## 6. 主要结论与发现

1. **层次架构是构建长时程智能体的有效途径**：10天活动成功完成，智能体在每天仅1次人类关注下复现了一个已发表的 RL 结果。
2. **不遗忘性成立**：智能体在每次上下文重置和会话边界都保持了任务主线。现场记录显示，驱动上下文经历了47次重置（压缩、轮换、watchdog），每次都从文件中恢复且不丢失目标。
3. **积累而非仅记忆**：早期写入的操作知识确实改变了后续行为——无需改变任何模型权重。三个典型例子：
   - **Steered labor**：三个未受引导的 worker 会话卡在 958 秒/步无诊断；驱动写入了6个带预测和守卫函数的排序假设，每30分钟发一条 directive，引导一个 worker 在单个有界会话内将步时间降至 180 秒，且无需 strong tier。
   - **评审者发现**：当有效性对比饱和时，评审者发现验证器可能被绕过而不解决实际任务，且存在两个可被模型短路的家族；任务混合被重建。此后又发现一个计划中的停止规则会使某臂与其对照的瞬时下降比较，该规则在结果记录前被重写。
   - **知识积累为框架规则**：worker 在拥有活跃运行作业时不得结束其会话——第一次作为规则写入每个 brief；第二次升级为框架终止守卫，阻止拥有活跃运行的 worker 结束，此后不再复发。
4. **学习组件的插入位置明确**：检查（gate）是学习组件的插入点——学习到的策略（tier 分配、唤醒间隔）替代保持不变的检查中的书面规则，使学习受框架验证约束。记录本身就是数据集（checkpoint、评审结果、卡片结论、判定）。
5. **无需学习也能积累**：纯写下的层次式记忆本身就能跨重置保存知识，这是任何更新权重的方法必须超越的最低基线。

- **实证经验丰富**：10天、40+实验、403个worker会话的记录提供了充分的证据，并通过多个典型案例具体呈现架构机制的运作方式。
- **定位和边界诚实**：明确将自己定位为“存在性证明”而非系统性基准，避免过度声称。
- **对持续学习社区具有启发价值**：明确到“checks 是学习者应嵌入之处”的结论，对未来的集成学习和架构改进提供了清晰方向。
- **成本控制机制完整**：cascaded intelligence 的 review-and-escalate 机制同时处理了成本和正确性，routine（86%）/strong（14%）的实际花费分布证明该机制在成本控制上有效。

## 8. 不足与局限

- **单一案例、单一任务领域**：仅一个研究任务（复现 RL 结果）的验证；作者明确承认这是既定基准的替代而非全面基准评估。不同领域（如运维、合规）的表现仍需更多案例验证。
- **缺少系统化的基线对比**：没有与更简单的记忆方法（如 MemGPT、生成代理式记忆）、单上下文方案或定期摘要重起的随机响应策略做受控对比，难以量化各机制族的独立贡献。没有消融研究（例如去掉 adversarial reviewer、去除 standing decisions 等）。
- **数据规模有限**：仅两种模型规模（未指定具体模型）、约40次实验、4次环境重新设计，统计显著性未报告（在 RL 中，尤其涉及随机种子的稳定性测试，缺乏种子数说明）。
- **评估标准的“自我实现”风险**：任务选择和成功标准部分由运行驱动会话设置（例如校准环境的成功标准、任务混合的重新设计），可能与自然研究活动的真实分布不完全一致。
- **对“不遗忘”的证据是叙述性的**：主要依赖“驱动被重置47次但保持了主线”的叙述和经验记录，未量化遗忘程度或对任务纵深的保持率。
- **标注中的日期和引用存在保留**：论文标注日期为 2026 年 9 月，部分引文年份为 2026 — 内容的最终可核验性有待后续确认。
- **缺少对失败成本的讨论**：虽然环境有防错阀（watchdog、kill rules），但未讨论出现不可恢复失败的场景、失败的严重性分布以及恢复机制是否在极端条件下失效。
- **对成本机制的具体数值估算未展开**：未提供 tier 路由决策的成本函数定义，也缺乏对 cost-accuracy 权衡的定量分析。
