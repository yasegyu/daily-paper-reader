## 摘要
LLM 智能体通常缺乏在新环境中可靠行动所需的操作知识，因为它们必须自行发现具体的工具行为或环境约定。若没有对过去尝试的记忆，它们会在不同任务中重复同样的错误，导致更多任务失败和更长的轨迹。为解决这一问题，智能体系统通常依赖人工编写的指南，或依赖由训练任务和预言机验证器构建的程序性记忆，而这两者都需要关于环境的先验知识。我们提出 DAEDALUS，一种无需已有任务或预言机验证器、从自生成练习中自举可复用智能体记忆的方法。DAEDALUS 将两个智能体配对：探索者与环境交互以生成具有挑战性但仍可解决的任务，求解者则尝试解决这些任务。每次求解失败都会导出一条启发式规则，并且只有当求解者在上下文中反复使用该启发式规则并成功后才接受它。这些结果也为探索者提供反馈，以调整未来任务的难度。被接受的启发式规则随后被整合为一个记忆库，供测试时使用。在 AppWorld、τ^2-bench 和 AutomationBench 上，DAEDALUS 相比无记忆基线将平均成功率最高提升 15.9 个百分点，并将 pass^5 最高提升至 2.2 倍，同时与使用训练任务的方法相比具有竞争力，且推理成本低于大多数方法。我们表明，即使探索预算很小，性能增益也已出现，并且其启发式规则也能使其他模型家族的智能体受益。我们的消融实验进一步揭示，求解者轨迹提供了推导有效启发式规则所需的关键信息，而将早期发现分解则使探索更具成本效率。除构建记忆之外，我们发现 DAEDALUS 生成的任务可以在按性能对模型排序时作为基准任务的代理。代码与工件：www.github.com/illuin-tech/daedalus。

## Abstract
LLM agents often lack the operational knowledge to act reliably in new environments, as they must discover specific tool behaviors or environment conventions on their own. Without memory of past attempts, they repeat the same mistakes across tasks, leading to more task failures and longer trajectories. To address this, agentic systems typically rely on human-written guidelines or on procedural memory built from training tasks and an oracle verifier, both of which require prior knowledge of the environment. We present DAEDALUS, a method for bootstrapping reusable agent memory from self-generated practice without existing tasks or oracle verifiers. DAEDALUS pairs two agents: an explorer that interacts with the environment to generate challenging yet solvable tasks, and a solver that attempts them. A heuristic is derived from each solver failure and accepted only after the solver repeatedly succeeds with that heuristic in context. These outcomes also provide feedback for the explorer to refine the difficulty of future tasks. Accepted heuristics are then consolidated into a memory bank for test-time use. Across AppWorld, $τ^2$-bench, and AutomationBench, DAEDALUS improves mean success rates by up to 15.9 points and pass^5 by up to 2.2x over a no-memory baseline, and is competitive with methods using training tasks, at a lower inference cost than most. We show that performance gains already emerge with a small exploration budget, and that its heuristics also benefit agents from other model families. Our ablations further reveal that solver traces provide the key information needed to derive effective heuristics, while factorizing early discoveries makes exploration more cost-efficient. Beyond memory construction, we find that the tasks generated by DAEDALUS can serve as a proxy for benchmark tasks when ranking models by performance. Code and artifacts: www.github.com/illuin-tech/daedalus.

## 1. 核心问题与研究动机

- **背景**：LLM 智能体正被广泛部署于真实职业与行业场景，需在缺乏人工指导的复杂环境中自主行动。可靠行动依赖跨任务可迁移的"操作知识"（如某工具 API 的确切行为、环境的约定与陷阱）。
- **问题**：缺乏程序性记忆时，智能体会在每个任务中重新"发现"环境，重复犯同样的错误，导致失败率上升、轨迹变长、成本增加。
- **现有方案的瓶颈**：
  - 主流做法（ExpeL、AutoGuide、ERL、ReasoningBank、ACE 等）需要**人工整理的训练任务**，并常配一个**预言机验证器**打分，这要求对目标环境有先验知识，而大量新环境（尤其是自动生成的智能体环境）并不具备。
  - 另一类做法是从测试时到达的查询中积累经验，但智能体最初几个任务必须在无记忆状态下执行，只能"先失败再改进"。
  - 最接近的 PREPING 虽也自生成任务，但其任务筛选偏向"可行/覆盖广"，而非"能暴露可学习的失败"。
- **核心主张**：提出 **DAEDALUS**，一种**免训练（training-free）** 方法，在既无策划任务、也无预言机验证器的条件下，仅通过自生成练习自举出可复用的环境特定记忆。

## 2. 方法论

### 2.1 核心思想
- 预算是**一次性的 n 次练习会话（practice sessions）**，产出一个冻结的**文本启发式记忆库**，在测试时一次性注入基座智能体上下文，**不更新模型权重**。
- 关键创新在于**记忆的验证方式**：一条启发式只有在"它把一次失败转化为连续多次成功"后才被接受，而非依据其来源轨迹的成败来判断。

### 2.2 多智能体角色分工
| 角色 | 职责 |
|---|---|
| **Surveyor（勘测者）** | 一次性探索环境，给出任务覆盖的"轴"与目标分布（含标签清单），保证任务多样性 |
| **Explorer（探索者）** | 与环境交互，提出真实、可解、难度适中的任务，并自行完成以确认可行性；可多次精炼任务难度 |
| **Solver（求解者）** | 在重置环境中尝试任务，携带当前启发式重试 |
| **Judge（裁判）** | 用 LLM 依据成功条件判定轨迹成败（不接触官方验证器） |
| **Extractor（提取者）** | 从失败轨迹写出/修订启发式（**不告知它漏掉了哪条成功条件**，以抑制任务特定补丁、鼓励泛化指导） |
| **Consolidator（整合者）** | 单次 LLM 调用合并所有被接受的启发式，去重去冗，形成最终记忆库 |

### 2.3 Solver Loop（算法流程，文字描述）
1. 重置环境，Solver 带当前启发式 h（初始为空）尝试任务 τ=(u, σ)（u 为指令，σ 为成功条件）。
2. Judge 判定是否通过；通过则 `streak+1`，失败则 `streak=0`、`failures+1`，并调用 Extractor 修订 h。
3. 循环终止条件：`streak = Ns`（连续成功数）或 `failures = Nf`（累计失败上限）。
4. 三种结局：
   - `streak=Ns` 且 `h≠∅` → **accepted**（启发式入银行）；
   - `streak=Ns` 且 `h=∅` → **too_easy**（从未失败）；
   - `failures=Nf` → **too_hard**。
- **接受规则的意义**：要求 Ns 次**连续**成功（而非单次），降低"偶然成功误纳无效启发式"的概率。

### 2.4 任务难度校准
- Solver Loop 的结果同时作为**难度信号**反馈给 Explorer：too_easy → 加难；too_hard → 降难；最多精炼 Nr 次，耗尽则本会话不产出启发式。
- 使任务分布逼近求解者能力的"边缘"，即失败可恢复的区域。

### 2.5 生成效率优化
- **环境勘测（Survey）**：Surveyor 定义目标任务分布，Explorer 据此选题，减少选题探索开销并提升覆盖多样性。
- **任务设计指南库（Guidelines）**：将每次精炼历史压缩为通用设计准则，帮助后续会话更快命中目标难度（减少精炼次数与成本）。

### 2.6 部署
- 最后一轮由 Consolidator 合并启发式，得到**冻结记忆库**，在每个测试任务开始时**一次性整体注入**系统提示（`ALL@START`）。

### 2.7 超参数（主实验设置）
- 会话数 n=90；任务精炼上限 Nr=5；失败上限 Nf=8；连续成功数 Ns=3；Explorer 单会话 40 轮；并发 Explorer 5 个。

## 6. 主要结论与发现

1. **无训练任务方法中最强**：相比无记忆基线，MSR 分别提升 **15.9 / 10.0 / 4.3** 点（AppWorld / τ²-bench / AutomationBench），pass^5 提升 **1.7×~2.2×**；全面优于 PREPING。
2. **可与使用训练任务的方法竞争**：在 6 个 MSR/pass^5 列中有 4 列处于误差范围内；仅在 AppWorld pass^5 落后 ACE、AutomationBench MSR 落后 ExpeL；且从未跌破无记忆基线（ACE、ReasoningBank、AutoGuide 会跌破）。
3. **自生成任务能恢复大部分策划任务的收益**：DAEDALUS 仅比 DAEDALUS-curated 低 0.6 / 2.5 / 4.0 MSR 点。
4. **跨模型家族可迁移**：9 组迁移增益全为正，GPT-5.4-mini 从 Qwen 银行获得的增益（+16.8）甚至略高于自身家族（+15.9）。
5. **验证是性能提升的主因**：仅靠探索的启发式（变体 A/B）**反而低于无记忆基线**；加入 Solver 轨迹带来 +15.8 MSR 的最大跃升，加入 Solver Loop 验证再带来 +4.5 MSR。
6. **指南库与勘测主要提升效率**：两者合计降低生成成本 48%，将接受率从 86.7% 提升至 97.8%，精炼次数从 183 降至 118。
7. **小预算即可见效**：仅 5 个会话就达到 90 会话峰值收益的一半以上。
8. **推理期最佳策略是"整体注入"**：合并后整体注入（60.2 MSR）显著优于每轮检索 top-k（最高 58.2）；检索器选择在 k=5 时无显著差异，说明启发式的相关性是"隐式/斜向"的，而非语义相似。
9. **生成任务可作评估代理**：9 个模型在生成任务与 AppWorld 官方测试集上的排序高度一致（Kendall τ=0.89，p<.001，36 对中 34 对一致）。
10. **超过 90 会话后性能下降**：银行增大反而使 MSR 从 60.2 降至 53.7，分层合并也无法恢复（54.6），主要源于少数启发式在整合中**丢失适用范围**。

## 7. 优点

- **问题设定切中要害**：明确指出现有记忆方法对"训练任务 + 验证器"的隐性依赖，并给出真正无监督的替代路径，对自动生成环境尤其有价值。
- **验证机制设计严谨**：要求启发式**连续 Ns 次成功**才被接受，并有反事实重放（配对 bootstrap，95% CI 排除 0）作为独立佐证；同时刻意不告知 Extractor 缺失的成功条件，抑制过拟合。
- **完整的角色分工与效率优化**：Surveyor 保证覆盖多样性、Guidelines 传递难度校准经验、Consolidator 压缩银行，形成闭环且成本可量化。
- **实验体系庞大且诚实**：包含累积消融、缩放曲线、跨家族迁移、judge 一致性、多种检索/注入策略对比，并主动报告**性能随预算下降**这一负面结果与失败原因分析。
- **实用价值延伸**：发现生成任务可作模型排序代理，为无测试集的环境提供评估方案。
- **可复现性强**：公开代码、prompt、生成任务、启发式银行与全部智能体轨迹。
- **成本友好**：AppWorld 与 τ²-bench 上推理成本与无记忆基线持平（因所需轮数更少）。

## 8. 不足与局限

- **记忆生命周期封闭**：银行在部署前一次性构建并冻结，不支持测试时更新；作者尝试的迭代更新方案未取得稳定增益。
- **环境假设受限**：要求 Explorer 能在可重置环境中**独立**设置并完成任务；**双控制场景**（如 τ²-bench telecom 需模拟用户同时操作环境）暂不支持。
- **验证信号不完美**：仅依赖 LLM Judge 对自写成功条件打分，与官方验证器的一致性虽达 κ=0.73~0.81，但仍非可靠；对代码类任务可考虑可执行验证器替代或补充。
- **规模扩展性问题**：银行超过约 90 条启发式后性能下降，单次整合调用会**误改启发式适用范围**，分层合并亦未能修复，说明大规模记忆的整合与检索仍是开放问题。
- **检索机制不成熟**：在当前规模下检索不如整体注入，且作者指出启发式检索属于"斜向检索"（相关性隐式），现有 BM25/稠密检索器难以适配更大银行。
- **实验覆盖不均**：几乎所有深度分析仅限 AppWorld，跨基准验证不足；τ²-bench 只测 retail、AutomationBench 只测 Operations 且因算力受限，覆盖不完整。
- **算力信息缺失**：未报告 GPU 型号/数量/时长，成本仅为 API 货币估算，无法评估真实资源消耗。
- **绝对分数不可直接比较**：生成任务被校准到特定求解者（如 GPT-5.4-mini），因此其绝对成功率与官方测试集不可比，只能用于**相对排序**。
- **生成成本偏高**：DAEDALUS 的 Solver rollout 数（1225 次）约为 ExpeL 的

倍量级，且每次 rollout 都是完整的多轮环境交互，导致生成阶段的总 token 消耗与货币成本显著高于多数基线（AppWorld 上 $109.7，部分消融配置（D）达 $210.4）。作者以"生成成本一次性、可跨测试任务摊销"作辩护，但若目标环境频繁更换或需要定期刷新记忆，摊销前提并不成立。
- **任务分布存在自选择偏差**：成功条件 σ 由 Explorer 自行撰写，因此天然倾向于"易于用自然语言描述、易于由 LLM Judge 判定"的任务形态。这可能导致练习任务分布与真实测试分布之间出现系统性漂移——例如需要精确数值容差、时序约束或多步状态依赖的任务，可能因"不好判定"而被排除在练习之外。
- **单点记忆库的统计效度有限**：每个方法在每个基准上只构建一个记忆库，生成阶段的随机性未被量化；而主结果仅 5 次推理，pass^5 的标准误偏大（部分达 ±7.8），因此方法间小于 5 点左右的差距不宜作强结论。

## 9. 综合评述与启示

### 9.1 论文定位与贡献分层

| 层次 | 贡献 | 评价 |
|---|---|---|
| **问题层** | 指出"程序性记忆"方法对人工策划任务与预言机验证器的隐性依赖，并提出在二者皆缺时的自举设定 | 切中领域被普遍忽视的前提假设，具有范式意义 |
| **方法层** | Solver Loop 的"连续成功才接受"验证规则 + Extractor 的信息遮蔽设计 | 简洁、可移植，是全文最具复用价值的技术点 |
| **工程层** | Surveyor / Guidelines / Consolidator 组成的效率闭环 | 以 48% 的成本削减与 97.8% 接受率证明其必要性 |
| **实证层** | 三基准对比 + 累积消融 + 跨家族迁移 + 评估代理发现 | 覆盖面广、诚实报告负面结果，但深度集中于 AppWorld |

### 9.2 对领域的方法论启示

1. **"验证即记忆"**：本文最重要的洞察不是"从失败中学习"，而是**用什么信号确认一条经验值得保留**。以"能否把失败转化为连续成功"替代"来源轨迹是否成功"，为无验证器的自监督场景提供了一种通用的经验筛选范式，可迁移至工具学习、代码修复、网页导航等领域。
2. **刻意制造信息不对称**：不告知 Extractor 缺失的成功条件，是一种低成本的正则化手段，值得作为通用实践（避免"补丁式记忆"）。
3. **难度校准即课程学习**：将 Solver Loop 的结局（too_easy / too_hard）作为反馈信号驱动 Explorer 调整难度，本质上是把课程学习嵌入多智能体生成循环，且无需额外标注。
4. **生成任务可作评估代理**：Kendall τ=0.89 的排序一致性提示，在缺乏公开测试集的新环境中，可以用自生成任务分布做**相对**模型选型——这为智能体环境的评测提供了一条现实路径（但作者也强调绝对分数不可比）。

### 9.3 开放问题

- 记忆的**在线增量更新**与**冲突消解**：何时该改写、何时该遗忘一条启发式，目前无稳定方案。
- 记忆的**规模-收益拐点**：90 条后性能反降，说明"整合会丢失适用范围"是核心瓶颈，可能需要结构化（如带前置条件的规则、依赖图）而非纯文本的记忆表示。
- **检索范式的重构**：作者提出的"斜向检索"（相关性隐式、非语义相似）暗示需要面向"操作适用性"的检索器，而非通用稠密检索。
- **双控制与不可重置环境**的扩展：当前假设排除了大量真实部署场景（如需人类/模拟用户协作的客服、无法回滚的生产系统）。
- **验证信号的升级**：以可执行断言、单元测试或状态校验替代 LLM Judge，可能进一步降低对 Judge 质量的依赖。

### 9.4 适用性判断

- **推荐使用**：目标环境可重置、任务可被单一智能体独立完成、缺乏人工任务与验证器、且愿意承担一次性较高生成成本的场景（如新上线的企业 SaaS 自动化、内部工具链智能体）。
- **暂不推荐**：双控制/多智能体协作环境、需要频繁更换目标环境的场景、对生成阶段成本极度敏感的场景，以及需要记忆在部署期持续演化的长期在线系统。

### 9.5 一句话总结

DAEDALUS 用"多智能体自生成任务 + 连续成功式验证 + 冻结文本记忆"的组合，证明了**在既无策划任务也无预言机验证器时，智能体仍能自举出可迁移的环境特定操作知识**，并以诚实的负面结果（规模不涨反降、检索不敌整体注入）为后续研究划出了清晰的边界。
