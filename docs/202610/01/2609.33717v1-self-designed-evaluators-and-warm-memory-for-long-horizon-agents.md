## 摘要
一个使用工具的语言模型智能体被部署在一长串任务上时得不到任何奖励，因此它无法判断自己是否成功，无法安全地重试，也无法为其改进所需的经验打标签。我们提出 SelfSuite：其中，智能体自身的基础模型仅给定世界的公开材料，就能设计一个小型评估套件，包含加权评判器和有依据的逐任务简报，将其冻结，并用它来门控保留最佳结果的重试，以及为类型化、结果追踪的记忆打标签。在 tau2-bench 和 AppWorld 上匹配的五次重复基准测试中，SelfSuite 在没有任何标签的情况下得分高于普通智能体，在 tau2-bench 上与给定十个专家标签的方法持平，并在 AppWorld 上落后于 Agentic Context Engineering (ACE)，其中代码执行提供了直接的成功信号。在同一任务上进行的消融实验中，它在每次重复中都高于无标签 ACE，而门控的第二次尝试是唯一一个在每次重复中移除后都会造成性能下降的组件。我们还模拟了一位领域专家，其每个世界对十个入门任务进行评分。使用这些标签校准 SelfSuite 的评估器可带来小幅且一致的增益，而用它们预热 ACE 的记忆可将 ACE 提升至与校准后的 SelfSuite 持平。在第二个模型家族上的单次运行研究显示了相同的排序。

## Abstract
A tool-using language-model agent deployed over a long stream of tasks receives no reward, so it cannot tell whether it succeeded, cannot safely retry, and cannot label the experience it needs to improve. We present SelfSuite, in which the agent's own base model, given only the world's public materials, designs a small evaluation suite of weighted judges and grounded per-task briefs, freezes it, and uses it to gate a keep-best retry and to label a typed, outcome-tracked memory. On matched five-repeat benchmarks over tau2-bench and AppWorld, SelfSuite scores above the plain agent without any labels, matches methods given ten expert labels on tau2-bench, and trails Agentic Context Engineering (ACE) on AppWorld, where code execution gives a direct success signal. In an ablation campaign run on the same tasks, it is above label-free ACE in every repeat, and the gated second attempt is the only component whose removal hurts in every repeat. We also simulate a subject-matter expert who grades ten onboarding tasks per world. Using those labels to calibrate SelfSuite's evaluator gives a small, consistent gain, and using them to warm up ACE's memory lifts ACE to tie calibrated SelfSuite. A single-run study on a second model family shows the same ordering.

## 1. 核心问题与研究背景

- **根本痛点**：在真实部署中，一个长时程工具调用智能体面对连续任务流时**拿不到任何奖励信号**。它无法判断任务是否成功，因此：
  - 无法安全地重试（不知该不该重试）；
  - 无法区分有用经验与误导性经验，因而无法标注记忆、无法自我改进。
- **传统做法的局限**：现有方法通常依赖专家手工编写检查项（成功评分表、策略断言、世界状态回读、单元测试），这既费人力、又强绑定具体世界、且脆弱；多数"自我改进智能体"研究因此默认基准自带 ground truth（GT）。
- **论文的核心主张**：模型可以**自己编写验证器**。给定与人类工程师相同的公开材料，基座模型能设计一个小型、分解化的评估套件，将其**冻结**，并在**完全无 GT** 的情况下用它门控重试循环、标注记忆。
- **现实约束下的问题延伸**：真实部署中唯一的人类信号来自 FDE/SME（前向部署工程师/领域专家），其可负担的标注量约为**每个世界 10 个任务**。论文进一步研究这 10 个标签能带来多少增益。
- **贡献概览**：
  1. SelfSuite：自设计、冻结、无 GT 的控制套件（含 grounded 任务简报、世界状态回读、keep-best 重试、类型化 PnL 记忆）。
  2. 匹配的五次重复评估（两个基准、五个世界），含噪声下限、配对置信区间、组件消融、尝试级诊断、第二模型复现。
  3. 模拟 SME 研究：10 个入门标签的两种用法（评估器校准 vs. 热记忆）。

## 2. 方法论

### 2.1 核心思想
SelfSuite 分两阶段：**一次性离线自设计**（每个世界一次）与**在线部署循环**。两阶段均无 GT。

### 2.2 自设计：架构师编写套件
"架构师"就是智能体自身基座模型，输入世界摘要、公开策略、工具签名及（fresh-suite 处理下）3 个无标签任务描述，输出一份 JSON 套件规范，含五部分：

- **Judges（评判器）**：每条是一个测量准则，含 system prompt、user 模板（槽位含 `{task, trajectory, policy, tools, lessons, brief, state}`）、输出 schema（boolean `pass`、`[0,1]` 分数、reason）、权重、折叠模式。分 **VETO**（硬门控，失败即整体失败）与 **SOFT**（加权聚合）。套件通常很小（1–3 个评判器），典型为：最终状态结果验证器、策略/前置条件守卫、副作用/范围守卫。
- **TaskBrief 策略**：把任务指令分解为成功标准、所需证据、顺序约束等，每项带指令引用。两个校验：**Grounding**（检查每项是否有公开材料支撑，不支持则丢弃，防止凭空发明要求）与 **Gating**（窄前置条件检查，保守设计，不制造假阴性）。grounded brief 通过 `{brief}` 槽位条件化每个评判器。
- **聚合与阈值**：聚合规则（min / mean / weighted）+ 阈值 τ。无 veto 失败且 soft 聚合分 ≥ τ 才算通过。
- **记忆分类法与重试策略**：命名任务族用于路由经验，规定重试次数与反馈生成方式。
- 评判器是对基座模型的独立 temperature-0 调用，**没有更强的独立评分模型**。

### 2.3 状态回读（证据而非裁决）
- 轨迹容易被宽松评分，世界状态不容易。每次尝试后，世界适配器重建环境（tau2 重放仿真最终状态；AppWorld 重开保存的数据库），对任务相关记录运行有界只读查询，序列化进 `{state}` 槽位。
- **不触碰基准奖励、金标动作或隐藏测试**，自身不能通过/失败/否决任何东西。
- 若回读失败，状态条件评判器**中性弃权**（分数 0.5，标记 `no_state`），避免缺观测造成假否决。实测弃权率：AppWorld normal 为 0%，challenge 低于 1%。

### 2.4 部署循环（六步）
1. **Retrieve**：任务路由到族，取 top-5 相关经验（族优先收集 → 按锚定状态与新旧预排序 → 约 20 个候选窗口内 LLM 相关性排序）。
2. **Attempt**：ReAct 智能体带检索到的经验执行任务。
3. **Judge**：冻结套件打分——构建并 grounding brief、回读状态、每个评判器输出 pass/score、折叠裁决（先 veto 后聚合对比 τ）。
4. **Retry**：若失败且预算剩余（共两次尝试），把失败评判器的理由蒸馏成一条反馈指令，智能体带该指令再试一次。反馈只描述世界证据，**从不提及评判器或标准**。
5. **Keep-best**：提交哪次尝试由"do-no-harm"规则决定——通过套件的尝试胜出；平局取最早；后来者只有在聚合分超过当前最佳一个**margin m**（重复实验 0.30，单次研究 0.15）时才替换。因此带噪的第二次尝试无法顶掉好的第一次。
6. **Learn**：从完成任务中抽取经验写入记忆，结果更新被检索经验的账本。

### 2.5 类型化、结果追踪的记忆
- 经验有类型（正面 "do" / 负面 "avoid"）、分节（策略、常见错误、领域知识）、路由到族，按桶上限存储：每桶最多 30 条，满 20 条时 LLM 蒸馏近重复，每 scope 全局上限 200 条。
- 每条带 **PnL 账本**：`uses / helps / hurts` 计数；被检索后成功则计入 helps、失败则计入 hurts，因此持续有害的经验被降权并可能被驱逐。
- 每任务只注入 5 条相关性排序的条目（对比 playbook 整块注入）。主处理用**平衡记忆**（正负皆有）。

### 2.6 模拟 FDE 的两种标签用法（§5）
- **评估器校准（Algorithm 1）**：确定性、仅评估器程序。
  - 把 10 个入门任务按种子打乱分为 F（6，fit）与 G（4，gate）；
  - 在 F 上计算每个评判器在正确/错误尝试上的触发率，eligible 条件为 `Pr[fire|wrong] − Pr[fire|correct] ≥ 0`（veto 必须具判别力）；
  - 枚举候选：eligible 子集 × 折叠 profile（preserve / state-veto / all-soft）× 聚合（min/mean/weighted）× 阈值网格（min 只保留 τ₀）；
  - 保留 F 上 agreement 与 balanced accuracy 不低于 S₀ 的候选，选最大化 (balanced accuracy, agreement, −FP, −FN, −#judges, −|τ−τ₀|) 者；
  - **只在 G 上严格改进且 FP/FN 均不增加时才接受**，否则保留 S₀；
  - 校准只改折叠、聚合、阈值，**不重新运行智能体或评判器**（基于已记录的裁决重新聚合）。
- **热记忆（warm memory）**：用 ACE 的 Reflector 和 Curator，从每个入门任务一个二值结果标签拟合热 playbook，之后部署继续无标签，用 ACE 自身的轨迹自推断。

## 3. 实验设计

### 3.1 数据集 / 场景
- **tau2-bench**：airline（50 任务）、retail（114）、telecom（114）——带模拟用户的对话式工具调用智能体，按 **pass@0.5**（最佳尝试奖励 ≥ 0.5）评分。
- **AppWorld**：test-normal（168）、test-challenge（417）——在应用 API 上生成代码的智能体，按 **Task Goal Completion**（全部子任务通过，奖励 ≥ 0.999）评分。无评估报告的运行目录计为失败。

### 3.2 模型
- 所有重复实验用 **GPT-5.5**（低推理努力）。
- 单次跨模型研究增加 **Claude Opus-4.8**（thinking 关闭）。
- 评判模型**始终是智能体自身模型**。

### 3.3 对比方法
- **Plain ReAct agent**（基线）。
- **ACE（Agentic Context Engineering）**：用作者发布的 playbook 工具、无 GT 的 Reflector/Curator 提示和 delta（累积）记忆，在严格无 GT 规则下运行（作者代码的 `no_ground_truth` 只对 Reflector 隐藏目标但仍以正确性门控控制流，本文版本从不读取基准奖励）。
- **ACE + warm playbook（10 标签）**。
- 另有 SelfSuite fresh suite、SelfSuite + calibrated suite，以及若干 ACE 变体（collapsing/delta、self-graded/calibrated evaluator/GT oracle）。

### 3.4 实验活动（Campaigns）
- **(A) 匹配五次重复基准**：5 次重复 × 25 个 tau2 任务（8 airline、8/9 retail、9/8 telecom）+ 25 个 AppWorld 任务（12/13 normal、13/12 challenge 交替）。任务 ID 跨方法一致、跨重复不相交、且与每个世界保留的 10 个入门任务不相交。
- **(B) 消融活动**：5 次匹配重复，以 SelfSuite（平衡记忆、两次尝试、margin 0.30）为参照，7 个单组件变体，加上 plain agent 与无标签 ACE 跑在同一任务上。每次重复 18/19 个 tau2 任务 + 25 个 AppWorld 任务。
- **(C) 双模型单次研究**：每格一次运行，GPT-5.5（5 个世界）、Opus-4.8（4 个世界，其 AppWorld-challenge 因网关失败作废）。
- **(D) 套件诊断**：用 (C) 的 GPT-5.5 fresh-suite 单次运行，加上校准套件在 airline/retail/telecom/AppWorld normal 全目录任务上的 5 次独立部署，刻画套件行为。

### 3.5 超参数
fresh suite 由 3 个无标签采样任务描述设计；每任务两次尝试；选择 margin 0.30；平衡记忆；briefing off；revision off；状态信号必需；top-5 检索；评判 temperature 0；每个重复与世界使用不同确定性种子。

### 3.6 统计方法
报告重复的均值与样本标准差（SD）、配对逐重复差异及 95% t 置信区间与配对 t 检验、非配对比较用 Welch's t 检验。50 任务单元观测 SD 为 2–7 pp，25 任务 tau2 切片为 4–13 pp。

## 6. 主要结论与发现

- **无标签 SelfSuite 有效**：fresh suite 无标签即高于 plain agent（配对 +6.0 pp，[−0.3, +12.3]），在 tau2 上与所有学习器同噪声水平（均值第二好）。
- **校准版最佳**：calibrated SelfSuite 在 overall 与 tau2 上均值最高（84.4%、79.2%），与最强预算匹配基线（ACE + 热记忆，84.0%）打平（配对差 +0.4 ± 2.6 pp）。
- **专家标签两种用法都有增益**：
  - 作为**热记忆**：把 ACE 从 81.2 提到 84.0（+2.8 ± 5.9 pp overall，tau2 +6.4 ± 9.2 pp，五次重复下不显著）；
  - 作为**评估器校准**：给 SelfSuite 带来 +2.0 pp 配对增益（[+0.2, +3.8]），**每次重复都不亏**（+2, +2, +2, 0, +4）。
- **基准差异显著**：tau2（无执行信号）上 SelfSuite 两行领先（78.4 / 79.2 vs 71.2–77.6）；AppWorld（代码执行给出免费成功信号）上 ACE 两行与 calibrated SelfSuite 都在 89.6–91.2 且同噪声，fresh suite 最低（86.4）。
- **消融核心发现**：**门控的第二次尝试是唯一在每次重复中移除都造成下降的组件**（overall −7.8 ± 3.5 pp，p = 0.007；tau2 −14.9 ± 5.7 pp，五次全负）；AppWorld 上效应小（−3.2 normal、−1.4 challenge）。平衡记忆替换默认记忆带来小而一致的 −2.7 ± 1.9 pp（p = 0.032）。记忆极性、TaskBrief、评判器分解在噪声内。
- **机制解释**：自设计套件是**保守的否决者**（fresh suite 只判 6%–64% 任务通过，而 GT 成功率为 66%–90%；假通过极少），keep-best 把这种保守性转化为**低风险重试收益**；每个世界平均损失不超过 1 个任务。
- **剩余空间在"选择"**：best-attempt oracle 与部署分之间仍有差距（校准套件 +2.0 airline、+4.3 retail、+4.6 telecom、+0.3 AppWorld normal；fresh 单次 +2.4 到 +12），说明智能体已产出正确答案，只是无 GT 套件挑不出来——是重复采样中 coverage-vs-selection 差距的智能体级对应物。
- **第二模型族复现排序**：SelfSuite 在 9 个单元中 7 个最好或并列，tie retail，airline 两个模型都输；对 agent 的提升 GPT-5.5 +4.9 pp、Opus-4.8 +8.4 pp。

- **Airline 是唯一的例外世界**：两个模型族上 SelfSuite 都输给 ACE——它是 5 个世界中**工具面最窄、对话最强**的场景，成功更依赖对话管理与用户澄清，而非状态回读与副作用守卫所能捕获的信号，因此 SelfSuite 的评判器设计在这里"看不全"任务成败；这也说明自设计套件的有效性**与世界可观测性成正比**。
- **控制流安全**：由于套件保守 + keep-best 门控，SelfSuite 的**负向风险被显著压低**——所有重复中，相对 plain agent 的净损失被限制在"平均每世界不超过 1 个任务"，未出现某次重复大幅崩溃的情况，符合其"do-no-harm"设计意图。
- **无 GT 并不等于无收益**：即使完全无标签，SelfSuite 也超过了未使用任何 GT 的学习器（ACE cold），说明"自己写验证器"这条路本身即可成立；而少量专家标签（10 个/世界）的边际收益，**在评估器校准上比在热记忆上更稳、更省**（校准是确定性重聚合，不重跑智能体）。

## 7. 局限性讨论

论文自陈的局限集中在以下几点：

1. **无成本归一化**：SelfSuite 增加了评判、brief 构建、状态回读与重试的额外调用；与 ACE 等方法的对比**未按 token/调用量归一**，"同等预算下的比较"缺失，作者将其列为未来工作。
2. **样本规模限制分辨力**：5 次重复仅在 50 任务单元上约束约 ±4 pp 的效应；更小的组件效应（记忆极性、fresh vs calibrated 在 tau2）**未被统计显著地分辨**，部分结论只能以"方向一致"表述。
3. **设计方差与运行噪声混合**：fresh suite 每重复重设计一次，报告方差里混入了设计方差，难以纯粹归因于部署噪声。
4. **模型与基准覆盖有限**：主结论基于 GPT-5.5，第二模型仅单次运行且缺 AppWorld-challenge 单元；基准为 tau2 与 AppWorld 两个，均为工具调用/对话式，未覆盖长时程真实工程场景。
5. **基线复现差异**：ACE 在 tau2 上为作者自行复现，与官方实现可能存在行为差异，比较公平性存在残余不确定性。
6. **套件能力受世界可观测性约束**：Airline 的失败表明，当任务成败主要取决于对话交互而非可回读的显式世界状态时，自设计套件难以完整覆盖。
7. **无权重更新**：方法完全依赖外部记忆与上下文，未验证与微调/强化学习等权重级方法的组合潜力。

## 8. 意义与启示

- **对智能体部署**：本文给出了一条**可落地的"无 GT 自监督"路径**——智能体用自身能力设计验证器、以状态回读为证据、用 keep-best 抑制噪声重试，从而在真实、无奖励流的环境中安全地重试与积累经验。
- **对自我改进研究**：把"自我改进"的瓶颈从"生成答案"重新定位到"**在无 GT 下选择答案**"，指出 coverage-vs-selection 差距在智能体层面的对应物，为后续研究提供了明确靶点（如何缩小 best-attempt oracle 与部署分之间的差距）。
- **对专家标注经济学**：10 个标签/世界的稀缺预算下，"**用于评估器校准**"比"用于热记忆"更稳定、成本更低（不重跑智能体），为 FDE/SME 的标注分配提供了实用建议。
- **对评估方法学**：匹配任务 ID、配对检验、噪声下限报告、入门任务隔离等做法，是 LLM 智能体评估中值得推广的规范。
- **对设计原则**：保守否决 + 强 keep-best 的组合，把"判断不确定"转化为"低风险行为"，是一种比"追求高精度评判"更鲁棒的工程取向。

## 9. 一句话总评

本文提出并验证了"智能体自设计、冻结、无 GT 的评估套件（SelfSuite）"，通过 grounded 任务简报、世界状态回读、保守否决门控与 keep-best 重试，在无奖励信号的真实部署约束下实现了安全重试与经验标注；实验表明无标签自设计套件即可超越无 GT 学习器，而每世界 10 个专家标签用于评估器校准能带来稳定小增益，其核心价值在于把"自我改进"的难题从生成转向**无 GT 选择**，同时诚实地保留了成本、样本量与可观测性方面的局限。
