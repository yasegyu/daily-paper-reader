## 摘要
长期记忆对于在持续对话中与用户交互的多模态智能体至关重要。然而，用户记忆并不总是被明确陈述：它们也可能由图像中反复出现的背景物体、音频中的环境声音或其他边缘多模态线索所暗示。现有基准大多聚焦于纯文本记忆或显式多模态证据，使隐式多模态线索未得到充分探索。我们提出 CUE-Mem，一个文本-图像-音频基准，用于从隐式线索评估长期用户记忆。CUE-Mem 包含 2,674 个问题，涵盖显式和隐式证据设置，并覆盖四项任务：实体回忆、长模式、个性化推荐和答案拒答。在文本化记忆系统中，隐式性能仍远低于 oracle 证据，表明主要瓶颈在于保留和检索细微线索，而非问题可回答性。增加描述细节能恢复更多此类证据，但带来不均衡的增益和迅速增长的 token 成本，促使采用原生多模态访问。然而，原生访问并不能一致地解决该瓶颈：证据使用强烈依赖主干模型，而多模态索引引入了大量检索噪声。CUE-Mem 为选择性保留、检索和使用细微多模态证据的记忆系统提供了一个测试平台。

## Abstract
Long-term memory is essential for multimodal agents that interact with users across sustained conversations. However, user memories are not always explicitly stated: they may also be implied by recurring background objects in images, ambient sounds in audio, or other peripheral multimodal cues. Existing benchmarks largely focus on text-only memory or explicit multimodal evidence, leaving implicit multimodal cues underexplored. We introduce CUE-Mem, a text-image-audio benchmark for evaluating long-term user memory from implicit cues. CUE-Mem contains 2,674 questions across explicit and implicit evidence settings and covers four tasks: Entity Recall, Long Pattern, Personalized Recommendation, and Answer Refusal. Across textualized memory systems, implicit performance remains far below oracle evidence, locating the main bottleneck in preserving and retrieving subtle cues rather than question answerability. Increasing caption detail recovers more of this evidence, but brings uneven gains and rapidly growing token costs, motivating native multimodal access. Yet native access does not uniformly resolve the bottleneck: evidence use depends strongly on the backbone, while multimodal indexing introduces substantial retrieval noise. CUE-Mem provides a testbed for memory systems that selectively retain, retrieve, and use subtle multimodal evidence.

- **现有空白**：
  - 现有基准多聚焦纯文本记忆（MemoryBank、LongMemEval、LOCCO）或显式多模态证据（Mem-Gallery、MemLens、Persona-MME、H2HMem）。
  - 音频、尤其是**环境声（ambient sound）**在多模态记忆基准中严重不足。

- **核心研究问题**：长期记忆系统能否从多模态历史中反复出现的背景视觉/听觉证据里形成用户记忆？
- **整体含义**：论文提出 **CUE-Mem**——首个文本-图像-音频的长期用户记忆基准，专门隔离由**反复背景视觉与听觉线索**支撑的用户记忆，为"选择性保留、检索与使用细微多模态证据"的记忆系统提供测试平台。

## 2. 方法论

### 2.1 核心思想

- 以**结构化用户画像**为起点，合成多会话文本-图像-音频对话历史，分为**显式（Explicit）**与**隐式（Implicit）**两种证据条件：
  - **显式**：目标属性在对话中直接陈述，或作为共享图像的前景主体。
  - **隐式**：目标从不被陈述，仅由边缘/背景视觉物体或非语音环境声暗示。
- 显式与隐式条件在**聚合层面**可比较，但个体样本**不构成一一对应的反事实对**。

### 2.2 三阶段构建流程

**阶段 1：脚本合成（Script Synthesis）**
- **用户画像生成**：从 ALOE / PersonaHub 抽取 persona 种子，LLM 扩展为覆盖娱乐、生活方式、宠物、外观、习惯、饮食、社交关系等类别的结构化画像，作为潜在记忆真值。
- **模态与证据分配**：LLM 智能体为每个属性分配模态与证据类型；从 ESC-50 与 FSD50K 构建环境声种子池（114 候选 → 人工保留 96 类）。
- **事件生成**：生成按时间排序的事件时间线，后续事件以前序事件为条件以减少重复、保持连续性；事件分布到多会话中使隐式线索反复出现。

**阶段 2：多模态对话合成（Multimodal Dialog Synthesis）**
- **图像合成**：为反复出现的人物、宠物、物体、地点建立参考资产以保持跨会话一致性；显式视觉证据位于前景，隐式线索置于杂乱背景的干扰物之间，可观察但边缘化且不在对话中讨论。
- **音频合成**：为每位用户构建可复用声音画像与锚点片段；显式场景中语音直接陈述目标，隐式场景中环境声可闻但不被文字转写。
- **对话生成**：整合事件时间线、用户画像、模态分配与多模态条目描述，生成多会话用户–助手交互。

**阶段 3：数据审查（Data Review）**
- **自动检查**（三项）：
  - CHECK 1 合成质量：过滤不自然脚本、低质图像、损坏音频、跨模态不匹配。
  - CHECK 2 长期一致性：用 SigLIP 2 比对视觉实体与参考资产，用 ERes2NetV2 比对声音与锚点。
  - CHECK 3 隐式性：要求文本–图像重叠与隐式目标–整图重叠均低于预设阈值，防止文本泄漏与目标过于显著；隐式音频需可闻且不在语音转写中。
  - 自动检查剔除初始样本的 **42.80%**。
- **人工检查**：12 名标注员、两轮评审、约 **550 标注小时**；三人独立评估对话自然度、多模态连贯性、证据有效性；平均 Fleiss' κ = **0.73**；人工审查再剔除剩余样本的 **22.10%**（最终保留初始候选的 **44.56%**）。

### 2.3 四类任务设计

| 任务 | 考察能力 | 正确选项约束 |
|---|---|---|
| **Entity Recall（实体回忆）** | 从长历史中恢复具体用户实体/属性（宠物、个人物品、居住环境） | 与画像一致的身份/关系/外观/职业等 |
| **Long Pattern（长模式）** | 跨会话聚合反复证据，推断高层偏好、习惯、作息、环境模式 | 同一生活域内三个合理模式，不能仅凭选项长度排除 |
| **Personalized Recommendation（个性化推荐）** | 将记忆应用于选择个性化推荐 | 至少两个同品类但偏好关键维度不同的硬干扰项 |
| **Answer Refusal（答案拒答）** | 证据缺失或不足时保持校准、避免过度推断 | 唯一"历史未指定"选项；保留一个由线索支撑但问题不兼容的诱饵 |

- **拒答的 8 种对抗变换**：人物/归属互换、属性槽互换、类别/类型互换、词汇概念互换、极性翻转、虚假预设、事件语境互换、隐式过度声称（仅用于隐式目标）。
- **Question-only filtering**：两个骨干各三次运行，非拒答问题若六次预测全对则剔除（共剔除 525 题）；拒答问题因拒绝短语本身可能是问题级线索而豁免。

### 2.4 数据统计

- 20 个合成用户，648 个会话，5,798 轮对话，496 张图像，2,228 个音频片段。
- 平均每用户 32.4 会话，每会话 8.95 轮。
- **2,674 道 QA**：1,401 显式 + 1,273 隐式。
- 任务分布：Entity Recall 1,128；Answer Refusal 819；Personalized Recommendation 364；Long Pattern 363。
- 排除拒答后，显式与隐式问题平均含 **3.14** 与 **3.34** 条支撑线索。
- 构建清单含 671 个事件，其中 551 个显式–隐式配对、120 个仅显式（关系类）；显式目标平均出现 3.32 次，隐式 3.62 次（隐式最少 3 次）；时间跨度中位数约 352–354 天。

## 3. 实验设计

### 3.1 评测范式与系统

- **文本化记忆（Textualized Memory）**：先将图像/音频转为 caption 再文本处理。默认使用 GPT-5.4 中等粒度图像 caption 与 Gemini 3.1 Pro 基于提示的音频 caption。
  - 对比系统：**Full Memory、NaiveRAG、Generative Agents、Reflexion、MemGPT、A-Mem、MemoryOS**。
- **原生多模态记忆（Native Multimodal Memory）**：基于 RAG 的索引/使用矩阵（Table 3）：
  - **Text-Index / MM-Index** × **Text-Use / MM-Use**，构成 TT、TM、MT、MM 四种配置。
  - 使用 Gemini Embedding 2（3,072 维）做统一嵌入与倒数排名融合，最终 k=5。

### 3.2 骨干模型

- 文本化记忆：**Qwen3.6-35B-A3B**、**GPT-5.4-mini**。
- 原生多模态记忆：**Qwen3-Omni-30B-A3B-Instruct**、**MiniCPM-o-4.5**。
- 文本化组件：GPT-5.4（图像 caption）、Qwen3-ASR-1.7B（ASR）、Gemini 3.1 Pro（音频 hint/背景音 caption）。

### 3.3 评测指标

- **Accuracy**（显式/隐式分别报告）。
- **EI-Gap = Acc_explicit − Acc_implicit**，越大表示隐式退化越严重。
- **Memory Avg.**：Entity Recall、Long Pattern、Personalized Recommendation 的宏平均；Answer Refusal 单独报告。
- 控制设置：**No Context**（无历史）、**Oracle Evidence**（合成线索所用的源文本提示）、**Human (Full)**（读完整文本化历史）、**Human (Oracle)**（仅 oracle 文本）。

### 3.4 三个研究问题

- **RQ1**：文本化记忆系统处理隐式多模态线索的效果如何？
- **RQ2**：文本化质量如何影响隐式记忆表现？
- **RQ3**：原生多模态访问能否缓解文本化瓶颈？
