## 摘要
大语言模型（LLMs）正越来越多地部署于企业、科学和医疗应用中，在这些场景里，智能体必须整合领域特定知识并从经验中适应。上下文工程通过推理时提供的指令、策略和证据来改进模型行为，为权重更新提供了一种实用的替代方案。然而，在线调整上下文通常需要代价高昂的试错过程，而查询往往被独立处理，导致有用的经验无法延续。记忆系统通过在交互间保留信息来应对这一局限，但将信息持续追加到共享上下文的方法会面临令牌成本不断上升、上下文窗口限制，以及随着上下文扩展而出现的性能下降。我们引入了一个统一的上下文优化形式化框架，并表明智能体记忆系统的更新可以被解释为对模型上下文的优化更新过程。这一视角试图为研究记忆设计及其效率提供一个具有原理支撑的框架。随后我们提出 GraphMemory，一种轻量级的基于图的记忆，它能够积累、精炼、组织和连接可复用的策略。对于每个查询，GraphMemory 仅检索相关子图，从而实现在线上下文适应，而无需让模型接触整个记忆。在有界检索下，随着已处理样本数量的增长，检索到的记忆量保持恒定。实验表明，GraphMemory 在实现有竞争力的下游性能的同时，相比我们的基线方法少用了约 81-85% 的记忆构建令牌。

## Abstract
Large language models (LLMs) are increasingly deployed in enterprise, scientific, and medical applications, where agents must incorporate domain-specific knowledge and adapt from experience. Context engineering offers a practical alternative to weight updates by improving model behavior through instructions, strategies, and evidence supplied at inference time. However, adapting context online typically requires a costly trial-and-error process, while queries are often processed independently, preventing useful experience from carrying forward. Memory systems address this limitation by retaining information across interactions, but approaches that continually append information to a shared context face increasing token costs, context-window limits, and performance degradation as the context expands. We introduce a unified formulation of context optimization and show that an agent memory system update can be interpreted as an optimization update procedure over the model's context. This perspective attempts to provide a principled framework for studying memory design and its efficiency. We then propose GraphMemory, a lightweight graph-based memory that accumulates, refines, organizes, and connects reusable strategies. For each query, GraphMemory retrieves only the relevant subgraph, enabling online context adaptation without exposing the model to the entire memory. Under bounded retrieval, the amount of retrieved memory remains constant as the number of processed examples grows. Experiments show that GraphMemory achieves competitive downstream performance while using approximately 81-85% fewer memory-construction tokens than our baselines.

# 论文总结：Decoupling Memory from Context（GraphMemory）

## 1. 核心问题与研究动机

- **背景**：LLM 智能体在企业、科研、医疗等场景需要持续吸收领域知识并从经验中适应，但部署后的模型参数固定，单次交互获得的经验无法自然改善后续行为。
- **现有路线的局限**：
  - 参数高效微调（PEFT）、按需生成适配器等方法仍需访问模型权重与训练设施，学到的状态绑定在特定模型参数上，难以跨智能体迁移。
  - 上下文工程（prompt 优化、如 MIPROv2/GEPA）无需改权重，但通常针对离线数据集优化单一任务级 prompt，无法在部署中积累经验。
  - 持久化记忆系统（Dynamic Cheatsheet、ACE）把可复用策略写入外部自然语言记忆，但多为**扁平集合或单一演化文件**，每次查询都要处理越来越大的异构上下文。
- **核心痛点**：**存储记忆的规模与每次查询所处理的记忆量被耦合在一起**。作者证明在“只追加”范式下，记忆上下文长度随样本数 N 线性增长（O(N)），累计暴露量更达 O(N²)，带来 token 成本膨胀、上下文窗口压力、以及上下文退化/坍塌。
- **论文主张**：应把“存储的记忆”与“暴露给模型的上下文”解耦——记忆可以持续增长，但每次查询的活动上下文保持有界。

## 2. 方法论

### 2.1 统一的形式化框架

- **离线上下文优化**：定义经验上下文风险
  \(L_D(c)=\frac1n\sum_{i=1}^n \mathbb{E}[\ell(f(c,x_i),y_i)]\)，目标 \(c^*=\arg\min_{c\in\mathcal C}L_D(c)\)。由于 c 是离散 token 序列且模型常为黑盒，无法做常规一阶优化。
  - prompt 优化类（MIPROv2、GEPA）被抽象为在候选池 \(P_T\) 内搜索：\(\hat c_T=\arg\min_{c\in P_T}L_D(c)\)。
  - 反馈迭代类（OPRO、TextGrad、TRACE）被抽象为 \(\Delta c_t=O(c_t,x_t,\hat y_t,\tau_t)\)、\(c_{t+1}=c_t\odot\Delta c_t\)，**结构上类比于对上下文的“梯度下降步”**，但并非真实梯度，也不保证降低目标。
- **从局部更新到记忆**：记忆系统从单个经验中抽取短上下文块 \(\Delta_i\)，形成外部记忆库 \(\delta=(\Delta_1,\dots,\Delta_n)\)，对应局部代理风险
  \(L^{\text{block}}_D(\delta)=\frac1n\sum_i \mathbb{E}[\ell(f(\Delta_i,x_i),y_i)]\)。
  - 作者明确指出这**不是**与全局目标等价的重新表述（块可能过拟合其来源样本），其动机是实用性的：让不完美的 oracle 只需提炼一条聚焦的“课程/纠错/失败模式”，泛化则交由记忆接口（组合或检索机制）承担。
- **增长性结论**：
  - 命题 1（只追加记忆）：若每例至多产生一个长度 ≤ B 的块，则 \(\text{len}(c_\delta^{(N)})\le L_0+NB=O(N)\)；累计暴露量为 O(N²)。
  - **有界检索**：\(\delta^{(t+1)}=\delta^{(t)}\cup\{\Delta^{(t)}\}\)，\(c_\phi^{(t+1)}(x)=\phi(\delta^{(t+1)},x)\)。
  - 命题 2：若每块 ≤ B token、每次检索 ≤ K 块，则每查询 \(\text{len}(c_\phi^{(N)}(x))\le KB=O(1)\)，累计 O(N)。

### 2.2 GraphMemory 设计

- **基本结构**：有向图 \(G=(V,E)\)。节点存储 ACE 风格的 bullet 知识点（唯一 id、简短路由 key、完整内容）；有向边 \(e=(u,v)\) 表示“检索到 u 之后 v 可能有用”。
- **对 ACE 的两处接口改动**：Generator 读什么（前置检索阶段，而非整本 playbook）；Curator 写什么（除 bullet 外还可写节点间关系）。
- **执行循环**：RETRIEVE–GENERATE–REFLECT–CURATE。训练样本 \(x_t\) 先用 \(G^{(t)}\) 检索出 \(c_t\)，生成 \(\hat y_t\)；之后 Reflector 才检查预测与轨迹，Curator 再做局部图编辑得到 \(G^{(t+1)}\)，**保证 y_t 信息不会泄漏到 x_t 的预测**。
- **检索流程（两阶段）**：
  1. LLM Retriever 只读**紧凑索引**（仅 id + 短 key，不含完整 bullet 内容），最多返回 2 个索引区段、至多 6 个入口节点。
  2. 以入口节点为深度 0，做**权重优先的确定性广度优先遍历**：每个节点最多取 2 个后验均值最高的出边邻居，边权相同时以目标节点 id 确定性打破平局；总预算为**最多 2 跳、最多 12 个加载节点、最多 2500 token 序列化内容**；重复节点只加载一次。
  - **无全记忆兜底**：图空或未选出有效入口时，检索记忆为空、直接无记忆生成，以避免“悄悄退回全 playbook 暴露”。
- **边权学习（Beta 证据模型）**：每条有向边维护两个置信加权计数器 \(S_e\)（helpful）与 \(F_e\)（harmful），先验 Beta(1,1)；检索排序用后验均值
  \(w_e=\frac{S_e+1}{S_e+F_e+2}\)（新边中性 = 0.5）。Generator 报告有序影响轨迹，相邻节点对构成候选转移；Reflector 给出 helpful/harmful/neutral 标签及置信强度 \(c_e\in[0,1]\)，按标签累加到对应计数器（中性或 c=0 不变）。幻觉/未加载 id、重复对、非法标签、越界置信度一律丢弃，每个唯一转移每例最多更新一次；**观察转移不会自动建边**，新边只能由校验过的 Curator 操作引入，删除也须显式操作。
- **理论边界之外**：作者明确该实现并非端到端严格 O(1)——Retriever 仍要读随节点数增长的索引；但索引项很小，命题 2 的 O(1) 只约束喂给 Generator 的节点内容。
