## 摘要
长期智能体不仅必须记住关于用户的真实信息，还必须记住随着共享历史演变，特定智能体应如何与该用户协同工作。现有基准主要监督用户事实和偏好，或可跨用户复用的经验，使得这种特定关系下的智能体记忆仍处于隐含状态。此外，大多数先前工作仅通过长交互历史上的最终答案问答来评估模型，导致评估仍不完整且不可靠。为此，我们提出 DyadMem，并给出新定义：用户条件化关系型智能体记忆（User-conditioned Relational Agent Memory, URAM）。DyadMem 沿相同的多会话轨迹联合标注用户侧记忆与 URAM，共得到 6 个记忆类别。总而言之，它包含 3,065 个情节、50,961 个会话和 61,210 个问答实例，并提供大量会话级 Capture 与 Update 黄金标注、查询级 Recall 支持，以及两种 QA 设置：Gold-Memory 和 Full-Pipeline。在 16 个开放权重模型和 4 个专有模型上，Gold-Memory QA 始终表现强劲，但 Full-Pipeline QA 则急剧下降。这种差距明确支持了我们细粒度评估设计的合理性。此外，若干定量结果进一步揭示了即使前沿大语言模型也存在 Capture 召回率低、Recall 不完整以及不安全删除等问题。我们进一步开展了一项严谨实验，以验证 URAM 的有效性，并观察到其对全部 20 个模型均有积极效果。总之，DyadMem 是一个双领域、全流程的记忆基准，并投入了大量标注工作，以推动该领域的发展。

## Abstract
Long-term agents must remember not only what is true about a user, but also how a particular agent should work with that user as their shared history evolves. Existing benchmarks primarily supervise user facts and preferences or experience reusable across users, leaving this relationship-specific agent memory implicit. Additionally, most prior works measure the model solely with final-answer QA over long interaction histories, making the assessment still incomplete and unreliable. To this end, we introduce DyadMem with the proposed new definition User-conditioned Relational Agent Memory (URAM). DyadMem jointly annotates user-side memory and URAM along the same multi-session trajectories, resulting in 6 memory categories. To summarize, it includes 3,065 episodes, 50,961 sessions, and 61,210 QA instances, with extensive session-level Capture and Update gold annotations, query-level Recall support, and two QA settings: Gold-Memory and Full-Pipeline. Across 16 open-weight and 4 proprietary models, Gold-Memory QA is consistently strong, yet Full-Pipeline QA drops sharply. Such a gap explicitly supports our fine-grained evaluation design. Additionally, several quantitative results further reveal low Capture recall, incomplete Recall, and unsafe-deletion issues arising from even the frontier LLMs. We further conduct a rigorous experiment to validate the effectiveness of our URAM and observe the positive effects for all 20 models. In summary, DyadMem is a dual-domain, full-pipeline memory benchmark with extensive annotation efforts for advancing the domain's development.

# DyadMem 论文详细总结

## 1. 核心问题与整体含义

- **背景**：长期交互智能体不仅要记住用户的客观事实与偏好，还必须随共享历史演变，记住"这个特定智能体应如何与该用户协同工作"。
- **现有工作两条主线彼此分离**：
  - 用户记忆基准（LoCoMo、LongMemEval、PerLTQA、ConvoMem、PersonaMem、Memora、STALE）主要建模用户事实、画像、偏好及其演化。
  - 经验型智能体记忆（Agent Workflow Memory、Memp、LongMemEval-V2、MemoryAgentBench、Mem2ActBench）抽取可跨用户/跨任务迁移的工作流、环境知识与失败模式。
- **两个关键缺口**：
  1. **关系特定记忆缺位**：同一用户的两个智能体因交互历史不同，未来应采取的行为也应不同，但这类记忆此前基本是隐式的。作者将其形式化为 **URAM（User-conditioned Relational Agent Memory，用户条件化关系型智能体记忆）**。
  2. **评估方式不完整**：多数基准只用最终答案 QA 衡量长历史记忆，把"构建正确记忆、维护记忆随信息变化、完整检索证据、利用证据作答"混在一起，正确答案可能掩盖不完整或不安全的记忆库，错误答案也无法定位失败阶段。
- **整体含义**：DyadMem 是一个**双域（用户侧 + 关系型智能体侧）、全流程（Capture→Update→Recall→QA）**的长期记忆基准，沿同一多会话轨迹联合标注两类记忆，并分阶段直接度量，使失败可定位。

## 2. 方法论

### 2.1 任务形式化
- 一个 episode 为 `E = ({S_t}, Q)`，其中会话 `S_t = (τ_t, D_t, C*_t, L*_t, A*_t)`：时间锚点、完整对话、黄金 Capture 条目、黄金 Update 的删除/新增操作。
- 每个 QA 实例 `Q_j = (q_j, a*_j, I*_j)`，`I*_j` 是终态记忆库中仍然有效条目的黄金 Recall 支持集；所有支持集非空，空检索算失败而非正确弃答。
- **记忆库时序转移公式**：
  `B*_t = Dedup[(B*_{t-1} ∪ C*_t) \ L*_t] ∪ A*_t`
  Dedup 按记忆 key（有索引用索引，否则用内容）合并并保留最后一次出现。

### 2.2 六类记忆
- **用户侧**：`user_profile`（持久属性、偏好、约束）、`fact`（用户提供的持久客观实体信息）。
- **URAM（智能体侧，关系特定）**：`agent_identity`（角色与行为边界）、`agent_method`（可复用协作流程）、`agent_knowledge`（通过交互与反馈习得的用户条件化判断规则）。
- **共享**：`episodic`（具体交互事件），可为两侧提供证据。
- 角色硬约束：user 轮只能产出 episodic / user_profile / fact；assistant 轮只能产出 episodic / agent_identity / agent_method / agent_knowledge。

### 2.3 四阶段与两种 QA
- **Capture**：仅接收当前完整会话与时间锚点，不看历史会话，逐轮抽取，不做跨会话去重。
- **Update**：
  - *Gold-conditioned standalone Update*：输入当前对话 + 黄金前一记忆库 + 黄金当前 Capture，隔离上游误差。
  - *Full-Pipeline Update*：输入模型自建的前一记忆库与自产 Capture。
- **Recall**：从终态黄金库中返回有序证据索引。
- **QA 两种设置**：
  - *Gold-Memory QA*：直接提供黄金支持条目，测证据齐备时的作答能力。
  - *Full-Pipeline QA*：从模型自建终态库中取 Top-K（K=16）作答。
  - **Gold-to-Pipeline gap**：`ΔG2P = Acc_gold − Acc_pipe`，仅作为端到端损失量，不是各阶段的因果分解。

### 2.4 数据构建（对话优先）
- 采用 plan-guided、**dialogue-first** 范式：先按计划生成并审核完整多会话对话，再从已实现的交互中重建 Capture/Update/Recall 标注，保证每条标注可溯源到对话证据。
- 生成时用演化形式（含两跳链 A→B→C）保证记忆变化自然发生；约 15% 对话内容不产生持久记忆。
- 规模：**3,065 episodes、50,961 sessions、61,210 QA、1,263,402 对话轮**，覆盖 5 大领域 25 个子领域，user/agent-centric 分别为 1,532/1,533。
- 构建池 4,000 episodes，保留率 76.6%；9 名全职质控标注员，2 个月，成本 **57,751 美元**。

### 2.5 匹配与评分
- Capture 与 Update 新增采用**双向语义覆盖**匹配：BGE-M3 余弦相似度阈值 0.82（命中）/0.67（未命中），灰区用 nli-mdeberta-v3（阈值 0.4）双向 NLI 裁决；当一个预测覆盖多个黄金条目时施加单向蕴含守卫（阈值 0.1）扣除未被保留的细节。
- Recall 与 Update 删除用**精确索引匹配**。
- QA 由 GPT-5-mini 判分（语义一致性，1/0.5/0）；另报告 Grounded accuracy、Over-abstention（OA）、Ungrounded-correct（Ung.）。
- 截断、不可解析、空输出、失败调用均保留在分母中且不得分。
- 置信区间用 200 次 bootstrap 重采样。
