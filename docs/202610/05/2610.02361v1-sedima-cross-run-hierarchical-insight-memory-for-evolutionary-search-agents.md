## 摘要
由大型语言模型（LLM）驱动的进化搜索是一种用于自动化程序和算法发现的强大范式，然而现有系统大多没有记忆：每次运行都从头探索，因此智能体会反复重新发现相同的改进，并再次遇到相同的死胡同。我们提出 SEDIMA，一种面向进化搜索智能体的持久分层洞察记忆。SEDIMA 将原始轨迹提炼为自然语言洞察，使用注意力加权质心按语义相似度对其进行聚类，并检索相关指导以调节未来的变异，从而跨运行和跨问题积累可迁移知识，而不是局限于单条轨迹内。作为一个即插即用模块，且不修改搜索算子，在固定评估 100 个候选的预算下，SEDIMA 在 AlgoTune 上将平均最终性能提升 5.5%，在 ALE-Bench LITE 上提升 6.6%。在 OpenEvolve 下，SEDIMA 在五个所评估的主干模型上达到基线最佳性能平均所需的迭代次数减少 32.3%。

## Abstract
Large language model (LLM)-driven evolutionary search is a powerful paradigm for automated program and algorithm discovery, yet existing systems are largely memoryless: each run explores from scratch, so agents repeatedly rediscover the same improvements and re-encounter the same dead ends. We introduce SEDIMA, a persistent hierarchical insight memory for evolutionary search agents. SEDIMA distills raw traces into natural-language insights, clusters them by semantic similarity using attention-weighted centroids, and retrieves relevant guidance to condition future mutations, accumulating transferable knowledge across runs and problems rather than within a single trajectory. As a drop-in module that leaves the search operators unmodified, SEDIMA improves average final performance by 5.5% on AlgoTune and 6.6% on ALE-Bench LITE under a fixed budget of 100 evaluated candidates. Under OpenEvolve, SEDIMA requires 32.3% fewer iterations on average to reach baseline-best performance across the five evaluated backbones.

## 1. 核心问题与研究动机

- **背景**：LLM 已从一次性代码生成器演变为迭代式搜索算子，广泛用于程序与算法发现、数学发现、启发式合成等任务；OpenEvolve、ShinkaEvolve、LLM4AD 等开源框架降低了使用门槛。
- **核心问题**：现有 LLM 驱动的进化搜索系统大多**没有持久记忆**，每次运行都从零开始，导致两类浪费：
  - **跨运行浪费**：智能体在新任务上反复重新发现已经学会的修改，重新探索曾经无效或中性的方向，因为不记得过去某次编辑为何有效或无效。
  - **运行内不稳定**：单条搜索轨迹中，解质量随迭代剧烈波动，智能体提出、遗忘、再提出局部有用编辑，缺少持续信号来巩固有效经验。
- **已有工作的不足**：ReEvo、LoongFlow、DeltaEvolve 等虽引入反思或记忆，但记忆局限于单条进化轨迹，运行结束即重置；CORAL、PRISM 等虽具持久记忆，但把搜索循环改造成长期多智能体系统，需要重构搜索架构。
- **论文含义**：SEDIMA 试图为单智能体进化搜索提供一种**跨运行、跨问题的持久分层洞察记忆**，且作为即插即用模块，不修改底层搜索算子，从而把“无记忆搜索”转变为“可积累经验的搜索”。

## 2. 方法论

- **核心思想**：将原始进化轨迹蒸馏为自然语言洞察，按语义相似度组织成三层记忆，并在每次变异前检索相关指导注入提示词，使未来变异条件化于过去跨运行、跨问题积累的经验。
- **两个接口**：
  - **写**：每次评估后写入记忆。
  - **读**：每次变异前读取并合成建议。
  - 选择、种群管理、变异算子均不修改。

### 三层记忆结构

- **Level 1：原始轨迹**
  - 存储 step index、父代与子代适应度、适应度差、事件来源、原始评估报告。
  - 不做解释，作为高层记忆的证据，使检索建议可回溯到具体评估事件。
- **Level 2：蒸馏洞察**
  - 用 LLM 将每条轨迹转成紧凑自然语言洞察，并链接回 Level 1 证据。
  - **问题级洞察**：问题首次评估时，描述主要算法或架构瓶颈。
  - **变更级洞察**：后续父代—子代评估时，描述修改类型及观察到的性能影响。
  - 抽象掉实现细节，保留可复用经验，如缓存、剪枝、向量化、数据结构变更、减少冗余计算等。
  - 每条洞察被嵌入，用于语义组织与检索。
- **Level 3：语义聚类**
  - 按嵌入相似度聚类：新洞察若与最近簇代表的余弦相似度 ≥ τ_cluster=0.8，则加入该簇，否则新建簇。
  - 簇代表随成员加入而刷新，可选 LLM 总结反复出现的优化模式。
  - 不使用简单均值，而使用**非参数注意力加权质心**：
    - 成员 i 的语义中心性：\(s_i = \frac{1}{n-1}\sum_{j\ne i}\cos(e_i,e_j)\)
    - 注意力权重：\(w_i = \frac{\exp(s_i/\tau)}{\sum_j \exp(s_j/\tau)}\)
    - 簇代表：\(c = \sum_i w_i e_i\)
    - 温度 τ=0.1 时，语义中心、原型化的高价值洞察权重更大；τ→∞ 时接近均值池化。

### 分层检索与使用

- 变异前，SEDIMA 嵌入当前程序及观察到的问题作为查询。
- 按 \(r^{cluster}_k = \cos(e_q, c_k)\) 排序簇，保留相似度 ≥ τ_ret=0.6 的前 K_c=3 个簇。
- 每个簇内按 \(r^{insight}_i = \cos(e_q, e_i)\) 选前 K_i=3 条洞察。
- 每条洞察可附带最多 2 条 Level 1 轨迹。
- LLM 将查询、洞察文本、簇相似度、洞察相似度和原始证据合成为 **3 条具体建议**，插入 diff 或全重写提示词。
- **检索是语义的，而非谱系式的**，因此在一个问题上获得的经验可迁移到结构相似但任务不同的新问题。

### 预算与回退

- 检索受固定上限约束：簇数、洞察数、提示词长度，使上下文成本不随记忆总量增长。
- 若无簇超过阈值，则回退到原始变异提示词。
- 每次写入增加一次蒸馏调用和一次洞察嵌入；每次记忆条件化变异增加一次查询嵌入和一次建议合成调用。
- 记忆持久化在磁盘上，运行中可持续写入和检索，后续变异可检索同一次运行早期写入的洞察，也可检索此前运行保留的洞察。

## 6. 主要结论与发现

- **最终性能提升**：
  - 在固定 100 个评估候选预算下，SEDIMA 平均提升 AlgoTune 最终性能 5.5%，ALE-Bench LITE 提升 6.6%。
  - 在 20 个模型—框架—benchmark 比较中，全部 20 个有利于 SEDIMA。
  - 即使 ShinkaEvolve 通常提供更强基线，SEDIMA 仍一致提升。
- **弱模型收益更大**：
  - Qwen 3 Coder 相对提升最大：OpenEvolve 下 ALE-Bench 提升 11.0%，ShinkaEvolve 下提升 9.0%，说明持久指导对较弱搜索尤其有价值。
- **搜索动态加速**：
  - OpenEvolve 下，SEDIMA 平均减少 32.3% 迭代达到基线最佳性能。
