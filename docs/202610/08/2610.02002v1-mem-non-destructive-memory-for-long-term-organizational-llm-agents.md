## 摘要
大型语言模型（LLM）智能体如今参与组织工作，其中许多作者会在数月间跨文档记录决策。由于修订后的决策是以新文档而非对原文档的编辑形式出现，回答一个问题需要知道在给定时间哪一版本有效。然而，大多数记忆系统会在写入时压缩记录。通过将每份文档蒸馏为事实、笔记或图边，这些方法在提问之前就固定了可回答的内容。为解决这一问题，我们提出Mem++，一种从写入时蒸馏转向读取时选择的非破坏性记忆框架。Mem++完整存储每份文档及其日期和作者，并且在写入时不调用任何生成模型。在读取时，它仅检索日期不晚于问题所询问时间的文档，并融合词汇与语义排序。与覆盖旧版本的系统不同，Mem++保留这些旧版本，并将选择权留给回答模型。在组织基准OrgMemBench上的评估表明，Mem++在两个回答模型上均以8.0至13.1分的优势超越最强的记忆系统基线。在使用gpt-4.1-mini时，它还取得了最佳总体得分，比RAG高2.6分。此外，Mem++在LoCoMo上取得最佳的平均LLM评审得分，并在LongMemEval-S上排名第二，仅次于其实体图变体。基准评估代码可在 https://github.com/AIDAChip-Inc/mem-plus-plus 获取。

## Abstract
Large Language Model (LLM) agents now take part in organizational work, where many authors record decisions across documents over months. Because a revised decision arrives as a new document rather than an edit, answering a question requires knowing which version held at a given time. However, most memory systems compress the record at write time. By distilling each document into facts, notes or graph edges, these methods fix what can be answered before any question is asked. To address this, we propose Mem++, a non-destructive memory framework shifting from write-time distillation to read-time selection. Mem++ stores every document whole with its date and author, and it calls no generative model at write time. At read time, it retrieves only documents dated up to the time a question asks about and fuses lexical and semantic rankings. Unlike systems that overwrite older versions, Mem++ keeps them and leaves the choice to the answering model. Evaluations on the organizational benchmark OrgMemBench demonstrate that Mem++ surpasses the strongest memory system baseline by 8.0 to 13.1 points across two answering models. With gpt-4.1-mini, it also achieves the best overall score, 2.6 points above RAG. In addition, Mem++ achieves the best average LLM-judge score on LoCoMo and ranks second on LongMemEval-S, behind only its entity-graph variant. Code for benchmark evaluation is available at https://github.com/AIDAChip-Inc/mem-plus-plus.

# Mem++ 论文中文结构化总结

## 1. 核心问题与研究动机

- **背景转变**：LLM 智能体已进入组织协作场景，决策由**多位作者**在数月内跨邮件、工单、会议记录、共享文档分别写入，形成"组织记忆"（organizational memory）。
- **关键难点**：决策的修订不是"编辑旧文档"，而是**以新文档形式出现**。例如 3 月制定的政策、6 月修订、9 月撤销，会留下三份并存的文档，无人删除。因此回答问题时不仅要找最新版本，还要判断"某时点哪一版本有效"、谁改的、改了什么。
- **与对话记忆的本质差异**：对话记忆只有一个叙述者，后续陈述被默认视为对先前陈述的"更新"；组织记忆是多作者、多通道、权威来源不明确，且**历史版本本身经常就是提问对象**。
- **现有方法的根本缺陷**：主流系统在**写入时蒸馏**（facts / notes / graph edges），把"能回答什么"在提问之前就固化了：
  - Mem0 在冲突时**覆盖**旧事实（如"批准的决策"被"提案"覆盖后无法再检索）；
  - Zep/Graphiti 虽为边打上有效期，但存的是**抽取后的事实**而非原始文档，理由、条件、批准信息因"非实体形态"而永久丢失；
  - RAG / MemGPT / 生成式智能体保留原文但**不做结构化**，无法区分被取代的值与仍生效的值。
- **整体含义**：论文主张将记忆范式从"写入时蒸馏"转为"读取时选择"，让版本判断权留给回答模型。

## 2. 方法论

### 2.1 核心架构
Mem++ 形式化为三元组 `Mem++ = ⟨R, C, Φ⟩`：R 为记忆库（写入路径填充），C 为可选的版本合并算子，Φ 为读取算子。

每条记录（行）为 `r = ⟨x, a, t, e, σ⟩`：
- `x`：全文；`a`：作者；`t`：事件日期；`e`：句向量；`σ`：状态（是否 active、被哪一行取代）。
- **仅 σ 可被修改，行永不被删除**，因此存储只增不减，历史版本连同原文始终留存。

### 2.2 写入路径（无生成模型）
- **整篇文档摄入**：每篇文档生成一行，用句编码器 `h(·)` 得到 `e`，不做切窗、不做 LLM 抽取，写入时**不调用任何生成模型**。
- 同一文本同时进入**全文倒排索引（lex）**与**向量索引（vec）**，作者标签进入**标签索引（tag）**；超长文档只在 `e` 中截断，`x` 与词法索引保留全文。
- **溯源与时间锚定**：作者以标签形式记录；事件日期存入 `t`（OrgMemBench 文档自带日期；对话基准中每个回合以会话日期作为 `t`）。
- **仅追加更新**：空文本或与同一作者范围内活跃行完全重复的文档被跳过，重复摄入不产生冗余行；新增一篇文档的成本仅为一次 embedding。

### 2.3 可选合并算子 C（消融项，主实验关闭）
- 对活跃行按余弦相似度 `≥ τ` 贪心聚类；
- 对每个簇调用 LLM 打标签：`CONFLICT / RESTATEMENT / DISTINCT`；
- **CONFLICT**：最新日期行保持 current，旧行文本与日期保留，仅在 σ 中标记为 superseded（**仍可被检索**）；
- **RESTATEMENT**：用一次 LLM 调用生成 ≤220 token 的合并行（继承最早日期与全部原作者），原行标记为 archived（退出检索）——这是全库中唯一由模型撰写文本的行；
- **DISTINCT / 调用失败**：原样保留。成本为"每簇至多 2 次调用"而非"每文档 1 次"。

### 2.4 读取路径：多索引融合
- **时间限定**：`Sθ = { r ∈ R | active(σr), tr ≤ θ }`，θ 为问题中的 as-of 日期；无条件时退化为全量。**时间过滤在排序之前**执行，保证 k 个槽位都留给合格行；无日期行在 as-of 提问中不可达。
- **三条检索腿**：lex（按 cover density 匹配内容词，恢复精确标识符）、tag（匹配作者标签，很少触发）、vec（问题向量与 `e` 的余弦相似度，恢复同义改写）。
- **加权 RRF 融合**：`RRF(r) = Σ_ℓ w_ℓ / (γ + rank_ℓ(r))`，使用秩而非原始分数，故无需分数归一化；同分按摄入新近度打破。
- **新近度保留槽**：k 个结果中 `k−3` 个按融合分返回，其余 **3 个槽位保留给"匹配行中事件日期最新者"**（无日期则回退到摄入时间），若不足则用最近摄入的未匹配行补齐。
- **证据呈现**：按排名渲染原文，前缀为事件日期（及作者标签，如有）；Φ **不读取 σ 的取代关系**，被取代行与活跃行平等竞争。Mem++ 在回答时不增加任何推理步骤，定位为"记忆"而非"推理器"。

### 2.5 图检索变体 Memg++
- 引入 Mem0g 式实体-关系图：写入时每篇文档 2 次 gpt-4o-mini 抽取三元组，查询时 1 次调用抽实体并搜索，最多追加 5 条三元组到融合结果之后。
- **三元组不带日期，as-of 条件不适用**，因此有日期的问题可能被"晚于 θ 的关系"污染。

**规模概览**

**客观性与公平性**
- **偏保守的公平设置**：Mem++ 使用较弱的 all-MiniLM-L6-v2，而所有检索基线使用更强的 text-embedding-3-small；Mem0/Zep 的检索上下文同样交给同一回答模型生成答案。

  - OrgMemBench 只有 73 题、6 个类别中 Contradiction 仅 6 题、Bi-temporal 仅 7 题，**统计功效有限**；只有 15 题带 as-of 日期；
  - 消融仅在单一回答模型（claude-sonnet-4-6）上运行，未跨模型验证；

## 6. 主要结论与发现

- **组织记忆上领先**：gpt-4.1-mini 下 Mem++ 总体 57.6，**超最强基线 RAG 2.6 分**；gpt-4o-mini 下 Memg++/Mem++ 以 44.4/44.2 居前二。相对"结构化记忆系统"，优势达 **+13.1（vs A-Mem, gpt-4.1-mini）与 +8.0（vs Zep, gpt-4o-mini）**。
- **Supersession 与 Audit Replay 最强**：Supersession 双模型均为最佳（67.7 / 57.0）；Audit Replay 在 gpt-4

.1-mini 下以 55.3 领先；Bi-temporal、Decision Provenance、Justification Chain 三类的表现随后续讨论。

- **Supersession 与 Audit Replay 最强**：Supersession 双模型均为最佳（67.7 / 57.0）；Audit Replay 在 gpt-4.1-mini 下以 55.3 领先，说明"保留全部历史原文 + 时间限定检索"确实服务于版本演进类问题。
- **Contradiction 是明显短板**：该类得分偏低且不稳定，作者归因于仅 6 题的小样本、以及"读取时选择"范式本身不主动做矛盾消解——模型需要自己在并存原文中发现冲突，而 40K 字符截断进一步限制了可比较的文档数。
- **对话基准上不占优但保持竞争力**：LoCoMo 上 Mem++ 未显著超过 Mem0/Zep/A-Mem 等专用系统，作者解释为对话记忆"单一叙述者、天然可覆盖"的特性与 Mem++ 的"多版本并存"假设不匹配，属**范式错配**而非能力缺陷；LongMemEval-S 上 Mem++ 在部分类别（如 temporal、知识更新）表现稳定，验证了长历史下的可扩展性。
- **消融结论**：三条检索腿互补——去掉 vec 腿伤害最大（同义改写无法恢复），去掉 lex 腿伤害精确标识符类问题，tag 腿触发少但提供溯源线索；启用合并算子 C **未带来稳定增益**，部分类别反而下降（合并行丢失了原始条件与措辞），支持"默认关闭合并、把选择权交给读取"的设计选择；Memg++ 相对 Mem++ 的增益有限且不稳定，在 as-of 问题上因三元组无日期而**出现污染**，印证"图抽取引入的时间信息损失"。
- **敏感性**：k 从 5 增到 30 时分数单调上升，30 之后趋于平台（受 40K 截断限制，更多检索结果无法进入回答模型）；检索 token 量随 k 线性增长，作者据此推荐 k 取中等值（约 30–50）。
- **总体论点成立**：在"多作者、多版本、历史即问题"的组织场景下，**读取时选择（Mem++）优于写入时蒸馏（Mem0/Zep）**；而在对话场景下两者接近，说明蒸馏并非普遍失效，而是**对特定记忆形态有偏**。

## 7. 局限性（作者自述 + 分析者补充）

**作者明确承认的**
- 只在合成组织数据（OrgMemBench）上验证，真实企业邮件/工单的噪声、隐式引用、非规范日期未覆盖。
- Mem++ 不做推理，复杂多跳与矛盾消解仍需回答模型自身能力。
- 组织基准规模小（73 题、6 类中部分仅 6–7 题），结论的统计稳健性受限。

**分析者补充的**

- **算力与成本不透明**：无延迟、token 成本、显存占用的定量报告，无法评估真实部署可行性；Memg++ 的"每文档 2 次 + 每问题 1 次"调用在大规模语料上可能昂贵。
- **评委偏置**：gpt-4o-mini 同时作为回答模型与评委，存在同族自偏好风险，且未报告人工校验或第二评委一致性。
- **σ 语义未被读取**：设计上"被取代行与活跃行平等竞争"，虽然保留了历史，但也放弃了系统已知的取代信号，可能让回答模型被陈旧版本干扰（Contradiction 类表现不佳或与此相关）。
- **时间过滤的硬边界**：无日期行在 as-of 提问中不可达，真实数据中大量缺失日期的文档会被系统性排除。

## 8. 启示与可迁移经验

- **范式层面**：记忆系统的核心设计选择是"**何时做信息损失**"——写入时蒸馏省检索成本但固化可答范围；读取时选择保留全部原文但把判断负担交给回答模型。当"历史版本本身是查询对象"时，后者更安全。
- **工程层面**：仅追加（append-only）+ 状态标记（σ）是一种廉价而有效的版本化策略，无需删除即可支持 as-of 查询；多索引（词法 + 向量 + 标签）融合用秩而非分数，避免了跨索引归一化难题。
- **方法层面**：合并算子 C 的消融结果提示——**LLM 生成的合并文本会丢失条件与措辞**，在需要精确引用或审计的场景中应慎用；这类"语义压缩"收益需与保真度损失权衡。
- **评测层面**：本文暴露的两个陷阱值得警惕——(1) 评测截断可能让被设计的新机制从未生效；(2) 用同一模型既答题又评分会引入系统性偏差。

## 9. 一句话总评

Mem++ 用一个**极简、免训练、仅追加**的记忆库和**多索引融合 + 新近槽位**的读取策略，论证了"组织记忆应当保留版本、把选择权留给读取"这一范式主张，在组织型基准上取得领先；但其结论受制于小规模合成数据、评测截断与成本透明度不足，**范式洞见强于实证强度**。
