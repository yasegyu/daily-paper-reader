## 摘要
LLM智能体依赖长期记忆，以在长时程任务中保留并复用信息。现有方法对处理因新观测或领域证据到来而过时的记忆支持有限。此类过时记忆可能仍具有语义相关性，会继续影响依赖记录，并作为历史证据保留价值。这要求两种能力：依赖追踪以识别下游影响，以及历史保留以保留有用的过往记录。我们提出溯源感知级联记忆失效（PACMI），一个在带有类型化依赖边的溯源图中表示记忆和新证据的框架。PACMI将记录分配到一个四状态有效性格，将有效性变化传播到依赖记忆，并利用所得状态进行检索和过时前提检测。我们还引入一个诊断基准，包含五个领域中的100个案例和300个查询。评估分别考察节点级、上下文级和答案级性能。PACMI在该基准上取得最高的最终答案准确率，其与最强基线的配对差异在精确McNemar检验下显著。前提检查器在受控查询分布上达到完美的精确率、召回率和F1。级联传播主要提升记忆状态正确性：移除它会使最终答案错误从3增至11，但配对差异未达到0.05显著性阈值。代码和数据将公开提供。

## Abstract
LLM agents rely on long-term memory to retain and reuse information when performing tasks over long horizons. Existing methods provide limited support for handling memories that become outdated as new observations or domain evidence arrive. Such outdated memories may remain semantically relevant, continue to affect dependent records, and retain value as historical evidence. This calls for two capabilities: dependency tracking to identify downstream effects and historical preservation to retain useful past records. We propose Provenance-Aware Cascading Memory Invalidation (PACMI), a framework that represents memories and new evidence in a provenance graph with typed dependency edges. PACMI assigns records to a four-state validity lattice, propagates validity changes to dependent memories, and uses the resulting states for retrieval and stale-premise detection. We also introduce a diagnostic benchmark with 100 cases and 300 queries across five domains. The evaluation separates node, context-, and answer-level performance. PACMI achieves the highest final-answer accuracy on this benchmark, and its paired difference from the strongest baseline is significant under an exact McNemar test. The premise checker achieves perfect precision, recall, and F 1 on the controlled query distribution. Cascading propagation primarily improves memorystate correctness: removing it increases final-answer errors from 3 to 11, but the paired difference does not reach the 0.05 significance threshold. Code and data will be made publicly available.

# PACMI 论文总结

## 1. 核心问题与整体含义

- **研究背景**：LLM 智能体在长时程任务中依赖长期记忆来保留和复用跨会话信息，已被广泛应用于个性化助手、任务自动化和多步问题求解。现有记忆系统（文本/向量索引、时序方法、图结构方法）主要关注**存储、组织与检索**，却很少关注新证据到来后**已存记忆是否仍然有效**。
- **核心问题**：新观测或领域证据会使用户位置、偏好、目标、计划等发生更新，但智能体常无法识别这些失效记忆，尤其在**隐式更新**场景下；反复的 LLM 重写还会引入新错误。
- **关键洞察**：
  - **语义相关性无法解决问题**——过时记忆可能仍高度相关并被检索出来。
  - **过时记忆并非总是无用**——它可能不再支持当前决策，但仍是合法的历史记录，也可能影响下游的声明、假设或推荐。
- **所需能力**：同时具备（1）**依赖追踪**以识别下游影响，（2）**历史保留**以保留有用的过往记录。论文将此定位为自然语言智能体记忆上的**真值维护系统（TMS）**问题，与经典的依赖导向信念修正、数据库溯源与增量视图维护一脉相承。

## 2. 方法论

### 核心思想
- 将先前记忆与新证据表示为**带类型化依赖边的记忆溯源图** `G_t = (V_t, E_t)`，其中先前记忆节点存储文本记录（事实、计划、推荐、声明、历史笔记、过往决策等），边为 `supports`、`used-by`，关系分类后可新增 `updates` 或 `contradicts` 边。
- 将局部语义判断与全局有效性传播**分离**：辅助 LLM 只做局部关系分类，依赖结构上的传播由确定性遍历完成。

### 四状态有效性格（Validity Lattice）
- 从左到右当前导向检索资格递减：**active < needs-verification < historical-only < superseded**。
- 该排序不是约定，而是**推理时查询相关检索偏置的排序**（当前导向查询分别为 +0.12、+0.04、−0.10、−0.22），并诱导多路径到达同一节点时的“**保留更强状态**”规则。
- 状态赋值**非破坏性**：原文保留，superseded 记录仍可作为历史证据。

### 算法流程（Algorithm 1）
1. 插入新证据 `e_{t+1}`，将所有推理时状态初始化为 active；
2. 对至多 k=6 条先前记忆排序得到候选集 `C`；
3. 对每个候选预测关系（duplicate / refine / update / contradict / temporally-compatible / unrelated），经确定性 slot、稳定性、时序约束归一化；
4. 仅 `update`/`contradict` 可产生**直接目标** `D`，赋予直接非当前状态并加边；
5. 从 `D` 出发对出向依赖边做**广度优先遍历**，按 `supports → needs-verification`、`used-by → historical-only` 映射下游状态，多路径取更强状态，未到达节点保持 active。

### 关键细节
- **候选评分**：`s_cand = 0.82·s_cos + 0.18·s_tok + 0.08·I[σ_e = σ_i ≠ other]`（余弦相似度 + token 级 Jaccard + 语义槽匹配加成）。
- **有效性感知检索**：查询时得分为余弦相似度 + 有效性状态偏置 + 0.06 新证据加成 + 0.05 槽匹配加成 + 0.04 归一化时近性加成；当前查询偏好 active/needs-verification，历史查询偏好 historical-only/superseded。
- **前提检查（Premise Checking）**：消费推断出的**图状态**而非仅检索上下文，对比 superseded 旧记录与新证据和 active 记录；若检测到查询假定过时事实，则在答案提示中插入旧事实与当前事实的纠正块，否则使用与基线相同的中性提示。

## 3. 实验设计

### 数据集 / Benchmark
- 论文自建**过时记忆依赖诊断基准**：**100 个案例、300 个查询、5 个领域**（Personal Profile、Location & Preference、Work & Project、Finance & Recommendation、Tool/Workflow State，每域 20 例）。
- 每案例含 **6 条先前记忆、1 条新证据、3 个查询**：
  - Q1 当前状态查询、Q2 过时前提查询、Q3 历史状态查询；
  - 6 条记忆设计为：直接受影响记忆、下游记忆、仍有效的相关记忆、语义相似硬负例、无关干扰项、额外支撑信息。
- 依赖结构固定为**两跳链** `M1 --supports--> M2 --used-by--> M3`，M4–M6 为 active；标注状态为 `{active, superseded, needs-verification, historical-only}`。

### 对比方法
- **Vector RAG**：语义 top-k 检索；
- **Recency-RAG**：加入时近性得分（0.7 相似度 + 0.3 时近性）；
- **LLM-Only Update**：本地分类并原地重写候选记忆后再余弦检索；
- **CUPMem-style**：改编自 STALE，对直接替换的单值槽做 supersession，允许历史查询取旧值，但不传播下游；
- **A-MEM-style**：构建语义链接并扩展一跳邻居，无显式有效性传播；
- **PACMI** 及 5 个消融变体。

### 评估指标（三层分离）
- **节点级**：Direct Stale-Node Recall (DR)、Affected-Node Recall (AR)、Over-/Under-Invalidation (OI/UI)；
- **上下文级**：Stale-in-Context (SIC)、Current Valid-Evidence Recall (CVER)，仅在当前导向查询（Q1/Q2）上计算；
- **答案级**：Final Accuracy、Stale Reuse、Premise Resistance（Q2）、Q3 历史保留准确率，由固定 `deepseek-v4-pro` 评判器按同一零温度评分标准打分。
- **统计**：10,000 次案例级 bootstrap 重采样（种子 20260728）给出 95% 置信区间；三个预设配对比较使用双侧精确 McNemar 检验。

## 4. 资源与算力

- 论文**未使用本地 GPU 训练**：所有答案生成、关系分类、前提检查、评判调用均发往**托管 API**（`https://api.deepseek.com`，OpenAI 兼容客户端 2.41.1），模型别名为 `deepseek-v4-pro`（最终答案 + 评判）和 `deepseek-v4-flash`（中间操作）。

- **未报告训练时长、GPU 型号/数量或墙钟延迟**；成本核算仅统计**辅助 LLM 调用次数**（PACMI 每更新 1 次、每查询 ≤1 次，总计 ≤400 次，约为次贵方法的 4 倍），作者明确说明这只是上界而非延迟或 token 的量化。

## 5. 实验数量与充分性

- **实验组数**：1 组主结果对比（5 基线 + PACMI）、1 组消融（6 变体 × 3 层指标）、3 个配对 McNemar 检验、1 组前提检测器固有评估、1 组错误分析（枚举 PACMI 全部 3 个错误与 LLM-Only Update 全部 58 个 Q3 错误）、计算成本表、新证据覆盖率表、按依赖深度召回表。
- **客观性与公平性**：
  - 所有方法共享同一最终答案模型、嵌入模型、零温度解码，控制变量较好；
  - 统计使用 bootstrap 置信区间与精确 McNemar 检验，报告完整不一致计数而非仅显著性判断；
  - **明确自我设限**：作者指出 A1（依赖边由标注提供）使 PACMI 获得基线不具备的结构信息，A3（标签是拓扑的确定性函数）使节点级指标只能验证传播实现正确性、**不能作为优势证据**，并据此将主张建立在上下文级与答案级指标上——这是难得的诚实做法。
- **充分性不足**：
  - 每方法仅运行**一次**（零温度），无多种子方差；
  - 每案例仅 6 条记忆、上下文预算为 5，检索近乎饱和，无法反映真实记忆规模；
  - 固定两跳拓扑，**过度失效无法被触发**，多路径状态消解从未被测试；
  - 评判器与答案生成器同属一个模型家族，存在**自偏好偏差风险**；
  - A-MEM-style 上下文预算为 8，其余为 5，作者承认这会**抬高其覆盖率类指标**。

## 6. 主要结论与发现

- **答案级领先**：PACMI 最终准确率 **0.99**，最强基线 A-MEM-style 为 **0.90**（300 个配对查询中 3 vs 29 个错误），双侧精确 McNemar 检验 **p = 2.56×10⁻⁶**，显著。
- **差距集中在 Q2**：两方法在 Q1、Q3 均接近上限，基准的判别力主要来自**过时前提查询**。
- **检索上并不占优**：A-MEM-style 的 CVER 更高（0.88 vs 0.83），PACMI 在 SIC 上更好（0.34 vs 0.47），即引入更少过时
