Abstract
Memory is essential for long-horizon robotic manipulation, where successful actions may depend on past
events that are no longer recoverable from the current observation. As episodes grow longer, however,
retaining the full history becomes increasingly costly, creating a fundamental scalability challenge for
memory-augmented policies. Existing approaches address this challenge by either storing selected
past observations in a bounded memory bank or compressing interaction history into a fixed-size
parametric state through Test-Time Training (TTT). Yet these formulations do not explicitly distinguish
between historical information that can already be recovered from the policy’s current context and
information that must persist beyond it. We introduce TTT-RM, which repurposes TTT as Residual
Memory, using fast weights not to generically compress history but to complement a bounded memory
bank by preserving task-relevant historical information that cannot be recovered from the policy’s
current context. Concretely, TTT-RM learns a history decoder that reconstructs historical representations
from the current observation and retrieved memory. The resulting reconstruction residual captures
what this context fails to explain and serves as the learning target for TTT. The TTT slow weights are
optimized against this residual target so that online fast-weight updates learn to encode complementary
historical information over time. The fast-weight state is then queried to produce a residual memory
representation that conditions action generation. Extensive experiments on memory-intensive simulation
benchmarks and real-world tasks show that TTT-RM consistently improves across multiple memory
designs, outperforms diverse baselines, and supports sustained execution on a three-minute, eight-stage
stowing task.
Keywords: Test-Time Training, Robot Memory
1. Introduction
Long-horizon robotic manipulation is often partially observable, such that the current observation alone may
not contain all information needed to determine the next action (7; 13). An object may become occluded after
being moved, an instruction may need to be recalled long after it is issued, or the next action may depend on
which subgoals have already been completed and on the outcomes of earlier actions. Consequently, task-relevant
information is distributed across the interaction history, requiring the policy to integrate past evidence to
recover the latent task state. Effective policies therefore require memory mechanisms that preserve relevant
historical information for history-dependent action prediction.
Yet many state-of-the-art robot foundation models (9; 11; 12; 15; 31) condition action prediction primarily
on the current observation or a limited temporal context. While sufficient for local visuomotor reasoning, this
limited context becomes inadequate when task-relevant information originates much earlier in the episode.
Recent work addresses this limitation through two prominent memory designs. The first store selected
multimodal observations as individually retrievable records in a bounded memory bank (21; 22; 30), which we
collectively refer to as Explicit Memory (EM). EM preserves event-specific information and allows the policy to
revisit past observations when needed. Its coverage, however, is constrained by the bank capacity, so relevant
events may be omitted or evicted as the interaction history grows. Increasing the bank capacity can improve
coverage but incurs additional storage and retrieval costs.

the policy’s existing context, rather than using them as a generic history compressor.
We therefore introduce TTT-RM, a framework that augments robot policies equipped with Explicit Memory
by repurposing TTT as Residual Memory to preserve task-relevant history that cannot be recovered from the
policy’s current observation and retrieved memory. During training, a history decoder reconstructs historical
representations from this context, and the resulting reconstruction residual captures what remains unexplained.
This residual supervises the TTT slow weights so that online fast-weight updates learn to encode complementary
historical information over the course of an episode. The fast-weight state is then queried to produce a Residual
Memory representation, which is combined with retrieved memory to condition action generation. TTT-RM
reuses the visual stream already processed by the Explicit Memory module, requiring no additional encoder or
VLM forward passes. At inference time, the history decoder is discarded, while the fast-weight state is updated
at every policy call and reset at the start of each episode.
TTT-RM is compatible with multiple Explicit Memory designs, making it a modular extension to exist-
ing history-dependent robot policies. Across multiple memory-intensive simulation benchmarks, TTT-RM
consistently outperforms diverse baselines, demonstrating robust gains across different task settings. On
real-world manipulation tasks, it improves task progress by 10% to 26.5% and supports sustained execution on
a three-minute, eight-stage long-horizon stowing task.
2. Related Work
2.1. Explicit Memory for Robot Learning
A growing line of work augments robot policies with Explicit Memory, storing selected history as retrievable
records. Existing methods differ in what they retain and how they organize it. MemER (22) retains task-relevant
keyframes from prior robot experience. MemoryVLA (21) instead maintains a perceptual-cognitive memory
bank spanning visual details and higher-level semantic information. EventVLA (29) stores visual anchors
and sparse task-critical events, whereas Mem-0 (5) retains keyframes around subtask completion to support
memory-conditioned planning and execution. Other approaches organize history across representations or
temporal scales. MemoryWAM (30) integrates recent frames, event-boundary anchors, and compact gist tokens.
MEM (25) combines video-based short-term memory with text-based long-term memory, and DiM-WAM (26)

maintains bounded banks of complementary historical event tokens. LaMem-VLA (17) accesses separate
short- and long-term memory stores before encoding selected evidence into latent memory tokens. Together,
these methods extend the policy’s effective temporal context through explicit storage and retrieval, but the
information available at each decision point remains bounded by the memory budget and the records selected
for retention.
2.2. Test-Time Training and Fast-Weight Memory
Test-Time Training (TTT) was originally introduced as an adaptation paradigm in which model parameters
are optimized on unlabeled test samples using a self-supervised objective (23). Building on the broader idea
of fast-weight models (2; 19; 20), which encode past information through dynamically updated parameters,
recent work has extended TTT to sequence modeling by treating fast weights as a recurrent memory state
updated online as new inputs arrive (3; 4; 24). Beyond language modeling, related test-time optimization has
also been explored for novel view synthesis and autoregressive video generation (32). In robot learning, TTT
has recently been adopted as a memory mechanism for history-dependent control. RoboTTT (10) integrates
TTT layers into robot policies to compress interaction history into recurrent fast-weight states. WAM-TTT (8)
instead meta-trains an adaptive memory that is updated from unlabeled human videos at deployment. Our work
builds on this memory interpretation of TTT, but fundamentally changes what the fast-weight state is trained
to preserve. Rather than generically compressing interaction history, TTT-RM specializes the fast-weight state
to preserve residual information that is not recoverable from the current observation and retrieved memory.

4. Methodology
Overview. We consider robot policies equipped with Explicit Memory and seek to use TTT as a complementary
memory substrate rather than a generic history compressor. To this end, we introduce TTT-RM, which repurposes
TTT as Residual Memory. Fig. 2 illustrates the overall pipeline. TTT-RM first learns a history decoder that
reconstructs historical information from the policy’s current observation and retrieved memory. The resulting
reconstruction residual captures the history unexplained by this context and supervises TTT so that online fast-
weight updates learn to encode it over time. The fast-weight state is then queried to produce a Residual Memory
representation, which is combined with the retrieved memory to condition action generation. Secs. 4.1–4.3
detail the history decoder, residual-memory learning, and training and inference procedures.
4.1. History Decoder Learning
Under a finite memory budget, Explicit Memory retains only a subset of historical representations. Yet historical
information is often redundant, and representations not retained by EM may still be recoverable from the current
observation and retrieved memory. Treating all unretained history as missing would therefore overestimate
what additional memory needs to preserve. We therefore define the target of Residual Memory by what remains
unexplained by the policy’s existing context, rather than by what EM fails to retain. We operationalize this
distinction with a history decoder that reconstructs historical representations from the current observation and
retrieved memory.

4.2. Test-Time Training as Residual Memory
With the history decoder fixed, we next repurpose TTT as Residual Memory. TTT-RM consists of three key
elements. First, an inner-loop update writes incoming visual information into the fast-weight state. Second,
the updated state is queried to produce a Residual Memory representation for action generation. Third, an
outer-loop objective uses supervision from the frozen history decoder to optimize the slow parameters, shaping
the online updates to preserve historical information that is not recoverable from the current observation and
retrieved memory.

4.3. Training and Inference
Training. We train TTT-RM in three stages. First, we train the history decoder D using Eq. 8 and freeze it
as the reference for constructing residual targets during subsequent policy training. Second, we train only
the newly introduced Residual Memory components while keeping the inherited Explicit Memory and action
policy frozen. At this stage, the fast-weight initialization ϕ0, visual writer K, reader Q, and zero-initialized
action adapters are jointly optimized using Eq. 14. Finally, we fine-tune the full policy with Eq. 14, allowing
the inherited Explicit Memory and action components to adapt jointly to Residual Memory. Alg. 1 summarizes
the training procedure.
Inference. At inference time, the history decoder is discarded and all slow parameters remain fixed. The
fast weights are initialized from ϕ0 at the beginning of each episode and updated once per policy call as
new observations arrive. Within each policy call, the updated fast-weight state remains fixed across all flow-
integration steps and is reused to condition action generation, avoiding repeated inner-loop updates for the
same observation. The fast-weight update is implemented as an explicit gradient step within the forward
pass. During training, the same update remains differentiable, allowing gradients to propagate through the
inner-loop step to the slow parameters.

5. Experiments
We evaluate TTT-RM in both simulation and real-world settings across tasks requiring diverse forms of long-
horizon memory. We compare against strong memory-based baselines and conduct targeted ablations and
diagnostic analyses to isolate the contribution of individual design choices.
5.1. Simulation Benchmarks
We first evaluate TTT-RM on two memory-intensive manipulation benchmarks, RoboMME (6) and RMBench (5).
RoboMME is a large-scale benchmark for long-horizon, history-dependent manipulation, comprising 16 tasks
grouped into four suites: Counting, Permanence, Reference, and Imitation. These suites target temporal,
spatial, object, and procedural memory, respectively, covering diverse forms of history dependence. RMBench
contains nine dual-arm manipulation tasks at two levels of memory complexity. M(1) tasks require a single
past observation to disambiguate the current state, whereas M(n) tasks require integrating information from
multiple past observations to determine the appropriate action. Together, these benchmarks cover both diverse
memory types and varying degrees of historical dependence. For a controlled comparison, all methods follow
the same evaluation protocol within each benchmark.
Baselines. We compare TTT-RM against the following baselines. Unless otherwise noted, baselines with learned
action policies use the same π0.5 (9) backbone:
• Base: The memory-free policy that conditions action prediction only on the current observation.
• SAM2Act+ (7): A perceptual-memory baseline that uses SAM2 (18) to maintain a memory bank over past
observations and predicts discrete keyframe actions. The predicted actions are executed by an external
motion planner rather than a learned action policy.
• MemER (22): A dual-system baseline that stores selected keyframe observations and uses a VLM (28) to
infer symbolic subgoals from the accumulated memory. The resulting subgoals are executed by the base π0.5
policy.

Results. Tab. 1 reports the results on RoboMME. Standalone TTT yields mixed performance across integration
designs. The Modul variant improves the average success rate from 18.4% to 21.9%, whereas Expert slightly
underperforms the base policy at 17.5%. This variation suggests that simply introducing a fast-weight memory
state does not consistently improve history-dependent control, and its effectiveness depends on how the
resulting memory representation interacts with the action policy. By contrast, all Explicit Memory variants
substantially outperform the base policy, showing the benefit of explicit retrieval for the memory demands
of RoboMME under the evaluated budgets and task horizons. TTT-RM further improves every configuration,
with average success-rate gains ranging from 2.2 to 7.1 percentage points. The gains are also consistent
across task suites, with TTT-RM outperforming the corresponding EM baseline in all 16 configuration–suite
comparisons. The best-performing configuration, FrameSamp w/ Modul, improves from 42.8% to 45.4%.
Overall, standalone TTT performance depends on how fast-weight memory is integrated into the policy, whereas
TTT-RM provides consistent gains across different Explicit Memory mechanisms, integration designs, and forms
of history dependence.

5.2. Real-World Experiments
Setup. We consider three real-world manipulation tasks: (1) Pen to drawer, in which the robot moves exactly
one of the two pens in the top cabinet into a drawer and then closes the drawer; (2) Pick N pens, in which the
robot places N ∈{1, 2, 3} pens into a pen holder according to the language instruction; and (3) Stow objects, an
eight-stage long-horizon task in which the robot opens the top cabinet, transfers a toy and tea box into an open
drawer, and closes the cabinet and drawer, requiring approximately three minutes for successful completion.
We use a single-arm mobile manipulator (27) and collect approximately one hour of demonstrations per task
for policy training. The deployed policy operates at 20 Hz with a fixed action-execution horizon.
We compare against three baselines: a memory-free Base policy, an Explicit Memory variant, and a
Test-Time Training variant, all initialized from the same π0.5 backbone. For the real-world Explicit Memory
baseline, each memory entry is a compact interaction record containing the observation, commanded action,
and resulting outcome rather than visual features alone. For the TTT baseline, we re-implement RoboTTT (10)
under the same training setup as TTT-RM. We evaluate each method over 20 trials per task under varied initial
configurations. Per-trial performance is measured using a task-progress score that awards integer points for
successfully completed task stages. For controlled comparison, all methods use synchronous policy execution.
Additional task definitions, scoring criteria, and training details are provided in the Appendix.
Results. Fig. 4 summarizes the qualitative and quantitative results across the three real-world tasks. For
quantitative evaluation, we report the progress profile, defined as the empirical survival function of per-trial
task progress (1). At each progress threshold, the profile measures the fraction of trials that reach or exceed
that level of completion, providing a more detailed view of rollout quality than mean progress alone. TTT-RM
consistently outperforms all baselines across all three tasks and at every progress threshold, indicating that its
gains are distributed across different levels of task completion rather than driven by a small subset of successful
trials. On Pen to drawer, TTT-RM achieves a mean task progress of 65.5%, compared with 55.5% for the
strongest baseline. The gains are substantially larger on the more memory-demanding tasks. On Pick N pens,
mean task progress increases from 47.0% for the strongest baseline to 73.5%, and on Stow objects, from 50.5%
to 77.0%. In both cases, the improvement is also reflected throughout the progress profiles, with TTT-RM
maintaining a larger fraction of successful rollouts as progressively later stages are considered. These larger
gains suggest that Residual Memory becomes increasingly useful when successful execution requires tracking
task progress over extended horizons.

6. Conclusion
We introduced TTT-RM, which repurposes Test-Time Training as Residual Memory to preserve task-relevant
history not recoverable from the current observation and Explicit Memory. It first learns a history decoder to
reconstruct historical representations from the policy’s available context, then uses the reconstruction residual
to supervise Residual Memory learning. The resulting representation is combined with retrieved memory to
condition action generation. TTT-RM generalizes across multiple memory designs, consistently outperforms
diverse baselines, and supports sustained execution on a three-minute, eight-stage real-world stowing task.
