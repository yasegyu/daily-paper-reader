## 摘要
记忆增强智能体通常通过将检索到的技能直接注入文本提示来整合程序性知识。这种做法危险地将可读文本等同于可靠执行。为弥合这一鸿沟，我们提出“从记忆到引导”这一新范式，将程序性记忆从被动的文本传递转变为主动的、推理时的策略适配。我们通过时空编排器实例化该范式；这是一种主动策略编译器，显式管理检索到的知识应以何种方式及何时被应用。时空编排器不将技能视为即插即用模块，而是动态地将历史知识与当前环境约束对齐（空间适配），并精确规定其适用生命周期（时间编排）。它主动将静态记忆转化为严格受限的运行时指南——为智能体配备局部化目标和行为护栏，且无需任何参数更新。在 EngramBench 的 13 项高难度、长时程软件工程任务上的大量评估表明，该架构具有明显优势。时空编排器不仅能稳健地防止上下文失配，还能在最复杂的任务上实现 7.2 个百分点的绝对通过率提升，同时将主智能体的 token 使用量削减 32.2%。

## Abstract
Memory-augmented agents typically integrate procedural knowledge by injecting retrieved skills directly into text prompts. This approach dangerously equates readable text with reliable execution. To bridge this gap, we introduce From Memory to Guide, a novel paradigm that transitions procedural memory from passive text delivery to active, inference-time policy adaptation. We instantiate this paradigm through the Spatio-Temporal Composer, an active policy compiler that explicitly manages exactly how and when retrieved knowledge should be applied. Rather than treating skills as plug-and-play modules, Composer dynamically aligns historical knowledge with current environmental constraints (spatial adaptation) and precisely dictates its applicable lifecycle (temporal orchestration). It actively transforms static memories into strictly bounded Runtime Guides---equipping the agent with localized objectives and behavioral guardrails without requiring a single parameter update. Extensive evaluations on 13 demanding, long-horizon software engineering tasks in EngramBench demonstrate the clear advantages of this architecture. Composer not only robustly prevents context mismatch but drives an absolute pass-rate increase of 7.2 percentage points on the most complex tasks, while simultaneously slashing the main agent's token usage by 32.2%.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：LLM 正从被动聊天机器人演变为执行复杂真实工作流的自主智能体，但通用知识与实际执行之间存在鸿沟。程序性记忆（procedural memory）作为关键基础设施，使智能体能够积累可复用的技能（Skills），无需重新训练即可持续学习。
- **核心问题**：现有记忆增强智能体（如 AtomMem、MemAgent、Mem-α）把程序性记忆视为**静态文本仓库**，通过基础语义检索把技能直接注入提示词，危险地将"可读文本"等同于"可靠执行"。
- **两类致命错配**：
  - **空间错配**：技能源自特定源上下文（如工具配置、任务领域），与目标环境冲突。例如技能规定用 `npm`，但目标项目强制使用 `yarn`，直接执行会破坏锁文件、崩溃整个构建系统。
  - **时间错配**：软件工程任务高度顺序化，在错误阶段执行正确技能会引发级联后果。例如架构重构技能在后期调试阶段被触发，会诱导智能体拆解可用代码而非修复局部 bug。
- **理论症结**：传统机器学习中策略适配（policy adaptation）依赖连续参数优化，而提示词注入迫使智能体在离散文本空间中工作，无法保证技能安全泛化。**人类语义上可读 ≠ 模型可执行泛化**。
- **整体含义**：应把 Skill Bank 视为**编码行为策略的仓库**，经验复用问题转化为严格的**策略适配问题**。论文提出"From Memory to Guide"范式，将程序性记忆从被动文本投递转为主动的、推理时的策略适配。

## 2. 方法论

### 2.1 核心思想
- 提出 **Spatio-Temporal Composer（时空编排器）**，作为主动策略编译器（active policy compiler），将静态技能转化为动态、情境感知的执行策略。
- 两大互补维度：
  - **空间适配（环境适配器）**：将通用技能裁剪到目标工作区的具体配置，确保历史知识与本地约束不冲突。
  - **时间编排（生命周期编排器）**：将指导与演进中的执行阶段同步，精确规定技能**何时触发**以及**何时必须过期**。
- 合成后编译为 **Runtime Guide（运行时指南）**：一个高度受限的动作空间，配有局部目标和严格行为边界。**无需任何参数更新**。

### 2.2 问题形式化
- 任务 $T$ 有档案 $p_T$（目标、规则、工具条件）；步骤 $t$ 智能体基于动态交互上下文 $h_t$ 生成动作 $a_t$。
- 原生技能使用：$a_t \sim \pi_\theta(\cdot \mid p_T, h_t, D(K, p_T, h_t))$，其中 $D$ 为检索机制，迫使基座模型每步隐式解释和适配检索知识，导致上下文错配与负迁移。
- 显式化适配过程：$g_\tau = C_\phi(p_T, K, o_\tau, g_{\text{prev}})$，$g_\tau \in G \cup \{\varnothing\}$，其中 $o_\tau$ 为执行证据，$\varnothing$ 表示无需新指导。
- 每个 Guide 是结构化策略接口：$g_\tau = (\ell_\tau, r_\tau, b_\tau, e_\tau)$：
  - $\ell_\tau$：局部目标
  - $r_\tau$：状态条件下的推荐动作
  - $b_\tau$：行为边界与适用前提
  - $e_\tau$：终止条件
- 新范式下的执行策略：$a_t \sim \pi_\theta(\cdot \mid p_T, h_t, g^{\text{act}}_t)$。**关键是将适配 $C_\phi$ 与执行 $\pi_\theta$ 解耦**。

### 2.3 架构与流程
- **三路信息来源**：任务档案 $p_T$（项目目标、业务规则、接口约束、工具条件）、执行证据 $o_\tau$（当前工作描述、会话上下文、验证结果、阻塞项）、先前 Guide $g_{\text{prev}}$（早期局部目标与建议）。
- **上下文条件化技能选择（Selector）**：将指导请求转为组合指令，输出三个结构化字段：
  - `decision`：是否生成新 Guide（结合当前目标与早期指导的反馈结果判断）。
  - `skillRefs`：从 $K$ 中选出用于当前请求的具体技能（可多选以互补）。
  - `whyNow`：记录指导决策的确切理由，识别当前执行缺口及新技能相对先前 Guide 的预期贡献。
  - **严格分离"用什么经验"（skillRefs）与"为什么现在需要"（whyNow）**。
- **空间组合**：由 whyNow 驱动，把抽象经验映射到具体项目实体，将相关规则对齐为连贯的推荐动作 $r_\tau$，并施加由 $p_T$ 决定的行为边界 $b_\tau$。
- **时间适配**：用显式生命周期规格（$e_\tau$ 与 $b_\tau$ 中的适用前提）约束 Guide。执行智能体通过 `Applies When`、`Verification`、`Termination` 子句独立判断指导是否继续。目标完成、阶段变化或不可逾越的阻塞会触发重新评估。
- **算法 1（运行时流程）**：初始化 $g^{\text{act}}_0 \leftarrow \varnothing$，向智能体提供 Catalog(K)；循环中智能体识别局部目标，若请求指导则记录 $\tau \leftarrow t$、提取证据 $o_\tau$、调用 Selector 得 $(d_\tau, R_\tau, w_\tau)$；若 $d_\tau$=Generate 则调用 Composer 生成 $g_\tau$ 并设为活跃 Guide，否则 $g_\tau \leftarrow \varnothing$；执行后检查终止条件，若终止则 $g_{\text{prev}} \leftarrow g^{\text{act}}_t$、清空活跃 Guide、执行"需求重入"（requirement re-entry）并更新上下文。

- **对比方法**：
  - **Codex + Skills**（基线）：用原生 Skill 机制访问固定技能库，由执行智能体自行解释和应用。

- **组件控制**：
  - **Selector-only**：仅选择并直接交付技能内容，不做 Guide 组合，检验情境化组合的贡献。
  - **Generic Advisor**：生成无技能输入的通用运行时建议，检验技能锚定的贡献。
- **设计消融**：
  - **w/o Dynamic Evidence**：移除组合模块对当前执行进度和反馈的直接访问，检验动态证据对状态条件化组合的贡献。
  - **w/o Lifecycle**：保留动态 Guide 生成但移除显式局部终止与需求重入规格，检验指导生命周期的贡献（全局任务需求仍生效）。
  - 组件控制与设计消融在 **DockChain、CarbonLedger、EscrowGuard、FlagFoundry** 四个任务上进行，每任务每条件 3 次运行。
- **评估指标**：
  - **任务质量**：每任务 3 次运行的平均确认通过率（confirmed-pass rate），分母包含被排除和诊断实例；聚合率按相同规则跨任务和运行合并计数。
  - **执行侧 token 效率**：主编码智能体开发期累计输入和输出 token（区别于辅助模型编排成本）。
  - **开发时间**：每次运行时长及累计时间（含工具执行与 Guide 等待），不含最终隐藏测试评估。

## 6. 主要结论与发现

- **任务质量与效率双提升**：在最复杂的 4 个任务子集（平均 8.48 小时/次）上，Composer 将聚合确认通过率从 **29.9% 提升到 37.1%**，绝对提升 **7.2 个百分点**，同时主编码智能体累计 token 使用量减少 **32.2%**。AccessSentinel 提升 9.4 个百分点，CreatorRightsExchange 提升 9.3 个百分点。
- **其余 9 个任务**：累计确认通过从 458 增至 563，相对提升 **22.9%**；主智能体 token 使用减少 **6.86%**。
- **超越技能选择与通用建议**：在 4 任务对比中，Composer 累计确认通过 229，Codex + Skills 为 173（相对提升 32.37%），Selector-only 为 149，Generic Advisor 为 157。Composer 比 Selector-only 多 80 次、比 Generic Advisor 多 72 次，且在每项任务上均优于三个基线。
- **双轴消融验证**：
  - 动态执行证据：累计确认通过从 190 增至 229，聚合通过率从 34.23% 升至 41.26%，提升 **7.03 个百分点**（4 任务中 3 个改善）。
  - 显式指导生命周期：累计确认通过从 173 增至 229，聚合通过率从 31.17% 升至 41.26%，提升 **10.09 个百分点**（4 个任务全部改善）。
  - 表明空间锚定与时间生命周期对可靠执行均不可或缺。
- **机制观察**：以 DockChain 为例，Port Call Guide 将事务一致性、幂等性和接口兼容性绑定到当前局部目标；实现与验证完成后 Guide 终止，智能体重读需求、识别下一局部目标并提交新的指导请求，体现"情境条件化生成 → 有界执行 → 需求重入"的持续循环。

## 7. 优点

- **范式创新**：将程序性记忆从"静态文本仓库"重新概念化为"可适配策略资源"，把经验复用问题转化为策略适配问题，视角新颖且理论动机清晰。
- **空间—时间双轴设计**：显式解决上下文错配的两大来源，结构上分离"选择什么经验"（skillRefs）与"为什么现在需要"（whyNow），避免信息损失。
- **无需参数更新**：实现真正的推理时策略适配，主智能体与 Skill Bank 保持固定，工程可行性强、部署成本低。
- **质量与效率兼得**：在提升通过率的同时显著降低 token 消耗，说明良好的指导可减少无效探索和调试循环。
- **实验规模与真实性**：13 个长时程任务、335+ 小时、单次最长超 12 小时，贴近真实软件工程场景。
- **消融设计严谨**：组件控制（Selector-only、Generic Advisor）与设计消

融（w/o Dynamic Evidence、w/o Lifecycle）结合，能同时验证情境化组合与生命周期管理的必要性，且消融方向与核心论点一一对应。
- **可解释性设计**：`whyNow` 字段强制记录指导决策理由，`Applies When`、`Verification`、`Termination` 子句使 Guide 的生效与失效条件显式化，便于调试、审计与人工干预。
- **动作空间约束**：将技能编译为"局部目标 + 推荐动作 + 行为边界 + 终止条件"的受限接口，降低智能体在离散文本空间中自由解释技能的风险，从机制上抑制负迁移。

## 8. 局限与不足

- **执行模型单一**：仅验证 Codex + GPT-5.5，未考察不同基座模型（尤其是推理能力较弱的模型）下 Composer 的收益是否稳健。由于适配依赖模型对结构化 Guide 的遵循能力，跨模型泛化性存疑。
- **基准单一**：全部实验基于 EngramBench 的 13 个迁移任务，未在 SWE-bench、WebArena 等主流智能体基准上验证，外部效度有限。
- **缺少与同类记忆方法的直接对比**：未与 ExpeL、Agent Workflow Memory、Memento、MemRL、AtomMem、MemAgent、Mem-α 等方法在同一设置下实验对照，仅作定性区分，难以量化相对优势。
- **样本量与统计严谨性不足**：每任务每条件仅 3 次运行，未报告置信区间、显著性检验或方差，长时程任务本身波动大，均值可能掩盖不稳定行为。
- **消融覆盖面有限**：组件控制与设计消融仅在 4 个任务上进行，且这 4 个任务是"最复杂子集"，结论未必可外推到其余 9 个任务。
- **辅助编排成本未量化**：论文强调主编码智能体 token 下降，但 Selector 与 Composer 的额外 LLM 调用成本、延迟与总开销未报告，端到端成本优势不完整。
- **超参数与设计选择敏感**：何时触发指导请求、如何判断终止条件、`decision` 生成策略等关键机制依赖智能体自主判断，论文未系统分析这些自由度的敏感性。
- **评估器依赖**：最终产物由任务专属评估器评定，可能存在评估器与任务设计耦合带来的偏差；隐藏测试虽保留用于评估，但评估器本身的可靠性未讨论。
- **技能库规模固定且较小**：Skill Bank 仅 18 个技能且全程固定，未研究技能库增长、冲突或冗余对 Selector 与 Composer 的影响。
- **理论刻画偏定性**：虽将问题形式化为策略适配，但未给出适配误差或负迁移的理论界，空间/时间错配的解决缺乏可证明保证。

## 9. 启发与展望

- **程序性记忆的新定位**：把 Skill Bank 视为"策略仓库"而非"文档库"，为记忆增强智能体提供了从检索范式向编译/适配范式迁移的清晰路径，可推广到非软件领域（如机器人操作、科学实验流程、企业工作流）。
- **推理时适配的通用性**：无需参数更新即可实现策略适配，意味着该方法可与任意冻结的基座模型组合，适合作为智能体框架的中间层组件。
- **空间—时间双轴的普适性**：环境适配与生命周期编排是任何"跨上下文复用经验"场景的共性挑战，双轴框架可作为设计原则迁移到其他经验复用系统。
- **可探索方向**：
  - 在更多基座模型（含开源模型）与更多基准上验证收益稳健性；
  - 引入自动化超参数搜索或学习式触发策略，减少对智能体自主判断的依赖；
  - 研究技能库动态增长、冲突消解与版本管理；
  - 量化端到端成本（含编排开销），并探索更轻量的 Selector/Composer 实现；
  - 为策略适配建立理论保证，刻画何时适配可避免负迁移；
  - 将 Guide 的终止与重入机制形式化为状态机，提升可靠性与可验证性；
  - 与主流记忆增强方法在同一协议下正面对比，明确相对贡献边界。

## 10. 总体评价

论文提出了一个理论动机清晰、工程可落地的新范式：将程序性记忆的经验复用从"静态检索注入"重构为"推理时策略适配"，并以空间适配与时间编排双轴、结构化 Runtime Guide、无需参数更新的方式落地。实验在 13 个长时程软件工程迁移任务上显示，Composer 在提升确认通过率的同时显著降低主智能体 token 消耗，且消融表明动态执行证据与显式生命周期管理均不可或缺，方向与核心论点高度一致。其最大贡献在于问题重构与机制设计，而非单纯性能数字。主要短板在于执行模型与基准单一、缺少与同类方法的直接对比、样本量与统计严谨性不足、编排成本未量化。总体而言，这是一项视角新颖、设计自洽、结果有说服力的工作，为记忆增强智能体提供了从"记忆"走向"引导"的可行路线，但外部效度与理论保证仍有待后续研究补强。
