## 摘要
记忆已成为LLM智能体生态不可或缺的组成部分，支持跨交互的信息保留与复用。然而，大多数现有智能体记忆系统以查询无关的方式构建记忆，这可能导致不必要的预处理成本，并丢弃后续被证明至关重要的细节。近期研究已开始将记忆处理转向运行时自适应，但通常局限于特定操作或固定处理方案，使得对性能、成本和延迟的灵活控制在很大程度上仍未得到充分探索。为应对这一挑战，我们提出MemPilot——一个灵活的框架，可在不同的性能—成本—延迟偏好下编排按需记忆整理。具体而言，我们通过强化学习优化一个多步LLM策略，使其迭代地在从查询无关记忆中检索与将原始多模态历史的查询特定整理委派给异构LLM和VLM之间进行选择。该策略联合控制证据量、整理指令、模型选择和视觉访问，从而实现运行时计算的细粒度分配。为在相互竞争的目标下优化该策略，我们采用目标级优势解耦，在聚合之前分别估计每个目标的优势。此外，我们引入基于前缀的边际效用估计，以在多步rollout中实现细粒度信用分配。在五个多模态智能体记忆基准上的实验表明，在不同的优化偏好下均能取得有利的性能—成本—延迟权衡，且偏好扫描产生的前沿比现有权衡感知基线更广。

## Abstract
Memory has become integral to the LLM agent ecosystem, supporting information retention and reuse across interactions. However, most existing agent memory systems construct memory in a query-agnostic manner, which can incur unnecessary preprocessing cost and discard details that later prove essential. Recent studies have begun shifting memory processing toward runtime adaptation, but typically specialize in particular operations or fixed processing schemes, leaving flexible control over performance, cost, and latency largely underexplored. To address this challenge, we present \textbf{MemPilot}, a flexible framework that orchestrates on-demand memory curation under different performance--cost--latency preferences. Specifically, we optimize a multi-step LLM policy via reinforcement learning to iteratively choose between retrieving from query-agnostic memory and delegating query-specific curation of raw multimodal history to heterogeneous LLMs and VLMs. The policy jointly controls evidence amount, curation instructions, model selection, and visual access, enabling fine-grained allocation of runtime computation. To optimize this policy under competing objectives, we adapt objective-wise advantage decoupling by separately estimating each objective's advantage before aggregation. Moreover, we introduce prefix-based marginal utility estimation for fine-grained credit assignment across multi-step rollouts. Experiments on five multimodal agent-memory benchmarks demonstrate favorable performance--cost--latency trade-offs across optimization preferences, with preference sweeps yielding broader frontiers than existing trade-off-aware baselines.

- **趋势与缺口**：近期研究开始将记忆处理转向**运行时自适应**（如 query-time 证据蒸馏、按需记忆构建、自适应记忆策略），但通常局限于特定操作或固定处理流水线，缺乏对性能、成本、延迟的灵活编排。
- **三大关键局限**：
  1. **运行时记忆控制结构僵硬**：依赖手工设计操作或固定模块/预算档位/启发式，查询级自适应自由度小，难以做细粒度权衡优化。

  3. **固定处理后端假设**：忽略异构模型在整理质量、成本、延迟上的显著差异，限制了对查询难度与证据模态的适应能力。
- **核心研究问题**：如何在可控的性能—成本—延迟权衡下，自适应地编排运行时多模态记忆整理？

## 2. 方法论

### 核心思想
- 采用**双视图记忆表示**：保留可替换的查询无关记忆库 \(M\)（兼容现成记忆系统，用于高效访问），同时保留原始多模态历史 \(H\)（分块保留图文上下文，用于查询特定运行时整理）。
- 将按需记忆整理建模为**多步决策过程**，由 LLM 编排策略 \(\pi_\theta\) 迭代地在“检索”与“委派整理”之间选择，实现运行时计算的细粒度分配。

### 关键技术细节
- **序列决策形式化**：状态 \(s_t=(q,a_{<t},o_{<t})\)，动作 \(a_t=(z_t,\phi_t)\)；动作类型 \(z_t\in\{\text{Retrieve},\text{Curate}\}\)。
  - Retrieve：对压缩记忆库做语义相似度检索 \(R_M(\phi_t)\)；
  - Curate：对原始历史做查询特定整理 \(C_H(\phi_t)\)，委派给异构 LLM/VLM 池。
- **因子化整理控制**：动作参数按类型分解：
  - Retrieve：\((r_t,k_t)\)；
  - Curate：\((r_t,k_t,i_t,m_t,v_t)\)。
  - 其中 \(r_t\) 为检索查询、\(k_t\) 为证据数量、\(i_t\) 为整理指令、\(m_t\) 为模型选择、\(v_t\) 是否包含原始视觉证据。**将“检索什么”与“如何整理”解耦**，避免语义混淆。
- **异构模型委派**：编排器仅接收匿名模型 ID 与轻量画像（参数规模、支持模态），自身保持纯文本、不直接处理图像像素；模型选择成为权衡控制的自然维度。

### 资源感知奖励建模（算法流程）
- **资源感知 GRPO**：对每个查询采样 \(G\) 条轨迹，定义三个目标奖励 \(r^Q_i=Q(\tau_i)\)、\(r^C_i=-C(\tau_i)\)、\(r^L_i=-L(\tau_i)\)；成本含编排器与外部模型 token 成本，延迟用代理估计器以保证训练稳定。
- **目标级优势解耦**：对每个目标独立组内归一化 \(A^j_i=\frac{r^j_i-\mu^j}{\sigma^j+\epsilon}\)，再按偏好 \(\lambda\) 加权聚合并在 batch 级再归一化，避免直接混合奖励掩盖各自学习信号。
- **基于前缀的边际效用**：在每个整理阶段后截断后续操作并直接生成答案 \(\hat{y}_{i,t}\)，令 \(u_{i,t}=Q(\hat{y}_{i,t})\)、\(\Delta u_{i,t}=u_{i,t}-u_{i,t-1}\)，作为该阶段边际质量贡献；仅对质量做探测以避免与资源惩罚重复计数，并将 \(\eta\Delta u_{i,t}\) 加到该阶段对应的策略推理与动作 token 上，实现细粒度信用分配。
- **最终损失**：带裁剪与 KL 正则的 GRPO 损失，其中阶段细化优势替换轨迹级优势。

## 6. 主要结论与发现

- **可控权衡**：MemPilot 在不同偏好下跨越多个质量—成本区间；MemPilot-Perf 在全部 5 个基准、两种回答模型下取得最佳 L-J；MemPilot-Bal 提供明显的中间权衡点；MemPilot-Cost 达到接近文本中心系统的低成本区。
- **前沿更广**：偏好扫描得到的性能—成本、性能—延迟前沿在较宽范围内包络现有方法，优于 LightMem、BudgetMem、OmniSimpleMem 等权衡感知基线。
- **运行时适应不等于可控权衡**：GAM、AgeMem、Mem-T 等虽在推理时自适应，但基本暴露固定运行点；MemPilot 能显式跨运行点调节。
- **多模态处理并非越贵越好**：MIRIX、M2A、MemVerse 常付出高成本却未稳定转化为更高质量；MemPilot 通过按需整理与选择性模型委派在更低成本下取得更强性能。
- **计算再分配机制**：随偏好转向低成本/低延迟，策略协同减少步数、Curate 频率、图像访问与输出 token，并将模型选择从大模型/专有 VLM 转向更便宜的模型组（最低成本点全部路由到 <70B 的 LLM）。
- **消融验证**：去除 LLM/VLM 委派（37.40→14.58）、边际效用（→14.82）、检索—指令解耦（→15.35）均造成大幅质量下降，目标优势解耦去除也降至 21.94，说明完整设计带来更优权衡而非单纯多消耗算力。
- **记忆库兼容**：替换为 SimpleMem/A-MEM 记忆库无需重训即可保持清晰前沿，说明不依赖特定查询无关记忆构建方式。

## 7. 优点

- **框架灵活性**：统一编排记忆访问、查询特定整理、异构模型委派与视觉访问，不依赖固定流水线、预算档位或固定后端。
- **多目标优化技术贡献**：目标级优势解耦 + 前缀边际效用估计，解决多目标奖励混合掩盖信号与多步信用分配粗糙的问题，且探测开销小（短答案 + 前缀 KV 缓存复用）。
- **评估全面**：IID + OOD、双回答模型、多偏好扫描、组件消融、记忆库兼容性、行为分析与案例研究，论证层次完整。
- **可解释的行为分析**：清晰展示策略如何在多个控制维度上协同再分配计算，而非单一旋钮。
- **实用性导向**：明确面向部署中的性能—成本—延迟偏好，呼应商业 LLM 服务分层提供运行点的趋势。

## 8. 不足与局限

- **隐私风险**：运行时整理会将检索到的交互历史发送给外部模型，敏感记忆存在泄露隐患；未来需引入隐私感知路由、本地处理或访问控制。
- **偏好标定不友好**：权衡通过预定义优化偏好控制，缺乏将高层部署偏好映射到奖励系数的用户友好机制。
- **延迟建模为代理**：训练使用代理延迟估计器以避免网络/服务波动，未直接优化真实测量延迟；未来需在受控沙盒中用实测延迟优化。
- **算力信息缺失**：未报告 GPU 型号、数量与训练时长，影响复现与成本评估。
- **实验覆盖限制**：策略训练仅基于 3 个 IID 数据集合并训练集，OOD 仅用于测试；单轨迹贪心评估可能低估多样性；部分基线成本异常可能影响跨方法比较的公平性。
- **应用限制**：依赖外部 API 模型池与 OpenRouter 访问，实际部署受 API 可用性、定价波动与速率限制影响；最大 6 轮整理、2 个并行调用的设置可能限制复杂查询场景。
