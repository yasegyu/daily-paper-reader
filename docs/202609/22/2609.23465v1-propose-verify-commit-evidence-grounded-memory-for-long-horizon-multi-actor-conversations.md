## 摘要
长时程对话记忆在多参与者场景中尤为具有挑战性，因为相关证据分布在不同的参与者和情境中，且先前建立的信息可能后续被修订。我们提出EGMEMORY，将长时程多参与者记忆建模为可搜索的状态机，将持久化的消息级证据与显式的活跃状态分离。在写入时，自适应状态解析和基于证据的提议-验证-提交协议管理状态的演化。在读取时，自适应证据导航迭代解析查询所需的状态和支持证据，利用对话结构缩小搜索空间，并通过词汇-语义相关性对候选进行排序。该系统通过提示和工具使用运行，无需针对记忆策略的训练。EGMEMORY在GroupMemBench上达到68.2%，在EverMemBench上达到77.9%，分别比最强基线高出22.7和21.4个百分点。此外，在双人对话基准LoCoMo上达到73.6%，展示了超越多参与者对话的泛化能力。我们将在正式发表后发布代码库。

## Abstract
Long-horizon conversational memory is especially challenging in multi-actor settings, where relevant evidence is distributed across participants and contexts and previously established information may later be revised. We introduce EGMEMORY, which formulates long-horizon multi-actor memory as a searchable state machine that separates persistent message-level evidence from an explicit active state. At write time, adaptive state resolution and an evidence-grounded propose-verify-commit protocol govern how this state evolves. At read time, adaptive evidence navigation iteratively resolves the state and supporting evidence required for a query, using conversational structure to narrow the search space and lexical-semantic relevance to rank candidates. The system operates through prompting and tool use without memory-specific policy training. EGMEMORY achieves 68.2% on GroupMemBench and 77.9% on EverMemBench, outperforming the strongest evaluated baselines by 22.7 and 21.4 percentage points, respectively. It further reaches 73.6% on the dyadic LoCoMo benchmark, demonstrating generalization beyond multi-actor conversations. We will release the codebase upon formal publication.

## 1. 论文的核心问题与整体含义

**研究动机与背景：**

- 大语言模型（LLM）智能体越来越多地运行在超出单次上下文窗口的交互场景中，**持久化记忆**已成为长时程智能体的核心组件。
- 现有记忆系统大多聚焦于**双人（dyadic）对话**或局部化交互，而**长时程多参与者（multi-actor）对话**引入了截然不同的记忆挑战：
  - 相关信息**分散在不同参与者、线程和演化情境**中；
  - 相似表述可能指向不同的讨论；
  - 先前确立的决策可能**后续被修订**。
- 两个新基准直接暴露了这些挑战：**GroupMemBench**（强调群体动态、说话者锚定信息、受众依赖语言）和**EverMemBench**（评估多方多组协作、跨情境推理与时间演化信息）。

**核心问题：**

> 在多参与者长时对话中，记忆系统必须判断**谁的证据相关**、**证据指向哪个对话状态**、以及**该状态是否仍然有效**——这不仅是检索问题，更是状态管理问题。

## 2. 论文提出的方法论

### 2.1 核心思想：可搜索状态机（Searchable State Machine）

EGMEMORY 将对话记忆建模为**可搜索状态机**，其核心在于**分离持久证据与活跃状态**：

- **持久证据层**：保留全部消息级交互历史，不可被覆盖删除；
- **活跃状态层**：显式追踪当前有效的信息状态；
- **状态转移关系**：记录证据之间的溯缘关系和版本演化。

**两个不变量：**
1. **修订非破坏性**：新证据可以改变活跃状态，但不会抹除先前的证据。
2. **状态权威显式化**：检索到的或语义相似的消息本身不重新定义当前有效状态。

### 2.2 数学形式化

记忆表示：**M_t = (E_t, S_t, R_t)**，其中 E_t 为持久证据存储，S_t 为活跃状态集，R_t 记录溯缘与转移关系。关键性质为 **E(t−1) ⊆ E_t**（证据单调累积），而 S_t 可随新证据演化。

读取过程建模为迭代式自适应访问：

- r_j = π(x, H(j−1))
- O_j = Access(M, r_j)
- H_j = H(j−1) ∪ O_j

### 2.3 写入端：证据锚定的状态演化（Evidence-Grounded State Evolution）

采用**提议-验证-提交（Propose–Verify–Commit）协议**：

1. **Propose**：LLM 代理提出结构化更新 Δ_t，包含对话主题、与现有状态的关系、状态承载值（value_quote）、先前状态引用（prior_ref）等；
2. **Verify**：确定性证据检查验证提议——状态值必须由源消息支持（token 重叠阈值 0.9），修订引用必须能解析到有效先验状态（阈值 0.8）；
3. **Commit**：验证通过的更新被转换为规范证据记录，提交到状态机，更新活跃状态。

**关键设计**：语义解释由 LLM 负责，状态修改权限由确定性检查控制，即"语义解释与状态权威分离"。

### 2.4 版本化状态维护

- 修订时，新记录 e(k+1) 通过 **≺ 关系**显式取代旧记录 e(k)，形成版本轨迹 e(1) ≺ e(2) ≺ ... ≺ e(K)；
- 所有历史版本保留在持久证据层，活跃状态由最新版本支撑；
- 对长轨迹额外构建**派生的压缩检索单元**（仅用于检索，不改变原始证据）。

### 2.5 读取端：自适应证据导航（Adaptive Evidence Navigation）

- 将读取视为**迭代式交互过程**，每次检索的条件基于此前已观察到的证据（遵循式 2）；
- **两阶段检索**：
  - 第一阶段：全局词汇-语义检索，选取少量高相关"锚点"；
  - 结构约束：由锚点诱导候选池（话题桶 + 溯缘邻域，包括回复链、版本关系等）；
  - 第二阶段：在受限池内重新应用词汇-语义检索。
  - 核心原则：**结构决定搜索范围，内容决定相关性排序**，结构不独立作为相关性信号。
- **四种读取工具**：search_memory（混合检索）、lookup_phrase（精确词汇查找）、get_current_decision（当前状态查询）、resolve_date（时间表达解析）。

## 6. 主要结论与发现

1. **EGMEMORY 显著优于所有基线**：
   - GroupMemBench：**68.2%**（超最强基线 +22.7 点）；
   - EverMemBench：**77.9%**（超最强基线 +21.4 点）；
   - LoCoMo：**73.6%**（超最强基线 +4.3 点，验证泛化性）。
2. **类别级分析**：
   - GroupMemBench 上 5/6 类别最优，最大增益在 Multi-hop（+39.0）和 Temporal（+33.9）；
   - EverMemBench 上 8/9 任务最优，Multi-hop Trajectory 从 3.6%→74.7%，Memory Awareness 三项均超 90%；
   - LoCoMo 上 4/5 类别最优。
3. **例外**：Abstention（弃权）、Adversarial（对抗）、Style（风格）三个任务未达最优，反映覆盖-弃权权衡和状态抽象对风格类信号适配不足。
4. **消融显示**：迭代读取（−7.9）、版本化状态（−5.0）和重排序（−4.7）是读取端最关键组件；证据验证（−2.3）作为状态完整性门控作用相对较小。
5. 提出核心原则：**"保留证据、演化状态、使两者都可搜索"**。

## 7. 优点

- **概念创新**：将对话记忆正式建模为可搜索状态机，明确区分"发生了什么"与"当前什么有效"，解决了平坦记忆存储中的混淆问题；
- **证据锚定**：提议-验证-提交协议将 LLM 语义解释与确定性状态修改权限分离，防止无依据的状态变更；
- **非破坏性修订**：版本化状态保留全部历史，同时支持当前值查询和历史追踪查询；
- **自适应访问**：写作和读取均采用迭代式证据导航，结构约束缩小搜索空间、内容相关性决定排序，设计合理；
- **无需专门训练**：纯提示 + 工具调用即可运行，降低部署门槛；
- **泛化验证**：在多参与者基准上优化后，在双人对话基准上也取得领先，证明方法通用性。

## 8. 不足与局限

- **验证机制局限**：确定性验证依赖源文本重叠启发式（阈值 0.9/0.8），强改写后的修订可能被误拒；词汇重叠无法保证语义正确性；
- **状态抽象局限**：显式状态机器更适合事实/决策型信息，对分散的风格、行为等软信号捕捉不足（EverMemBench 的 Style 任务仅 32.4%）；
- **成本开销**：自适应多轮交互比一次性检索需要更多模型调用，论文未优化延迟与 Token 成本；
- **评估范围有限**：仅使用单一模型族（qwen3.7-max），未跨模型验证；仅使用英文基准，未覆盖多语种；未处理说话者归属含噪的真实场景；
- **消融不充分**：消融实验仅在 GroupMemBench 上进行，未在其他两个基准验证；
- **隐私风险**：持久多方记忆可能包含敏感信息，论文仅提示需要访问控制与删除策略，未提供具体方案。
