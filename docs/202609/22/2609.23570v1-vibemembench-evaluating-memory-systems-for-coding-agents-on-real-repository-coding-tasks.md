## 摘要
编码代理处理真实仓库的编码任务，持久记忆系统有望在任务间复用经验。然而现有评估并未表明这些系统能否改善可执行的仓库工作。仓库基准测试代码变更但不隔离记忆，而记忆基准仅评分召回率而不衡量下游编码结果。我们引入VibeMemBench，一个从90个SWE-rebench V2仓库和这些目标仓库的3,634条历史轨迹中选取111个编码目标来评估记忆系统的基准。这些目标遵循SWE基准风格，涵盖缺陷修复、功能请求、接口变更和配置工作。代理在声明的记忆条件下编辑每个目标代码库，由可执行测试判定任务解决情况。仅当注入的历史经验在参考设置中改善其可执行结果时，该目标才被保留，因此每个目标都带有先前经验，且其有用性已在该设置中通过执行验证。随后将冻结的已验证经验转移给五个保留的求解器。直接注入使其中四个求解器的观测任务解决率提升1.1至4.5个百分点，同时降低所有五个求解器的代理步骤。然而，当四个现有记忆系统必须从相同历史中构建和检索经验时，十二个求解器与系统配对中有十一个未能超过匹配的无记忆基线。VibeMemBench揭示了仓库历史所蕴含的有用经验与现有记忆系统为仓库编码任务提供经验之间的差距。

## Abstract
Coding agents operate on real repository coding tasks, and persistent memory systems promise to reuse experience across tasks. Yet existing evaluations do not show whether those systems improve executable repository work. Repository benchmarks test code changes but do not isolate memory, while memory benchmarks score recall without measuring downstream coding outcomes. We introduce VibeMemBench, a benchmark for evaluating memory systems on 111 coding targets from 90 SWE-rebench V2 repositories and 3,634 history trajectories from the target repositories. The targets follow the SWE benchmark style and cover bug fixes, feature requests, interface changes, and configuration work. An agent edits each target codebase under a declared memory condition. Executable tests decide task resolution. Each target is retained only when injected history experience improves its executable outcome in a reference setting, so every target carries a prior experience whose usefulness is verified by execution in that setting. The frozen verified experience is then transferred to five held-out solvers. Direct injection raises observed task resolution on four of them by 1.1 to 4.5 percentage points while lowering agent steps on all five. Yet when four existing memory systems must construct and retrieve experience from the same history, eleven of twelve solver and system pairings fail to exceed the matched memory-off baseline. VibeMemBench exposes the gap between the useful experience that repository history holds and the experience existing memory systems deliver for repository coding tasks.

## 二、论文提出的方法论

### 2.1 总体框架：从部分信号到受控对比

**核心思想**：在同一任务、同一代理、同一工具、同一沙箱和同一预算下，唯一改变的是记忆条件（Memory OFF vs Memory ON），通过可执行测试判定任务是否解决，从而归属因果效应于记忆组件本身。

### 2.2 基准构建流水线：SIEVE

论文提出一个四阶段的离线构建流程，名为**SIEVE**（非首字母缩写，仅代表其过滤性）：

| 阶段 | 核心操作 | 复用目标 |
|------|---------|---------|
| 源验证 | 注入源金标补丁、执行声明测试，剔除金标补丁无法通过的实例 | 数据质量 |
| 补丁模式筛选（历史—目标筛选） | 启用oracle（仅用目标金标补丁做离线筛选），仅接受同仓库更早的历史实例，排除目标标识符；以确定性评分（共享文件、目录、清理后的标识符）筛出候选，再由LLM判定修复模式 | 泄漏控制 |
| 历史执行与经验蒸馏 | 运行参考MiniSWEAgent执行所选历史任务，保留完成轨迹；然后按目标问题陈述引导，将历史问题陈述、压缩轨迹和历史最终补丁蒸馏为经验（记录缺陷类、根因、修复模式、可复用教训） | 经验生成 |

**关键公式（参考设置中的提升量）**：
- 对于目标 $t$ 和候选组合 $k$，定义 $g_{t,k} = b^{pref}_{t,k} - b^{pref}_{t,0}$，其中 $b^{pref}_{t,k}$ 为注入记忆后的四种子解决率，$b^{pref}_{t,0}$ 为无记忆基线。
- 保留条件为：$b^{pref}_{t,0} < 1$ 且 $g_{t,k^*_t} > 0$，其中 $k^*_t = \arg\max_{k} g_{t,k}$。

### 2.3 受控干预协议（Matched Intervention Protocol）

对每个固定目标和种子，对比记忆关与记忆开两个运行。**只有记忆组件（声明为写策略、检索触发、上下文插入规则、截断规则）可变**，其余（模型、工具、提示词、预算、上下文预算、沙箱、任务顺序）全部固定；同时配有一个“无关记忆控制”（注入不含软件内容的杂散日常句子）以排除“仅注入文本”的干扰。

### 2.4 评估两层结构

- **第一层：冻结经验迁移**。将参考设置验证过的经验直接注入5个保留求解器（deepseek-v4-pro、glm-5、glm-5.2、kimi-k2.7-code、qwen3.8-max），考察跨模型迁移效果。
- **第二层：现有记忆系统检索**。由4个现有记忆系统（Mem0、SimpleMem、MemoryOS、A-MEM）从完整历史中自主构建和检索经验，由deepseek-v4-flash提取、Qwen3-Embedding-4B嵌入，注入同一求解器，比较能否超过无记忆基线。

## 六、论文的主要结论与发现

1. **冻结经验直接注入带来小幅正向提升**：4/5求解器的任务解决率提升1.1–4.5个百分点（如kimi-k2.7-code +4.5pp，glm-5.2 +3.6pp），并同时降低所有求解器的代理步骤（缩短约2–11步/运行），但所有bootstrap区间跨零，说明**证据方向性而非决定性**。
2. **无关记忆控制无增益**：注入无软件内容的杂持文本导致解决率下降0.7–3.4pp，排除“注入文本本身有效”的干扰解释。
3. **现有记忆系统几乎全面失败**：12个求解器—系统配对中有**11个未超过无记忆基线**（其中9个点估计为负），唯一例外是MemoryOS on glm-5（+2.0pp），但仍远低于冻结经验。4个系统均显著缩短glm-5的token和步骤，却未转化为解决率增益，表明**更短轨迹 ≠ 有用记忆**。
4. **失败归因明确指向形式退化（Form Degradation）**：231个失败配对中，160个（69.3%）因“相关历史可达但修复模式被丢弃或埋在原始转录中”失败；排名缺失仅1.3%。进一步分解发现**指令污染（40%）和过度泛化的修复模式（18.1%）**占主导。
5. **危害机制为转录体积而非指令语义**：剥离污染行与随机删除同等数量未污染行的恢复效果相当（+0.60 vs +0.48种子/配对），说明危害源于“原样转录的冗长记录”而非“指令特有的语义信息”。
6. **记忆价值取决于求解器余量（Headroom）**：在同一检索记录下，两个求解器在64个对立符号配对中有61个由较低记忆关基线的求解器获益；8个记录属性无法区分对立与同向组。
7. **检索宽度无法修复缺陷**：将Mem0的检索预算从1增至5条记录，所有预算均低于无记忆基线，说明问题不在排名而在记录形式。
8. **反事实替换界定收益上界**：将失败配对中的记录替换为已验证冻结经验，可恢复196个种子（表单退化组），表明形式修复有实质提升空间。

## 七、优点

1. **清晰的问题定义**：以“配对受控的可执行测试”作为评测尺度，实现真正因果归因，解决了记忆评估信号碎片化的根本难题。
2. **工程严谨的构造流程（SIEVE）**：以禁止泄漏的离线屏幕、参考设置执行验证、冻结经验传递三环构建基准，确保每个保留目标确实有“可用经验”作证。
3. **丰富而系统的消融设计**：涉及无关记忆控制、锚定层级、指令污染剥离、检索预算、上限分层、反事实替换等多层多维验证，逻辑严密。
4. **失败归因的透明化**：将231个失败案例逐一定位到四阶段（覆盖缺失、排名、形式退化、使用失败），并以独立judge盲标审计（两种模型族群），增强可信度。
5. **发现鲜明且实用**：将问题精准锁定在“列格式/转录体积”而非“语义内容”或“检索排序”，对记忆系统设计给出可行的修复方向（压缩轨迹、保留修复字段、按求解器余量门控）。

## 八、不足与局限

1. **目标选择引入选择性偏差**：111个目标经正提升筛选，代表的是“有已知可转移经验”的子群体，不能估计部署环境下记忆系统实际找到此类配对的概率。
2. **统计功效不足**：所有提升（1.1–4.5pp）的95%置信区间跨零，111个目标的规模使其**只能报告方向性证据**，不能给出决定性结论。
3. **求解器覆盖不完整**：未纳入Claude、GPT等专有前沿模型，模型泛化能力的协议未被验证。
4. **记忆系统评测方式受限**：现有系统只做了离线单轮检索（非在线闭环记忆），未体现其在交互中自主写读的真实行为模式；且记忆端的token消耗未纳入统计，资源比较有局限。
5. **唯一的正结果解释较弱**：MemoryOS on glm-5的正效应更像“最弱求解器余量释放”而非记忆质量，其整体区间跨零。
6. **可复现性有留白**：未报告计算资源细则（GPU型号/数量、总推理时长、能耗），影响精确复现；且部分附录细项（如筛选评分阈值、LLM提示细节）依赖release manifest，外部验证成本较高。
