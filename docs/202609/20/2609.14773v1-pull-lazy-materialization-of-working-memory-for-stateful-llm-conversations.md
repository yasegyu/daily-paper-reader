## 摘要
随着LLM对话发展到数百轮，全上下文注入产生O(N^2)的累积令牌成本，而有损摘要或硬截断则不可逆地丢弃历史状态。我们提出Pull，一种会话路由器，通过本地确定性的净化器（零LLM调用，毫秒级延迟）维护可寻址的元数据目录。在查询时，LLM仅懒物化所需的轮次；未物化的轮次仍然可访问但已折叠。与不可逆压缩不同，Pull的物化是可逆的；后续查询可以展开任何折叠的轮次。在LoCoEval（128个对话，12,780轮）上，Pull在单跳任务上将每查询上下文令牌（阶段2）减少75.1%，质量相当（Δ=-0.002，无显著差异），在多跳任务上减少72.0%，且无质量损失（Δ=+0.017）。受控路由基准（7,831个查询 × 10种方法）表明，实体生命周期跟踪在经验上是距离无关路由的先决条件。在BEAM 1M（14个对话，263个问题）上，Pull与截断基线相比将F1提高了+55.2%。

## Abstract
As LLM conversations grow to hundreds of turns, full-context injection incurs $O(N^2)$ cumulative token costs, while lossy summarization or hard truncation irreversibly discards historical state. We propose Pull, a session router that maintains an addressable metadata directory via a local, deterministic Purifier (zero LLM calls, millisecond-level latency). At query time, the LLM lazily materializes only the turns it needs; unmaterialized turns remain accessible but collapsed. Unlike irreversible compression, Pull's materialization is reversible; subsequent queries can expand any collapsed turn. On LoCoEval (128 conversations, 12,780 turns), Pull reduces per-query context tokens (Phase 2) by 75.1 percent on single-hop tasks with equivalent quality ($Δ= -0.002$, n.s.) and by 72.0 percent on multi-hop tasks with no quality loss ($Δ= +0.017$). A controlled routing benchmark (7,831 queries x 10 methods) shows that entity lifecycle tracking is empirically a prerequisite for distance-independent routing. On BEAM 1M (14 conversations, 263 questions), Pull improves F1 by +55.2 percent over a truncation baseline.

## 1. 论文的核心问题与整体含义

**研究动机与背景：**
- 随着LLM对话延伸到数百轮，全量上下文注入（Full-context injection）使每次请求的上下文长度线性增长（O(N)），整段对话生命周期的累计重传令牌量呈平方级增长（O(N²)）。
- 论文对287个编码助手会话（59,520条消息，55.6亿计费令牌）的分析发现，约20×的令牌放大效应——原始内容仅2.8亿令牌，但API计费55.6亿。查询与历史间的实体重叠中位数仅20.7%，说明模型被迫搜索大量无关历史。
- 另一端，有损摘要（如LLMLingua）或硬截断会不可逆地丢失历史细节——一旦一轮被摘要掉，变量定义、分支决策、已弃用实现等精确状态就永久丢失。
- 现有方案中，RAG或长时记忆系统擅长跨会话知识归档，但对于会话内状态管理存在架构性局限。论文将LLM系统架构定义为三层：第一层（全上下文）管理"当前查询"，第三层（长时记忆）管理"过去会话发生了什么"，但第二层——活跃会话状态路由器——缺乏清晰的系统抽象。Pull正是要填补这一空白。

## 2. 论文提出的方法论

**核心思想：懒物化（Lazy Materialization）**
- Pull将会话管理重新定义为**懒物化**：不推送压缩摘要或检索死片段，而是维护一个实时元数据目录（metadata directory）。LLM看到的是包含实体生命周期、分支拓扑和因果依赖的目录，可主动"拉取"（pull）所需的具体轮次进入工作记忆。未物化的轮次保持可访问但折叠状态；后续查询可随时展开任何折叠轮次——因此物化是**可逆的**。

**架构两阶段：**
1. **阶段一（在线标注，每轮零LLM调用）**：本地确定性组件**Purifier**计算每轮的结构化元数据，包括：
   - 抽取式摘要（约100字符）
   - 实体集合（16个正则模式、13种类型族：函数/类定义、代码标识符、URL、时间/数字/命名实体等）
   - 信息密度评分（九种实用与词汇信号加权）
   - 保真度评分（fidelity score）
   - 生命周期状态（四态状态机：DEF → REF → MOD → DEP，全部由规则触发，无LLM参与）
   - 分支ID（branch ID）
2. **阶段二（查询时物化，每查询2次LLM调用）**：
   - **Selector**：读取M10追踪层（实体依赖图+生命周期标签+分支拓扑），单个LLM调用决策需要物化的轮次集合S，然后执行确定性**级联扩展**（cascade expansion）——对S中每个实体引用的最早定义轮次进行单跳填充，限额外5轮。
   - **Answerer**：接收全量M0目录 + 物化轮次原文 + 查询q，生成答案。

**关键公式：**
- 问题形式化：选择子集 S 以最小化令牌数，同时约束信息损失 ≤ ε：arg min TokenCount(prompt(q,S))，s.t. L(answer(q,S), answer(q,C)) ≤ ε
- Pull用可计算的代理：S = f_θ(q, M0, M10)

**存储层级（类比OS内存层次）：**
- 活跃区（0–300轮）：原文+元数据
- 冻结区（300–800轮）：块摘要+元数据+归档指针
- 外部归档：第三方存储
- Pull占据的是L1+L2缓存层：确定性本地元数据（活跃区）+块摘要（冻结区）

## 6. 论文的主要结论与发现

1. **LoCoEval单跳**：Pull减少75.1%阶段2令牌，质量等效（Δ=-0.002，n.s.，TOST通过p<0.01）。
2. **LoCoEval多跳**：Pull减少72.0%令牌，质量略优于全量（Δ=+0.013，级联在多跳中贡献更大）。
3. **BEAM 1M**：即使简化Purifier（仅M0、无M10），Pull的F1较截断基线提升+55.2%（0.299→0.464）；即使检索基线拿到2.5×令牌预算（163K），仍远低于Pull（F1=0.137）。
4. **元数据消融**：实体生命周期跟踪（M10）是距离无关路由的经验性先决条件——无生命周期，Recall@10封顶74%；有生命周期，达到96.0%，且跨距离无衰减（78–98%），而Last-K从75.6%崩溃至0.8%。
5. **Pull优于不可逆压缩**：在64多跳对话上，Pull F1=0.6500 vs LLMLingua2 r50=0.6118、r28=0.5079；可逆性探针确认自适应路由（Pull-Adaptive 0.6785）显著优于固定压缩（LLMLingua2-Fixed 0.5272）。
6. **"Lost in Conversation"现象**可能并非源于Transformer注意力本身，而是输入信噪比问题——通过懒物化提高信噪比可显著改善长对话表现。
7. **成本与延迟收益**：多跳场景下每查询成本从$0.91降至$0.29（-68%）；端到端延迟在200K上下文下减少0.74秒。生产中已验证13个SWE-bench Pro实例、350+工具轮零崩溃。

## 7. 优点

- **设计优雅的架构分层**：借鉴经典OS内存层次（L1/L2缓存→主存），将LLM会话管理系统化，分离确定性本地计算（元数据维护）与LLM决策（选择/推理），实现关注点分离。
- **零LLM调用的在线标注**：Purifier完全确定性（正则+规则+轻量嵌入），毫秒级延迟、无幻觉风险、内存线性增长，从根本上避免LLM驱动的元数据维护带来的不确定性与成本。
- **可逆性作为核心原则**：与不可逆压缩（LLMLingua）和有损摘要的根本区别——折叠轮次可随时展开，后续查询不受先前选择限制。
- **强效的实验验证体系**：多数据集（LoCoEval+BEAM 1M+受控基准）、跨模型验证、统计检验（TOST）、消融链、失败案例机制级分析、延迟与成本分析——证据链条相对完整。
- **诚实评估局限**：论文在Limitations和失败案例分析中坦承了M0有损性、级联过度扩展、正则实体提取覆盖率上限等问题，无过度宣称。
- **清晰的系统定位**：明确了Pull在"三层架构"中的位置（第二层），不再与RAG/长时记忆竞争，而是互补关系；生产部署验证了工程可行性。

## 8. 不足与局限

- **代码域偏向性与泛化受限**：实体提取的13个模板和受控路由基准均基于代码会话（SWE-bench）；对低实体密度领域或其他领域的泛化能力未验证。论文承认这是未来工作。
- **M0摘要的有损性**：约100字符的抽取式摘要会折叠不同草稿间的精细差异（失败案例Repo-B），影响路由选择精度。极端情况下，摘要省略会影响路由质量。
- **级联过度扩展问题**：失败案例Repo-A显示，级联可能扩展进因果相关但任务无关的连续块，挤占分散种子回合的预算（0.390 vs 无级联0.668）。
- **正则实体提取器的覆盖率天花板**：失败案例Repo-C显示，低信号区域中正则提取播种的回合无法覆盖任务关键簇（三个消融均无法恢复vanilla性能）。
- **同模型评审偏差**：主要实验用GLM-5生成+评审；独立评审（Qwen3.7plus）确认方向但22/64样本判断方向相反——存在残余的评审偏差风险。令牌节省也显著依赖模型（GLM-5批量75.1% vs Qwen3.7plus逐任务45.6%）。
- **BEAM使用简化版Purifier**：BEAM验证仅使用M0目录（无M10生命周期层），与主实验的完整系统不完全一致，将生命周期贡献独立到受控路由中验证——由此带来的系统整体性能可能被低估或高估。
- **BEAM选择14/35对话**：论文说明是"控制主题多样性"而非最大化数量，但仍存在选择偏差风险。
- **生产部署无A/B对照**：所有生产实例均使用Pull，无法进行对照组比较；文中token节省相对有限（约10K令牌/实例），主要价值体现在延迟降低和上下文膨胀预防。
- **领域局限性（单用户）**：初始实证发现（287个会话）来自单用户开发日志，可能不适用于多用户或非编码场景。
