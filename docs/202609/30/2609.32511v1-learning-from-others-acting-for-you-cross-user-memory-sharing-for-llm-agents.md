## 摘要
为不同用户服务的大语言模型（LLM）智能体常常解决相关任务，但彼此分离的用户历史可能使可复用经验无法被其他智能体获取。汇聚记忆能扩大访问范围，却可能迁移与接收用户需求相冲突的偏好。我们提出 ShareMem，一种记忆架构，在共享可复用经验的同时，将其应用建立在接收用户自身偏好之上。共享经验指示如何行动以及应参考哪些偏好；接收用户的记忆则提供其具体偏好值。两阶段整合先在本地精炼经验，再将接受的编辑整合进共享池。在执行阶段，范围优先检索在统一条目预算下联合选择本地与共享经验，而用户绑定通道支持初始的和由智能体发起的偏好检索。我们在网络导航（Mind2Web）、在线个性化交互（VitaBench~2.0）和多会话编码（MemoryCode）上，使用四个骨干模型评估 ShareMem。相较于匹配的用户本地记忆，它在所有四个模型上分别提升了步骤成功率、平均任务成功率和对话宏编码分数。消融实验表明，两阶段整合有利于更小的共享池、更低的归纳 token 使用量和更好的下游性能，并支持经验指导与主动偏好检索之间的互补性。进一步分析显示，当相关本地经验稀缺时，共享帮助最大，而来源质量和跨用户偏好干扰会限制有效迁移。

## Abstract
Large language model (LLM) agents serving different users often solve related tasks, yet separate user histories can leave reusable experience inaccessible to other agents. Pooling memories expands access but risks transferring preferences that conflict with the receiving user's requirements. We introduce ShareMem, a memory architecture that shares reusable experience while grounding its application in the receiving user's own preferences. Shared experiences indicate how to act and which preferences to consult; the receiving user's memory supplies their concrete values. Two-stage consolidation refines experience locally before integrating accepted edits into a shared pool. During execution, scope-first retrieval jointly selects local and shared experiences under a common entry budget, while a user-bound channel supports initial and agent-initiated preference retrieval. We evaluate ShareMem across web navigation (Mind2Web), online personalized interaction (VitaBench~2.0), and multi-session coding (MemoryCode) with four backbone models. It improves step success, average task success, and dialogue-macro coding scores, respectively, over matched user-local memory across all four models. Ablations favor two-stage consolidation for smaller shared pools, lower induction token usage, and better downstream performance, and support complementarity between experience guidance and active preference retrieval. Further analyses show that sharing helps most when relevant local experience is scarce, while source quality and cross-user preference interference limit useful transfer.

## 1. 核心问题与整体含义（研究动机与背景）

- **研究背景**：LLM 智能体通过长期记忆复用经验并实现个性化，但在多用户部署（如组织内部共享同一智能体系统）中，每个用户通常拥有独立实例和交互历史。
- **核心问题**：用户历史彼此隔离，导致可复用经验无法被其他智能体获取，形成 **experience-reachability bottleneck（经验可达性瓶颈）**。
- **朴素方案的风险**：直接汇聚所有用户记忆虽能扩大访问范围，但会把贡献者的个人偏好（如命名习惯、具体选择）一并迁移，可能与接收用户的需求冲突。
- **关键洞察**：让经验“可访问”不等于让经验“可应用”。成功个性化需要区分：
  - **可复用程序**：如何执行任务、应参考哪些偏好维度；
  - **用户特定偏好**：具体应采用什么值。
- **研究问题**：智能体如何复用他人经验，同时仍应用接收用户自己的偏好？
- **整体含义**：论文提出 ShareMem，一种在跨用户共享可复用经验的同时，将具体应用锚定到接收用户自身记忆中的架构，为 LLM 智能体集体学习提供“共享指导、用户绑定偏好”的实践原则。

## 2. 方法论：核心思想与关键技术细节

### 2.1 核心思想

- **共享经验 + 用户绑定偏好**：共享经验说明“如何做”和“该查哪些偏好维度”；接收用户自己的偏好库提供“具体值”。
- **记忆结构**：
  - 用户 \(u\) 的本地记忆 \(M_u\) 包含偏好 \(P_u = \{p^1_u,\dots,p^{n_u}_u\}\) 与按适用范围 \(s\) 组织的经验 \(E_{u,s}\)。
  - 共享记忆 \(S\) 包含跨用户经验集合 \(R_s\)，但**不共享其他用户的偏好存储**。
  - 环境适配器负责分配 scope 与检索优先级。

### 2.2 两阶段经验固化（Two-stage consolidation）

- **第一阶段：本地更新**
  - 对轨迹或会话 \(\tau\)，由 scope 分配函数 \(s=\sigma(\tau)\)。
  - 本地检索器 \(R_{\text{local}}\) 从 \(E_{u,s}\) 中取最多 \(k_w\) 个相关邻居 \(N_{u,s}\)。
  - LLM 更新算子 \(U_{\text{local}}\) 基于邻居与证据编辑集合，得到更新后的本地经验 \(E'_{u,s}\) 与接受的编辑集 \(\Delta_{u,s}\)。
  - 编辑可为 add / replace / remove / no-op；管理器需将来源特定值抽象为语义槽位，并保留偏好检索指导。
- **第二阶段：共享更新**
  - 对每个被接受的本地编辑 \(\delta \in \Delta_{u,s}\)，由 \(R_{\text{shared}}\) 检索共享邻居。
  - 共享更新算子 \(U_{\text{shared}}\) 独立决定如何更新共享池 \(R_s\)。
  - 本地替换或删除**不会**自动映射为共享池的相同操作；若本地无接受编辑，共享记忆不变。
- **目的**：先本地精炼，再整合进共享池，减少冗余、降低归纳 token，并提升下游性能。

### 2.3 范围优先的联合经验检索（Scope-first retrieval）

- 对任务 \(x\)，适配器构造若干 scope 组 \(G(x)=(G_0,\dots,G_{J-1})\)，从直接匹配到更宽泛回退，优先级由小到大。
- 每个组内，本地与共享候选合并：
  - \(C_j = \bigcup_{s \in G_j} [R(x,E_{u,s};K_c) \cup R(x,R_s;K_c)]\)。
- 最终通过 `ScopeTopK` 在**统一 K 条目预算**下联合重排本地与共享经验：
  - 低优先级组只填补剩余名额，不能挤占已选高优先级条目；
  - 选满 K 或候选耗尽即停止。
- 该设计避免为本地/共享设置固定配额，而是让二者在同一预算下竞争。

### 2.4 主动偏好检索（Active preference retrieval）

- 对含偏好通道的任务，\(R_{\text{pref}}(q,P_u;k_p)\) 返回最多 \(k_p\) 条偏好。
- **初始召回**：\(B^0_u = R_{\text{pref}}(x,P_u;k_p)\) 与任务 \(x\)、经验指导 \(H_x\) 一起进入上下文 \(h^0\)。
- **执行时**：策略 \(\pi_\theta\) 从动作空间 \(A_{\text{env}} \cup A_{\text{pref}} \cup A_{\text{out}}\) 选择动作：
  - 环境交互、偏好检索、终止响应；
  - 偏好动作 \(a_t \in A_{\text{pref}}\) 返回观察 \(o_t = R_{\text{pref}}(q_t,P_u;k_p)\)；
  - 上下文拼接 \(h_{t+1} = h_t \parallel (a_t,o_t)\)。
- 环境固定用户 \(u\)，防止跨用户偏好访问；经验指导“该解决哪些约束”，但当前任务要求与用户偏好具有更高优先级。

## 3. 实验设计：数据集、Benchmark 与对比方法

### 3.1 数据集 / 场景

## 6. 主要结论与发现

- **经验积累有效**：LOCAL 在四个骨干上均优于 NONE，说明用户本地经验对网页交互等任务有价值。
- **共享经验带来额外收益**：
  - Mind2Web：ShareMem 相比 LOCAL 提升步骤成功率 2.35–4.10 个百分点；平均比 NONE 高约 10.5 个百分点；
  - VitaBench 2.0：ShareMem 在四个骨干上 Avg@3 均最高，平均比 LOCAL 高约 1.8 个百分点；
  - MemoryCode：ShareMem 在四个骨干上平均 D-MS 均高于 LOCAL。
- **偏好访问是关键**：VitaBench 2.0 与 MemoryCode 上，从 NONE 到 PREF 的增益最大，说明访问个人偏好至关重要。
- **共享他人偏好未必有益**：SHARE-ALL 在 Avg@3 上均低于 ShareMem，且在部分指标上低于 PREF，说明跨用户偏好访问会引入干扰。
- **两阶段固化更优**：相比直接写入或 append-only，两阶段固化产生更小共享池、更低归纳 token、更好下游性能。
- **scope-first 检索有效**：在 Mind2Web 上优于 flat 检索，且检索到更高比例同网站经验。
- **主动偏好检索与经验指导互补**：两者同时可用时增益更大（9.48 pp vs 1.37 pp）。
- **共享收益的边界**：
  - 本地相关经验越稀缺，共享收益越大；本地覆盖接近 100% 时增益消失甚至为负；
  - 经验来源质量下降时，ShareMem 性能下降幅度大于 LOCAL；
  - 准入阈值过严会减少经验覆盖，形成质量与覆盖的权衡。
- **跨用户偏好干扰真实存在**：即使有来源标签与禁止指令，审计仍确认了误用案例，因此必须将偏好通道绑定到当前用户。

- **部分增益的实践显著性存疑**：如 MemoryCode 上某些骨干仅提升约 0.16 D-MS，在对话级方差较大时难以确认实际意义；
- **共享池的治理与隐私机制较薄弱**：论文主要从“偏好通道绑定”角度防止跨用户偏好访问，但对共享经验本身的去标识化程度、可审计性、用户撤回（right to be forgotten）与删除传播等部署级治理问题讨论有限；
- **经验池长期演化未充分刻画**：缺乏对共享池随任务规模增长时的容量、检索退化、陈旧经验污染、以及经验冲突累积等长时程行为的系统分析；
- **归纳阶段存在错误传播风险**：本地经验一旦抽象不当，错误可能经共享更新被放大到其他用户，论文虽做了来源质量敏感性分析，但未提供纠错或回滚机制；
- **缺少与更强记忆/智能体基线的对比**：参考系统多为通用上下文或 RAG 类方法，未与专门的长时记忆架构、反思式记忆或层次记忆方法系统比较；
- **任务与领域泛化仍受限**：网页、个性化服务、编码三类场景均为可文本化、可自动评分的任务，对具身、多模态、高风险领域（医疗、法律、金融）的适用性未验证。

## 9. 对领域与实践的启示

- **“共享经验 ≠ 共享偏好”应成为跨用户智能体记忆设计的基本原则**：可复用的程序性知识适合集中沉淀，而具体偏好值应保留在用户侧并受控访问；
- **两阶段固化提供了低成本共享路径**：先本地精炼、再择优进入共享池，可在不牺牲性能的前提下显著压缩归纳开销，对大规模多用户部署具有现实意义；
- **检索预算的统一分配优于固定配额**：scope-first 联合重排说明，让本地与共享经验在相同预算下竞争，比人为设定配额更符合“按需取用”的实际需求；
- **主动检索是可扩展方向**：允许智能体在执行中按需查询偏好，与经验指导形成互补，暗示未来记忆系统应同时支持“被动召回”与“主动询问”两种模式；
- **共享收益有明确边界条件**：本地经验覆盖度、来源质量、准入阈值共同决定共享是否划算，部署时需动态监控这些量而非盲目扩大共享池。

## 10. 可复现性与未来研究方向

- **可复现性**：论文提供了 benchmark 协议、受控记忆配置定义、更新与检索流程、关键 prompt 及部分 token 成本数据，方法层面具备较好的可复现基础；但算力信息缺失、部分分析仅单骨干、共享池规模与数据未完全披露，限制了端到端复现与成本估算。
- **未来方向**：
  1. 在更强、更多样的骨干与真实线上环境中验证共享收益的稳健性；
  2. 设计共享经验的可撤回、可审计与差分隐私式写入机制；
  3. 研究经验冲突检测与共享池的自动纠错/回滚；
  4. 探索偏好通道的细粒度权限控制（按维度、按场景授权）；
  5. 将两阶段固化扩展到多模态与工具调用等更复杂经验形态；
  6. 建立衡量“跨用户负迁移”的标准指标与基准。

## 11. 总体评价

ShareMem 抓住了一个在多用户 LLM 智能体部署中真实且被忽视的问题——经验可达性与可应用性的分离，并给出结构清晰、工程可行的解决方案：以两阶段固化生成去个人化的可复用经验，以 scope-first 联合检索在统一预算下取用本地与共享经验，以用户绑定偏好通道确保“共享指导、用户绑定偏好”。实验覆盖三类任务、四个骨干，受控配置设计合理，边界条件分析较为深入，尤其在“共享他人偏好反而有害”“本地覆盖度高时共享收益消失”等反直觉结论上具有启发价值。其主要短板在于算力信息缺失、在线验证与治理机制不足、以及部分关键分析的骨干覆盖有限。总体而言，该工作为 LLM 智能体集体学习提供了一个有说服力的设计范式与一套值得后续研究跟进的问题清单。
