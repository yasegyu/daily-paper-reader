## 摘要
持久记忆使语言模型智能体无需更新模型权重即可改进提示和技能。我们表明，将检索范围与认证范围相匹配，可使这些编辑支持在反复出现的任务族中可靠地重复适应。我们在 ProcStream-RSI（一个 12 轮代码修复流）上研究冻结模型智能体，使用正交回归控制（Orthogonal Regression Control, ORC），一种面向持久技能编辑的、基于执行的门控。在一项保持提案和门控决策固定的干预中，仅将每个被接受的技能检索用于其来源任务族，使平均隐藏轨迹效用从全局记忆下的 0.713 提高到 0.816，并将有害部署从八次中的六次变为零次。在 27 个配对的随机顺序流中，Scoped-ORC 相比 Global-ORC 将平均轨迹效用提高 0.063 [0.037, 0.094]，接受 63 次而非 12 次更新，并在 19/27 个流中产生多次被接受的更新，且 0/63 次有害接受。全局控制达到 0.713，低于静态智能体的 0.775，因为局部有效的编辑可能干扰无关任务族。这些结果确立了范围匹配作为持久智能体记忆的一种互补控制：认证决定一项编辑是否得到支持，而检索范围决定该证据在何处授权其使用。

## Abstract
Persistent memory lets language-model agents improve prompts and skills without updating model weights. We show that matching retrieval scope to certification scope enables these edits to support reliable repeated adaptation across recurring task families. We study frozen-model agents on ProcStream-RSI, a 12-round code-repair stream, using Orthogonal Regression Control (ORC), an execution-grounded gate for persistent skill edits. In an intervention that holds proposals and gate decisions fixed, retrieving each accepted skill only for its originating family raises mean hidden trajectory utility from 0.713 under global memory to 0.816 and changes harmful deployments from six of eight to none. In 27 paired randomized-order streams, Scoped-ORC improves mean trajectory utility by 0.063 [0.037, 0.094] over Global-ORC, accepts 63 rather than 12 updates, and produces multiple accepted updates in 19/27 streams, with 0/63 harmful acceptances. The global control reaches 0.713, below the static agent's 0.775, because locally valid edits can interfere with unrelated families. These results establish scope matching as a complementary control for persistent agent memory: certification determines whether an edit is supported, while retrieval scope determines where that evidence authorizes its use.

## 1. 核心问题与整体含义

- **研究背景**：大语言模型（LLM）智能体可以通过持久化记忆（prompt/技能）在不更新模型权重的情况下改进自身，形成所谓"自改进"系统（如 Gödel Agent、Darwin Gödel Machine 等）。这类系统通常将一次被接受的技能编辑**全局部署**，供所有后续任务复用。
- **核心问题**：当反馈证据来自某个特定任务族时，该编辑被"认证"有效，但若将其作为全局技能检索给**所有任务族**，可能会干扰与证据无关的任务族。作者将这一现象命名为 **跨任务族干扰（cross-family interference）**。
- **整体含义**：论文指出，持久记忆需要两个独立决策——(1) 编辑是否**得到支持**（认证问题，由门控决定）；(2) 该编辑应在**何处被使用**（部署范围问题，由检索范围决定）。现有工作普遍只关注第一个决策，而忽略第二个，导致全局控制甚至低于静态智能体（0.713 vs 0.775）。
- **核心主张**：**范围匹配（scope matching）**——让检索范围与认证范围一致，是把局部认证增益转化为可靠持续适应（continual adaptation）的关键补充控制手段。

## 2. 方法论

### 核心思想
- 将"持续性自改进"建模为一个**部署过程**而非"归档最优选择"：每轮由冻结 actor 解题，冻结 editor 产出技能提案，门控决定是否部署，被部署的策略又反过来影响下一轮的解题与证据。
- 关键分离：**认证范围（certification scope）** vs **部署范围（deployment scope）**，两者不匹配是干扰的根源。

### 关键技术细节

- **问题形式化**：设 $\pi_\theta$ 为冻结 actor，$K_t$ 为第 $t$ 轮持久技能。在发现批次 $D_t$ 上产出修复程序，editor 生成提案 $K'_t$，门控 $G_t$ 在配对探针任务上比较 $K_t$ 与 $K'_t$：
  $$K_{t+1} = \begin{cases} K'_t, & G_t(K'_t,K_t)=1 \\ K_t, & \text{otherwise} \end{cases}$$

- **门控漂移命题（Proposition 1）**：设提案有益概率为 $\pi$、有益增益 $G$、有害损失 $L$，门控对有益/有害提案的接受率分别为 $\alpha$、$\beta$，则期望部署变化为正的充要条件是
  $$\pi\alpha G > (1-\pi)\beta L$$
  对条件独立的多个证据通道（误接受率 $\beta_j$），联合误接受率为 $\prod_j \beta_j$；但若各通道误接受事件**相同**，增加通道并不降低 $\beta$。这说明**边际验证精度不足够，通道误差的相关性才关键**。

- **Orthogonal Regression Control（ORC）门控**：对每对任务计算候选减去当前策略的通过率差 $d_{i,c}$，通道 $c \in \{\text{pub}, \text{priv}, \text{meta}\}$：
  - 4 个公开样例、4 个私有精确输出测试（actor/editor 不可见）、≥6 个无答案变形（metamorphic）检查；
  - 对每个"任务族分组 × 通道"计算单侧 95% 配对 bootstrap 下界 $L_{g,c}$（$n \le 50000$ 精确枚举，否则 2000 次种子采样）；
  - 部署条件（$\delta_{new}=0,\ \delta_{reg}=0.02$）：
    - 当前族公开通道 $L_{current,pub} \ge -\delta_{reg}$
    - 当前族私有通道 $L_{current,priv} > \delta_{new}$
    - 当前族变形通道 $L_{current,meta} \ge -\delta_{reg}$
    - 所有历史族 $g<t$ 的所有通道 $L_{g,c} \ge -\delta_{reg}$
    - 且私有/变形评估未报告不安全程序
  - 使用**合取（AND）**而非加权平均，防止单通道增益掩盖其他通道的退化。

- **Scoped-ORC（范围化检索）**：被接受的候选存入**当前任务族的槽位**，任务来自族 $f$ 时取：
  $$K_t(f) = \begin{cases} K_t^{(f)}, & \text{若 } f \text{ 有已接受槽位} \\ K_0, & \text{否则} \end{cases}$$
  活动策略仍恰好 360 字符，检索只改变供给哪个策略，不改变 prompt 预算；提案生成与门控完全不变。

## 3. 实验设计

### Benchmark 与场景
- **ProcStream-RSI v3.1**：12 轮代码修复流，包含 9 个任务族（boundary、rotation、ordering、normalization、nested、missing、prefix、chunk、tie-breaking），每族使用种子派生的不透明协议 token。
- 每轮 4 个发现任务 + 4 个探针任务；固定 checkpoint 库和 final 库每族各 1/2 个任务，每流共 123 个任务。
- 公开/私有/隐藏输入两两不相交；隐藏用例对在线智能体不可见。
- 后续还有 **v4 生成器**：对族多重集做种子确定性置换，支持平衡随机入口。

### 对比方法（7 种配对方法）
| 方法 | 说明 |
|---|---|
| Static | 从不提案更新 |
| Frozen-compute | 与 ORC 相同的调用但从不部署（控制额外调用效应） |
| Latest-only | 部署每个非空、格式良好的提案 |
| Self-judge | actor 自估正确性并取高者 |
| Replay | 当前公开增益 + 历史公开非退化 |
| ORC | 完整分通道门控 |
| Batch-ORC | 累积发现的一次性更新对照 |

### 实验规模
- **主实验**：8 个未见种子的完整 12 轮流。
- **固定输出范围干预**：在 8 条主流上仅改变检索范围（提案、决策、程序、分数固定）。
- **平衡随机入口复制**：18 条流（9 个可能首族各 2 条），1 轮更新。
- **完整随机顺序扩展**：27 条 12 轮流（每首族恰好 3 条），Global- 与 Scoped-ORC 流内配对。
- **外部迁移**：HumanEval+ 固定 32 任务；GPT-OSS-120B 在 18 任务 sealed final bank 上做 actor-only 诊断。
- **路由器鲁棒性**：oracle 路由、随机 fallback-on-miss 曲线、留一种子的字符 3–5-gram 朴素贝叶斯路由器。

### 模型与运行
- Actor/editor：**Qwen3-Coder-Next**，pinned Parasail BF16 端点，OpenRouter，禁用 provider fallback，temperature 0，固定流种子，700 actor tokens / 500 editor tokens；技能文本填充至 360 字符，editor 输入填充至 48,000 字符（Batch-ORC 为 64,000）。

## 6. 主要结论与发现

1. **全局部署会反向损害性能**：Global-ORC 平均轨迹效用 0.713，**低于** Static 的 0.775；8 次接受中 6 次降低下一个隐藏 checkpoint。宽松基线更差（Latest-only 0.703、Replay 0.707、Self-judge 0.736），有害接受比例约 49–52%。
2. **机制验证**：被接受的 boundary 规则使 boundary 族隐藏效用平均 +0.398，但使 missing、rotation、tie-breaking、chunk 族分别变化 −0.461、−0.234、−0.148、−0.117，即局部有效编辑通过共享全局技能耦合到无关族。
3. **范围匹配带来核心改善**：固定提案与门控下，Scoped-ORC 把平均隐藏轨迹效用从 0.713 提升到 **0.816**，对 Global-ORC 配对优势 **0.103**（[0.052, 0.151]，$p=0.03125$），有害部署从 6/8 降为 **0**。
4. **完整扩展证实持续适应**：27 条配对 12 轮流中，Scoped-minus-Global 平均隐藏轨迹效用 **+0.063**（[0.037, 0.094]，Holm $p<10^{-4}$）；接受更新 **63 vs 12**；多接受流 **19/27 vs 2/27**；有害接受 **0/63 vs 6/12**。
5. **通道证据质量高但仍需范围匹配**：私有/变形通道 AUROC 达 0.998，公开通道 0.752；所有 8 次 ORC 接受在同族门控上安全，但仅 2 次改善全局 checkpoint（PPV 从 1.00 降到 0.25）——说明**强同范围选择仍不足够，必须范围匹配部署**。
6. **外部迁移**：HumanEval+ 上 Global-ORC 0.895 略低于 Static 0.914；GPT-OSS sealed bank 上 scoped 检索达 0.960，比 Static 高 0.020（[0.004, 0.035]）。
7. **路由器鲁棒性**：字符 3–5-gram 朴素贝叶斯路由器在 243/243 留出 checkpoint prompt 上路由正确（100%），与 oracle 路由点重合；fallback-on-miss 曲线显示路由误差增加时效用平滑退化。

## 7. 优点

- **问题定位精准且新颖**：将"认证范围 vs 部署范围"的错配识别为持久记忆的独立设计问题，并提出可操作原则（证据认证更新，同时决定其检索位置）。
- **干预设计干净**：固定输出干预保持提案、门控、程序、分数完全不变，只改变检索范围，机制归因明确；随机入口扩展进一步在所有 9 个可能首族上平衡验证。
- **实验层次完整**：从机制隔离 → 平衡随机入口 → 27 条完整端到端扩展，形成递进证据链；同时包含外部迁移与跨 actor 诊断。
- **统计严谨**：配对设计、seed-bootstrap 区间、sign-flip 检验、Holm 校正、预注册协议与日期化 deviation log。
- **可复现性强**：提供生成器与评估器代码、公开与 sealed manifests、精确 prompt、种子、端点路由、被接受/拒绝策略、raw response ID、预算 ledger、沙箱测试。
- **工程安全性考虑**：无网络 Docker 沙箱、AST 校验、事务性预算账本、超时后不自动重试、不完整单元归档重放。

## 8. 不足与局限

- **模型与任务覆盖窄**：单一冻结模型（Qwen3-Coder-Next）、9 个代码契约族、仅 scaffold 级可检查编辑；未验证其他 editor/search 骨干、开放世界任务或更多模态。
- **缺少复合效应对照**：作者自己承认"测试 compounding 还需要累积一次性对照"（cumulative one-shot comparator），这是未来工作。
- **路由诊断偏乐观**：100% 路由准确率基于模板化 prompt，属于分布内诊断；未测试错误槽位路由（wrong-slot routing）与开放世界路由。
- **基准是程序化实例化的熟悉契约**：任务语义固定、仅 token/名称/程序变体/用例随种子变化，不是随机新语义的适应；可能高估真实场景泛化。
- **统计力有限**：主流仅 8 个种子；平衡随机入口实验主效应 $p=0.1875$（未达显著）；HumanEval+ 仅 32 题。
- **成本与可扩展性**：虽然总花费低（$6.9965），但 Frozen-compute 反事实成本约为 Static 的 5 倍，Batch-ORC 需 64k 字符累积证据预算，长流下的成本增长未充分讨论。
