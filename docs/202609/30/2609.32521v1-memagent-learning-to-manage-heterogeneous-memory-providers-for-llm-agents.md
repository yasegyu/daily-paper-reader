## 摘要
当前智能体在跨任务时大多仍是无状态的，限制了它们从先前交互中持续改进的能力，也使记忆成为长时程智能体行为的关键。现有记忆方法试图复用过去经验，但大多依赖单一的记忆表示（如轨迹、反思、技能、结构化知识），其有效性会因任务分布而异。重新审视这一设计空间，我们评估了13种记忆方法，发现没有一种单一方法能在各基准上泛化，这揭示了管理异构记忆提供者的潜力。我们将智能体记忆形式化为一个路由问题，其中记忆智能体决定从哪个记忆提供者检索、是否注入短期记忆，以及应由哪些提供者存储产生的经验。基于这一视角，我们提出MemAgent，其具有内容感知的路由架构和训练数据合成流水线。该路由架构结合了检索前的内容感知探测、执行期间的短期记忆门控以及选择性多提供者存储，而训练流水线则为路由决策合成阶段特定的监督信号。在GAIA、WebWalkerQA和xBench-DS上，MemAgent将平均准确率提升了10.0%，并在所有三个基准上均优于每一种单独的记忆方法。这些收益仅带来不到0.3%的路由开销，并使平均任务步数减少12%。

## Abstract
Current agents remain largely stateless across tasks, limiting their ability to continually improve from prior interactions and making memory essential for long-horizon agentic behavior. Existing memory methods seek to reuse past experience, but most rely on a single memory representation (e.g., trajectories, reflections, skills, structured knowledge) whose effectiveness varies across task distributions. Rethinking this design space, we evaluate 13 memory methods and find that no single method generalizes across benchmarks, revealing the potential of managing heterogeneous memory providers. We formulate agent memory as a routing problem in which a memory agent decides which memory provider to retrieve from, whether to inject short-term memory, and which providers should store the resulting experience. Based on this perspective, we propose MemAgent, featuring a content-aware routing architecture and a training-data synthesis pipeline. The routing architecture combines content-aware probing before retrieval, short-term memory gating during execution, and selective multi-provider storage, while the training pipeline synthesizes phase-specific supervision for routing decisions. Across GAIA, WebWalkerQA, and xBench-DS, MemAgent improves average accuracy by 10.0% and outperforms every individual memory method across all three benchmarks. These gains come with less than 0.3% routing overhead and a 12% reduction in average task steps.

- **研究动机**：当前 LLM 智能体在跨任务时大多仍是“无状态”的：每次调用从零开始，无法复用先前交互中的经验、策略或教训，限制了长时程任务中的持续改进能力。

- **整体含义**：智能体记忆的关键可能不是寻找“唯一最优记忆格式”，而是**在异构记忆 provider 之间进行内容感知的路由与生命周期管理**。论文据此将记忆管理形式化为路由问题，提出 MemAgent。

## 2. 方法论

### 2.1 核心思想

- 将智能体记忆建模为对一组异构记忆 provider 的**三阶段路由问题**。
- 任务智能体 \(A_T\) 负责解题；记忆智能体 \(A_M\) 负责在任务生命周期中做三类决策：
  - **BEGIN**：执行前选择哪个长期记忆 provider 检索并注入；
  - **IN**：执行中每一步决定是否注入短期工作记忆；
  - **END**：任务结束后选择哪些 provider 存储本次轨迹。
- 形式化目标：学习策略 \(A_M(d|c)\)，最大化任务成功率 \(E_\tau[y_\tau]\)。
- 所有 provider 共享统一接口：`retrieve` 与 `store`，从而将路由策略与 provider 内部实现解耦。

### 2.2 三阶段内容感知路由架构

- **BEGIN：内容感知探测**
  - 不只看任务描述和静态 provider 描述，而是先对全部 provider 并行发起轻量探测，获取与当前任务最相关记忆的 snippet 预览。
  - 预览中**移除检索分数**，避免模型学习“选分数最高者”的伪捷径；provider 顺序随机打乱以缓解位置偏差。
  - 记忆智能体根据探测内容选择 provider，并将检索到的长期记忆注入任务智能体系统提示。
- **IN：短期记忆门控**
  - 短期记忆 provider 以规则方式抽取任务内状态，包括已验证事实、访问过的 URL、搜索历史、工具错误等。
  - 每一步，记忆智能体根据任务问题、步数、短期记忆摘要、近期动作/观察，决定 `QUERY` 或 `NOOP`。
  - 目标是只在短期记忆可能实质性帮助下一步时注入，减少噪声和低信息量注入。
- **END：选择性多 provider 存储**
  - 任务完成后，根据轨迹摘要、任务成败、各 provider 的存储描述，选择 provider 子集 \(S \subseteq P\) 存储轨迹。
  - 避免“全量存储”导致记忆池污染，只写入未来可能被复用的 provider。

### 2.3 训练数据合成与监督微调

- 核心困难：没有路由决策的 ground-truth 标签。
- **强制探索**：
  - 对每个训练任务，枚举所有 provider 和 IN 阶段动作组合，记录轨迹与任务结果 \(y_\tau^{(p,a)}\)。
- **逐决策奖励**由三类信号构成：
  - **任务正确性（BEGIN）**：若某 provider 导致正确结果，则给予正奖励；当成功 provider 集合是真子集时，信号最具区分度。
  - **LLM-as-Judge 因果归因（BEGIN/IN）**：评估记忆是否被使用、是否相关、是否帮助推进、是否造成噪声等，多维分数加权聚合为标量奖励：
    \[
    r_d = \langle w^{(\phi)}, \hat{s} \rangle
    \]
    其中正向维度归一化为 \(s_i/s_{\max}\)，负向维度归一化为 \(1-s_i/s_{\max}\)。
  - **下游复用奖励（END）**：存储是否有价值取决于后续任务是否检索并成功使用该记忆：
    \[
    r_{\text{end}}(\xi_\tau,p)=\frac12\min(1,\frac{|T_{>\tau}^{(p)}|}{H})+\frac12\cdot\frac{\text{下游成功数}}{\max(|T_{>\tau}^{(p)}|,1)}
    \]
    使用饱和常数 \(H\) 防止单条轨迹主导奖励。
- **奖励过滤与 SFT**：
  - BEGIN：保留成功 provider 的决策；若全部成功则按 judge 奖励取 top-k；若全部失败则丢弃；空/无关检索也丢弃。
  - IN：保留 \(r_d \ge \epsilon_{IN}\) 的高质量 QUERY/NOOP 决策。
  - END：保留 \(r_{\text{end}} \ge \epsilon_{END}\) 的存储决策。
  - 使用 LoRA 对 Qwen3.5-4B 进行监督微调，仅对结构化决策 token 计算交叉熵，mask prompt token；任务级 train-validation split 防止同一任务决策泄漏。

### 2.4 新增 provider

- **InsightGraph**：图结构长期记忆 provider，将轨迹抽取为洞见节点，并以同任务边、相似概念边连接；检索时混合 TF-IDF、语义搜索与图扩展，边权根据历史复用成功率自适应更新。
- **短期记忆 provider**：规则化维护任务内工作状态，输出“收集事实、访问页面、近期搜索”等分区内容，并设置最小显示阈值以避免稀疏注入。
