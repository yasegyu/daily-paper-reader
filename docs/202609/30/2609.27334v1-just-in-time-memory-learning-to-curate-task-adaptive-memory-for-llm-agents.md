## 摘要
智能体记忆系统复用过往经验以提升未来表现，但大多数现有设计在写入时整理记忆：任务一旦完成，其轨迹就被蒸馏为固定产物，如反思、工作流、技能或推理策略，之后通过相似度进行检索。这迫使系统在未知未来查询之前就决定什么值得记住，不可逆地丢弃信息，并生成一个与查询无关的摘要，而该摘要必须服务于许多可能的下游任务。学习这样的写入时整理器也很困难，因为存储决策的价值可能只有在相关查询到来时才显现，且可能是在许多任务之后，从而造成长时程信用分配问题。我们则保留原始轨迹，并将整理推迟到读取时，此时当前任务已知。给定检索到的轨迹和新任务，记忆整理器会合成一个紧凑、任务自适应的有效载荷，以贴合即时需求。由于该有效载荷在同一任务上被使用，整理器可以直接根据即时任务成功进行训练，避免延迟的效用信号以及人为分组相关任务的需要。在 ALFWorld、WebShop 和 $τ^2$-bench 上，我们的即时记忆（JitMem）持续优于无记忆智能体以及启发式和已学习的写入时记忆方法，分别将最强基线提升了 16.2、16.3 和 3.9 个绝对成功率百分点。值得注意的是，即使未训练的整理器也已与这些基线相当或超越它们，表明任务自适应的读取时整理本身就是主要增益来源；训练整理器则进一步叠加提升。

## Abstract
Agentic memory systems reuse past experience to improve future performance, yet most existing designs curate memory at write time: once a task is completed, its trajectory is distilled into a fixed artifact, such as a reflection, workflow, skill, or reasoning strategy, that is later retrieved by similarity. This forces the system to decide what is worth remembering before the future query is known, irreversibly discarding information and producing a query-independent summary that must serve many possible downstream tasks. Learning such a write-time curator is also difficult because the value of a storage decision may only become apparent when a relevant query arrives, potentially many tasks later, creating a long-horizon credit-assignment problem. We instead retain raw trajectories and defer curation until read time, when the current task is known. Given the retrieved traces and the new task, a memory curator synthesizes a compact, task-adaptive payload tailored to the immediate need. Because this payload is consumed on the same task, the curator can be trained directly from immediate task success, avoiding delayed utility signals and the need to artificially group related tasks. Across ALFWorld, WebShop, and $τ^2$-bench, our Just-in-Time Memory (JitMem) consistently outperforms no-memory agents as well as heuristic and learned write-time memory methods, improving over the strongest baseline by 16.2, 16.3, and 3.9 absolute success-rate points, respectively. Notably, even an untrained curator is already competitive with or surpasses these baselines, showing that task-adaptive read-time curation itself is a major source of the gain; training the curator further compounds the improvement.

# JITMEM（Just-in-Time Memory）论文深度总结

## 1. 核心问题与研究动机

- **背景**：LLM 智能体越来越多地需要连续处理一系列任务，而非孤立问题。复用自身过往经验（agentic memory）是提升表现的关键，但现有记忆系统几乎都在**写入时（write time）整理记忆**。
- **写入时整理的固有缺陷**：
  - 任务完成后，轨迹被蒸馏为固定产物（反思、工作流、技能、推理策略等），之后靠相似度检索。
  - **信息丢失不可逆**：系统必须在未来查询未知时就决定"什么值得记"，一旦丢弃细节，后续依赖该细节的任务无法恢复。
  - **产物与查询无关**：同一轨迹对不同下游任务可能有不同价值（如家庭交互轨迹既可提供"状态转换"经验，也可提供"物品放置"经验），但固定摘要只能服务一种框架。
- **学习层面的困难**：写入决策的价值可能只在很久之后、某条相关查询到来时才显现，构成**长时程信用分配问题**。为此，已有方法（如 SkillOS）不得不人为"分组相关任务"来制造延迟学习信号，其消融显示分组是性能的主要贡献者。
- **核心主张**：将整理从写入时推迟到**读取时（read time / just in time）**——此时当前任务已知，可生成任务自适应载荷；同时因为载荷当次即被消费，奖励是即时的，信用分配退化为单步问题。
- **理论呼应**：该设计契合认知科学中"情景记忆是重构性而非回放性"的观点（Schacter & Addis, 2007），检索受当前目标与线索塑造。

## 2. 方法论

### 2.1 整体框架与四个组件

系统面向流式任务序列 $\{x_1,\dots,x_T\}$，目标为 $\max_\phi \mathbb{E}[\sum_t r_t]$。四个组件中**只有整理器（curator）可训练**：

- **记忆库 $M_t$**：存储**完整、未抽象的原始轨迹** $\xi=(x, o_1,a_1,\dots,o_n,a_n)$，写入时不做任何摘要/反思/技能抽取。
- **检索器 $R$**：BM25，仅对任务描述检索 top-$k$ 轨迹（与轨迹长度解耦），不训练、训练与测试一致。
- **记忆整理器 $\pi_\phi$**：输入为"当前任务 $x_t$ + $k$ 条原始轨迹 $\hat\xi_t$"，输出紧凑自然语言载荷 $p_t=\pi_\phi(x_t,\hat\xi_t)$，包含最相关经验识别、可复用策略、针对当前任务的具体指导。
- **执行器 $\pi_L$**：冻结的预训练 LLM，载荷前置到其 prompt；同一模型兼作 LLM-as-judge。

### 2.2 推理流程（四步）

1. **Retrieve**：$\hat\xi_t = R(x_t, M_t)$
2. **Curate**：$p_t = \pi_\phi(x_t,\hat\xi_t)$
3. **Execute**：$(\xi_t, r_t) = \pi_L(x_t, p_t)$
4. **Update**：$M_{t+1}=\text{UPDATE}(M_t,\xi_t,r_t)$，仅当质量门（judge 判定成功）通过时追加

关键设计：**载荷 $p_t$ 是临时的，不被存储**；只有执行轨迹才考虑入库存。

### 2.3 质量门与训练库构造

- 部署时无真实成功标签，用执行器作 LLM-as-judge 把关，只保留被判定成功的轨迹作为正例。
- 训练时为保证奖励反映载荷质量而非"恰好检索到什么"，用**固定训练库**：先用基座执行器（无整理器）跑一遍训练集，用**真实标签**保留成功轨迹，训练全程冻结。这带来轻微的训/测分布偏移（测试库含整理器增强的轨迹），论文用"分阶段刷新"量化该差距。

### 2.4 整理器训练：GRPO

- 对每个采样任务，整理器生成 $G$ 个候选载荷 $\{p_t^{(i)}\}$，冻结执行器分别尝试任务，返回真实奖励 $r_t^{(i)}$（ALFWorld/τ²-bench 为二值成功，WebShop 为连续分数）。
- 组内优势：$\hat A_i = r_t^{(i)} - \text{mean}_j r_t^{(j)}$（依 Liu et al. 2025，**省略标准差归一化**）。
- 损失：
  $$\mathcal{L}_{\text{GRPO}} = -\frac{1}{G}\sum_{i=1}^{G}\hat A_i \cdot \log \pi_\phi(p_t^{(i)} \mid x_t, \hat\xi_t)$$
- 无价值网络（value network），执行器全程冻结。
- **核心性质**：$r_t$ 是同一任务载荷 $p_t$ 的直接函数，**时间间隔为零**，无需任务分组或延迟回报机制。

### 2.5 评估协议

- 测试记忆库默认**初始为空**，随任务解决在线增长（存在自然冷启动效应）。
- 采用**批式流式协议**：批内任务共享同一记忆库状态，批后统一更新。
- 任务成功由 benchmark 真实验证器判定，记忆更新策略用 LLM judge（避免泄漏真值）。
- 因任务顺序与批组成会影响结果，报告多次随机顺序运行的均值±标准差。

## 3. 实验设计

### 3.1 数据集 / 场景

| Benchmark | 场景 | 规模 |
|---|---|---|
| **ALFWorld** | 文本具身家务控制 | 140 测试任务 |
| **WebShop** | 网页商品购买 | 500 测试实例 |
| **τ²-bench** | 会话式工具使用（Airline / Retail / Telecom 三域） | — |

指标：三者均报成功率（SR），WebShop 额外报平均分数（Score）。τ²-bench 因无标准训练集，只评估免训练变体。

### 3.2 对比方法

- **No Memory**：仅冻结执行器。
- **三种写入时记忆基线**：ReasoningBank（蒸馏策略与洞见）、MemP（多粒度记忆项）、SkillOS（用 RL 训练技能整理器，带复合奖励与任务分组）。
- **变体**：`-base`（同基座模型、不训练整理器）、`-gpt/-gemini`（用 GPT-5.4 或 Gemini-2.5-Pro 作 zero-shot 提示式整理器）。

### 3.3 执行器与配置

- 三种冻结执行器：**Qwen3-8B、Gemini-2.5-Pro、GPT-5.4**。
- 训练整理器：Qwen3-8B（关闭 thinking），GRPO 100 步，学习率 $1\times10^{-6}$，batch size 32，group size 8，训练时用 Qwen3-8B 作执行器。
- 检索 $k=3$；评估批大小 ALFWorld/WebShop 为 10，τ²-bench 为 5。

### 3.4 消融实验

- **JITMEM-base 消融**：去掉任务自适应条件、改为"存全部轨迹+正确性标注"、改为写入时蒸馏（ReasoningBank 风格）。
- **JITMEM 消融**：强制检索返回空集、去掉任务条件、分阶段刷新训练库、测试库热启动。
- 补充：检索数 $k\in\{3,5\}$ 敏感性、GRPO 训练曲线。

### 3.5 基线复现

- 因 SkillOS 未完全公开推理设置（Qwen3-8B 的 thinking 模式），作者做了预实验校准：ALFWorld 用 thinking、WebShop 用 non-thinking；WebShop 额外加简短搜索指导段落，并刻意校准使**无记忆基线不高于**其报告值（8.6 vs 9.8 SR），保证增益"保守测量"。

## 6. 主要结论与发现

1. **读取时整理优于写入时整理（同容量整理器下）**：即使免训练，JITMEM-base 也常超过写入时基线。例：WebShop 上 JITMEM-gemini 达 61.0 SR，而 SkillOS 仅 41.0（同用 Gemini-2.5-Pro）；ALFWorld 上 JITMEM-base 60.5 vs ReasoningBank 55.7、SkillOS-base 53.1。
2. **RL 训练进一步叠加增益，且优于写入时 RL**：主结果中较最强基线分别提升 **+16.2（ALFWorld）、+16.3（WebShop）、+3.9（τ²-bench）** SR 点；τ²-bench 增益集中在 Telecom（+11.0），Airline/Retail 提升不显著，说明读取时整理更适合需要"程序性指导合成"而非简单事实检索的任务。
3. **弱整理器可胜过强整理器**：ALFWorld + GPT-5.4 执行器下，JITMEM-base（Qwen3-8B 整理）79.3 > ReasoningBank（GPT-5.4）77.9 与 SkillOS-gpt 70.0——说明增益来自读取时任务自适应机制本身，而非整理器模型强度。
4. **训练更简单**：仅用任务奖励，无需额外 judge 的内容质量奖励、无需任务分组、无需回报塑形；训练曲线稳定上升，执行步数同步下降。
5. **跨执行器可迁移**：单次用 Qwen3-8B 训练的整理器迁移到 GPT-5.4 后达 88.1 SR，与直接训练版本仅差 1.4 点，说明学到的是通用整理策略而非执行器特定模式。
6. **效率更高**：相比写入时方法，输入 token 减少 50.3%–56.3%，执行步数减少 28.4%–31.4%；相对无记忆仅增加 1.9K 输入 token（ReasoningBank +10.7K、SkillOS-base +13.4K），同时步数减少 18.5%–21.9%。
7. **消融结论**：
   - 任务自适应条件是核心：去掉后 RL 版最多掉 11.4（ALFWorld）/10.4（WebShop），且训练后差距扩大，说明 RL 专门学会了利用任务信号。
   - 质量过滤入库优于"存全部+标注正确性"（掉 1.5–2.9 / 2.3–3.4）。
   - 原始轨迹保留重要：改为写入时蒸馏最多掉 8.2 SR（WebShop）。
   - 强制检索为空集导致最大退化（最多 −14.8 / −15.2），证明 RL 增益**确实来自"学会蒸馏检索到的经验"**，而非参数化知识。
   - 分阶段刷新收益有限（最多 +2.8 SR）；测试库热启动几乎无影响，说明冷启动处理得当。
   - $k=3$ 与 $k=5$ 差异在标准差内，对检索数量不敏感。
8. **定性发现**：同一轨迹对不同任务产生不同载荷（"热土豆"任务突出状态转换策略，"报纸"任务突出放置策略）；RL 训练还能自发涌现环境特定的程序语义（如"先移动到台灯，再用台灯检查碗"），而该流程并未写在提示词中。

## 7. 优点与亮点

- **问题重构清晰有力**：把"何时整理记忆"这一被忽视的维度提炼为核心研究问题，动机论证（信息不可逆丢失 + 查询无关摘要 + 长时程信用分配）逻辑闭环。
- **信用分配极大简化**：读取时整理使奖励零延迟，直接消除 SkillOS 类方法对任务分组的依赖，训练框架显著更简洁（无价值网络、无复合奖励、无回报塑形）。
- **模块化解耦**：整理器与执行器分离，一个整理器可服务多个执行器，降低部署成本，并让记忆组件可被独立评估——这是相对并发工作 MemHarness 的明确优势。
- **免训练即有效**：`-base` 变体的强表现把"机制贡献"与"训练贡献"干净地分离开，使结论更有说服力。
- **实验严谨性好**：同一检索器、基线复现校准至保守、多次随机顺序 + 标准差、消融矩阵完整（每个设计选择逐一隔离）。
- **效率与效果双赢**：token 与步数同时下降，说明载荷信息密度高，具有实际部署价值。
- **定性分析具体**：用同一轨迹在不同任务下的不同载荷（图 3）直观证明"任务自适应"非空谈。

## 8. 不足与局限

**论文自陈的局限**：
- **检索器简单**：仅用 BM25 且只索引任务描述，记忆库规模增大、任务多样化后可能成为瓶颈。
- **额外开销**：每个任务多一次 LLM 调用（整理器），带来推理成本与延迟。
- **载荷格式固定且按 benchmark 手工设计**：缺乏通用性，跨新领域需重写提示词。
- 未来方向：联合优化载荷格式、更强检索器、从"每任务一次"扩展到 turn/step 级自适应。

**可进一步指出的局限**：
- **τ²-bench 训练缺失**：无标准训练集，导致该 benchmark 上无法验证训练版 JITMEM，也缺少消融，覆盖不完整；且该 benchmark 上 Airline/Retail 域提升不显著，方法适用边界被论文自身承认（更适合程序性指导合成类任务）。
- **训/测分布偏移**：训练用静态库（基座执行器轨迹 + 真值标签），测试库在线增长且用 LLM judge 过滤，两者来源不同；虽然分阶段刷新实验显示差距不大，但这本身是设定的非理想性。
- **LLM-as-judge 依赖**：入库质量门依赖 judge，可能引入系统性偏差（错误接受/拒绝轨迹），论文未量化 judge 准确率或与真值的偏差。
- **批式评估协议非真实流式**：批内共享记忆库状态，与真实"一任务一更新"的流式设定有差异，可能高估或低估早期任务收益；冷启动效应虽被讨论，但影响未完全解耦。
- **定性分析样本少**：图 3、图 4 及附录示例为个案展示，缺乏系统性的载荷质量量化分析。
- **奖励信号单一**：仅用任务成功率，可能在成功但低效或不符合政策的轨迹上缺乏惩罚（WebShop 的连续分数部分缓解了此问题）。
- **算力门槛**：8×H200、单次训练 21–27 小时，加上每任务一次额外 LLM 调用，对资源受限场景不太友好。
- **超参敏感性覆盖有限**：只测了 $k\in\{3,5\}$，未系统探索批大小、group size、检索策略等。
