## 摘要
语言模型智能体日益处理长时程任务，这些任务的交互历史超出了模型的活跃上下文。近期研究开始利用强化学习将记忆控制纳入策略，通常依赖于相对短时程的领域特定训练环境中预定义的记忆工具。这种设置将学到的记忆行为绑定到基础模型预训练之外、必须从头学习的特定环境接口上，因此即使经过后训练，智能体在长时程任务中也难以使用记忆。为解决这些局限，我们提出 Coding Agent Memory Gym（CAMG），一套跨越 Shop、Coding、DeepResearch 和 AutoResearch 的长时程智能体强化学习环境。除每个环境的原生任务接口外，CAMG 还提供可执行的 shell 访问和回合持久工作区，使智能体能够在整个回合中创建、修改、搜索和复用文件作为记忆。我们还提出 CAMG-RL，它使用完全异步 PPO 在四个环境中联合训练单一策略，直接从下游任务奖励中学习这种基于文件的记忆行为，并从匹配规模的 Qwen3.5 模型训练了 CAMG-RL-4B 和 CAMG-RL-9B。在 SWE-bench Verified 和 MLE-bench Lite 上，CAMG-RL-4B 和 CAMG-RL-9B 分别与 Qwen3.5-35B-A3B 和 Qwen3.5-122B-A10B 具有竞争力。

## Abstract
Language-model agents increasingly tackle long-horizon tasks whose interaction histories exceed the model's active context. Recent work has begun to use reinforcement learning to make memory control part of the policy, often relying on predefined memory tools within domain-specific training environments of relatively short horizons. This setup ties learned memory behavior to environment-specific interfaces that lie outside the base model's pre-training and must be learned from scratch, so even after post-training, agents struggle to use memory in long-horizon tasks. To address these limitations, we introduce Coding Agent Memory Gym (CAMG), a suite of long-horizon agentic-RL environments spanning Shop, Coding, DeepResearch, and AutoResearch. Alongside each environment's native task interface, CAMG provides executable shell access and an episode-persistent workspace, enabling agents to create, revise, search, and reuse files as memory throughout an episode. We also introduce CAMG-RL, which trains a single policy jointly across all four environments with fully asynchronous PPO, learning this file-based memory behavior directly from downstream task reward, and we train CAMG-RL-4B and CAMG-RL-9B from Qwen3.5 models of matching size. On SWE-bench Verified and MLE-bench Lite, CAMG-RL-4B and CAMG-RL-9B are competitive with Qwen3.5-35B-A3B and Qwen3.5-122B-A10B, respectively.

## 1. 核心问题与研究动机

- **背景**：语言模型智能体越来越多地处理长时程任务，交互历史不断累积并超出模型的有效上下文。例如编码智能体需要回忆起"早先某个修复为何被拒绝"，但该对话已离开提示词。
- **现有做法的缺陷**：近期工作开始用强化学习（RL）把记忆控制纳入策略，但通常依赖**预定义的记忆工具**和**短时程的领域特定训练环境**。
- **关键矛盾**：这类记忆工具属于环境专用接口，落在基础模型预训练分布之外，必须从头学习。因此即便经过后训练，智能体在长时程任务中仍难以有效使用记忆。
- **核心开放问题**：在代码预训练之上做强化学习，能否激发编码智能体**保留并复用超出活跃上下文的信息**的能力？
- **整体含义**：作者主张不再引入专门的记忆工具，而是让任务型编码智能体用**普通文件系统操作**（创建、修改、搜索、读取文件）来维护记忆，并通过下游任务奖励端到端地学出来。

## 2. 方法论

### 2.1 CAMG：长时程智能体强化学习环境套件

- 覆盖四个环境，任务奖励均由固定程序从策略实际执行行为中产生：
  - **Shop**：由 720 个验证过的 WebShop 商品合成六会话购买任务；会话间清空活跃会话记录，后续购买依赖策略保留的信息。含 8 类跨会话依赖家族（属性链、潜在偏好、近因覆盖、干扰鲁棒性、组合回忆、负约束、意图澄清、选择性记忆）。
  - **Coding**：从 SWE-smith 抽取 issue–仓库对，保留可执行且参考修复能通过测试的任务，共 **11,218 个任务 / 93 个仓库**。
  - **DeepResearch**：基于 LiteResearcher 的 Search–Visit–Answer 交互，从固定检索语料收集证据后作答，由冻结的语义裁判评分，共 **26,597 个任务**。
  - **AutoResearch**：使用公开 OpenMLE 任务包（数据、可执行提交、原生指标），共 **931 个任务 / 804 个任务家族**。

### 2.2 通用编码智能体接口

- 每个环境保留原生任务交互，同时共享一个**可执行 shell 访问**与**回合持久工作区**。
- 动作空间为任务动作集与文件系统动作集的并集：`A_d = A_task_d ∪ A_fs`，其中文件系统动作是单一 `shell_command`（可创建、检查、搜索、修改、执行文件）。
- **记忆载体**：工作区内 `.agent_memory/` 下的常规文件才算策略记忆；仓库编辑、临时文件、缓存不计入。
- **上下文替换机制**：环境在上下文压力或子回合边界触发替换，并用固定提醒要求策略用**一次普通文件动作**创建/更新 `.agent_memory/CONTINUATION.md`（8,192 字节上限）。环境本身从不写入或清空该文件；只有验证策略动作确实把该文件变为非空常规文件后，才替换活跃消息历史。替换后**不插入文件内容**，策略需通过后续读取自行恢复信息。

### 2.3 CAMG-RL：算法与关键技术细节

- **核心思想**：把任务交互与文件系统操作放在**同一条动作轨迹**上，用下游任务奖励端到端优化，包括策略生成的记忆文件内容。
- **策略轨迹**：每个完整响应 `a_t = y_{t,1:L_t}` 构成一个 RL 步骤 `z_t = (h_t, a_t, ℓ^b_t, r_{d,t}, e_t, v^b_t)`，其中 `ℓ^b_t` 为行为策略对数概率，`v^b_t` 标识行为策略版本。
- **信用分配**：对响应步做 GAE（`γ = λ = 1`），`δ_t = r_{d,t} + γ(1−e_t)·V̄_{t+1} − V̄_t`，`Â_t = δ_t + γλ(1−e_t)Â_{t+1}`；把响应级优势 `Â_t` 赋给该响应内所有采样 token，再做环境内中心化、环境 token 数逆权重与掩码标准化。
- **双粒度 PPO**：**每响应估计一个优势**（稳定），**每采样 token 裁剪一个概率比** `ρ_{t,j}`（细粒度），避免 Turn-PPO 过粗、token 级 GAE 高方差。策略裁剪 `ε = 0.2`，价值裁剪 `ε_V = 0.5`。
- **联合目标**：`J_CAMG-RL(θ) = (1/|D|) Σ_{d∈D} J_d(θ)`，`|D| = 4`，每次 rollout 均匀采样一个环境。
- **全异步 PPO**：rollout 与学习完全解耦并行。rollout worker 将完成的回合追加到持久队列，learner 组装优化批次、更新共享 actor 与 critic，并把新权重发布给后续回合。队列吸收不同长度回合的完成时间差，避免等待最慢回合。
- **奖励设计**（稀疏、基于成功）：Shop 按购买正确性给分；Coding 仅隐藏测试通过给 1；DeepResearch 由语义裁判判定；AutoResearch 含首次提交、首次成功执行、首次验证指标等一次性里程碑。

## 3. 实验设计

- **CAMG 基准**：每环境 128 个测试任务，共 **512 个任务**。划分互斥依据：Shop 按商品、Coding 按仓库、DeepResearch 按重复问题组、AutoResearch 按任务家族。所有方法共享相同任务、解码、动作预算、运行时、接口与 grader。
- **外部迁移基准**：
  - **SWE-bench Verified**（500 任务，官方容器 grader，issue 解决率）
  - **MLE-bench Lite**（22 个竞赛，Any Medal 率）
- **对比方法**：
  - 冻结/免训练控制：冻结 Qwen3.5-4B、**Mem0**、**Letta Code**
  - 可学习记忆方法：**CompactionRL**（学习式上下文压缩）、**AgeMem**（六个 LTM/STM 工具）
  - 外部对比：冻结 Qwen3.5 的 4B / 9B / 27B / 35B-A3B / 122B-A10B / 397B-A17B
- **主要消融与控制实验**：
  - 无记忆动作梯度（从 actor loss 中移除所有 `.agent_memory/` 访问响应）
  - 无通用记忆文件（重训版 / 仅评估版，只保留 CONTINUATION.md）
  - token 级估计控制（用 per-token GAE 替代响应级优势）
  - **记忆内容干预**：在首次上下文替换后分叉为 intact / blank / shuffled 三条件，做因果隔离
  - 单一分布外工具（`apply_patch`）对照，隔离"接口"与"工具清单"两个变量
  - AgeMem 在**原配方**（三阶段渐进训练 + step-wise GRPO + 复合奖励）下的复现
  - 接口先验探针：4 类意图（store/retrieve/revise/remove）× 多个变体（原生文件、别名文件、AgeMem 工具原生形式、hybrid、删除 shell 文档），用冻结基座的动作 NLL（nats/token）度量
- **统计**：10,000 次配对 bootstrap 重采样，按环境分层；每方法重复训练 5 次做鲁棒性检验。
