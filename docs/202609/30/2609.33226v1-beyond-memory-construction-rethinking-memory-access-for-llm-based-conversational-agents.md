## 摘要
记忆是对话智能体的核心组件，使其能够在长程交互中表现出连贯且具有上下文感知的行为。近期方法通常依赖基于LLM的记忆构建，即将原始交互改写为结构化记忆单元，随后通过RAG流水线进行检索。尽管在受控环境中有效，我们表明这一范式在长时程、高熵对话中会失效：随着上下文长度和信息复杂度增长，记忆构建变得日益有损且不稳定，并且由于反复调用LLM而带来难以承受的成本。为解决这些局限，我们提出Threader，一种将关注点从记忆构建转向对原始交互进行高效、结构感知访问的记忆系统。Threader不重写交互，而是将其作为一等记忆保留下来，通过轻量级增量分割将其组织为主题连贯的片段，并通过多视图表示实现准确检索。在查询时，它执行多信号检索，将片段级访问与局部证据匹配相结合，确保完整性和连贯性。大量实验表明，Threader持续提升答案准确率和证据召回率，同时显著降低记忆构建开销。

## Abstract
Memory is a core component of conversational agents, enabling coherent and context-aware behavior over long interactions. Recent approaches commonly rely on LLM-based memory construction, where raw interactions are rewritten into structured memory units and later retrieved via a RAG pipeline. While effective in controlled settings, we show that this paradigm breaks down in long-horizon, high-entropy conversations: memory construction becomes increasingly lossy and unstable as context length and information complexity grow, and incurs prohibitive cost due to repeated LLM invocation. To address these limitations, we propose Threader, a memory system that shifts the focus from memory construction to efficient, structure-aware access over raw interactions. Instead of rewriting interactions, Threader preserves them as first-class memory, organizes them into topic-coherent segments via lightweight incremental segmentation, and enables accurate retrieval through multi-view representation. At query time, it performs multi-signal retrieval that combines segment-level access with localized evidence matching, ensuring both completeness and coherence. Extensive experiments demonstrate that Threader consistently improves answer accuracy and evidence recall, while significantly reducing the memory construction overhead.

# 论文总结：Beyond Memory Construction: Rethinking Memory Access for LLM-based Conversational Agents

## 1. 核心问题与研究动机

- **背景**：LLM 对话智能体需要在长程多轮交互中维持长期记忆。当前主流范式是"外部记忆 + LLM 记忆构建"：先用 LLM 将原始交互改写、摘要或抽取为结构化记忆单元，存入记忆库，再通过 RAG 流水线检索。
- **核心问题**：该范式在**长时程、高熵**的真实对话场景中失效。作者通过实证分析揭示两大缺陷：
  - **记忆构建有损且不稳定**：随着会话被拼接变长（1×→8×），Mem0 的 QA 准确率从 55.00% 降至 5.00%，构建出的记忆单元数量和信息量同步萎缩；大量查询相关证据被"部分保留"或"完全丢失"。
  - **构建成本过高**：处理 100K token 交互时，Mem0/MemU/EverMemOS/A-Mem 的构建期 LLM 输入 token 分别膨胀至原始的 2×/9×/13×/21×，并伴随数百次 LLM 调用。
- **关键洞察**：现有方法的根本瓶颈在于**构建时抽象（construction-time abstraction）**——既有损又昂贵。因此应转向"将原始交互作为一等记忆，在查询时进行高效、结构感知的访问"。
- **新挑战**：在长且纠缠的交互历史中，如何精确定位完整且连贯的查询相关证据。

## 2. 方法论：Threader

### 2.1 核心思想
放弃 LLM 重写，保留原始交互为无损记忆；通过**轻量级增量分割 + 多视图表示 + 多信号检索**实现结构感知访问。

### 2.2 关键技术细节

- **增量主题连贯分割（Incremental Topic-Coherent Segmentation）**
  - 将分割形式化为流式二元决策：对当前片段 $s'$ 与新到回合 $t'$，预测 CONTINUE 或 SEGMENT。
  - 输入构造：$x = \text{Concat}(s', [\text{SEP}], t')$，输出二分类标签 $y \in \{0,1\}$，实现完全在线分割。
  - 使用轻量级 **BERT 编码器**，训练标签结合会话边界的硬标签与 GPT-4.1-mini 标注的会话内主题边界软标签，采用标准交叉熵损失。
  - 相比 LLM 分割（SECOM、EverMemOS）更轻量，相比 LightMem 等启发式方法支持完全增量。

- **多视图片段表示（Multi-View Segment Representation）**
  - 将每个片段拆为三个互补视图：用户侧 $x^{(u)}$、助手侧 $x^{(a)}$、完整交互 $x^{(f)}$。
  - 共享编码器 $f_{enc}$ 分别编码：$e^{(v)}_i = f_{enc}(x^{(v)}_i)$，$v \in \{u,a,f\}$。
  - 目的：避免冗长的助手内容淹没稀疏但关键的用户侧证据。

- **多信号证据检索（Multi-Signal Evidence Retrieval）**
  - 三种信号：稠密语义（三视图加权余弦，权重和为 1）、BM25 词法、Cross-encoder 重排。
  - **Stage I 高召回片段检索**：取稠密与 BM25 各自 Top-$K_1$ 的并集构成候选池 $C$。
  - **Stage II 证据级精炼**：将稠密匹配从片段级下沉到消息级，对片段内每条用户/助手消息计算相似度，取 Top-$K_2$ 求平均得到精炼分数；再与 BM25 归一化融合，最后与 cross-encoder 分数加权（权重 $\alpha$）得到最终分数。
  - 最终仍以**片段为单位**返回 Top-$K$，兼顾细粒度定位与上下文连贯性。

### 2.3 算法流程（文字版）
遍历会话 → 增量分割得主题片段 → 构建三视图嵌入与稠密/BM25 索引 → 查询编码后 Stage I 粗召回 → Stage II 消息级精炼 + 重排 → 选 Top-$K$ 片段 → 交由响应模型生成答案。

## 3. 实验设计

- **数据集 / Benchmark**
  - **LongMemEval**：500 个 QA，平均会话长度约 2,160 token，含 6 类问题（单会话用户/助手/偏好回忆、多会话推理、知识更新、时间推理），用 LLM-as-a-Judge 评估。
  - **PersonaMem**：589 个 QA，平均会话长度约 26,165 token，含 7 类个性化问题，用 exact match 评估。
  - 未纳入 LoCoMo，因其会话过短（~586 token）且为模拟双人对话，与目标场景不符。
- **对比方法（7 个）**
  - 记忆系统：Mem0、MemU、A-Mem、MemOS、EverMemOS。
  - Agentic RAG：Self-RAG、HippoRAG2。
- **模型配置**
  - 主设置：GPT-4.1-mini 用于记忆构建，GPT-5-mini 用于响应生成；低延迟设置用 GPT-5-nano。
  - 额外跨骨干验证：Qwen3.5-Flash + Qwen3.5-Plus。
  - 所有 LLM 构建方法共享同一构建模型，所有方法共享同一响应模型以保证公平。
- **消融维度**：分割方式、多视图表示、检索信号、检索粒度。
- **附加分析**：Top-K 敏感性、视图权重/融合权重敏感性、成本分解、动机数据（会话拼接 1×/2×/4×/8×）、证据保真度人工检查、案例研究。

## 6. 主要结论与发现

- Threader 在两个数据集、两个响应骨干上均持续优于全部 7 个基线：
  - LongMemEval：相对最强基线提升 3.33%（GPT-5-nano）与 6.84%（GPT-5-mini）。
  - PersonaMem：相对提升 4.50% 与 7.29%。
- **证据密集型任务增益最显著**：时间推理 +6.94%/+11.02%，知识更新 +5.80%，PersonaMem 的泛化到新场景 +17.07%~25.00%。
- **成本大幅降低**：构建阶段零 LLM 调用，索引耗时 18.33s，相比重写类方法提速超 110×；查询时延 8.66s，无检索侧 LLM 调用，token 零额外开销。
- **在偏好聚合类任务上不占优**（如 Single-Session-Preference、Preference-Evolution），因其不做显式摘要，需依赖响应模型完成高层综合；但证据审计显示其检索召回率可达 100%，瓶颈在生成侧——换用更强响应模型后准确率显著回升（如 SS-Pref 达 100%）。
- 跨 Qwen 模型族仍保持最优，说明结构感知访问的优势不依赖特定模型族。

## 7. 优点

- **范式创新**：将记忆系统设计重心从"构建压缩表示"转向"对原始交互的结构感知访问"，直面构建时信息损失与成本问题。
- **轻量无损**：构建期完全无需 LLM，保留原始证据，避免摘要/改写带来的信息丢失与不稳定性。
- **在线增量分割**：将分割建模为流式二分类，支持流式交互且无需全上下文重算，训练数据构造巧妙（硬会话边界 + 软主题边界互补）。
- **多视图表示针对性强**：显式解耦用户/助手/完整视角，缓解助手冗长内容淹没用户关键信号的问题。
- **两阶段多信号检索设计合理**：粗召回保证覆盖率，消息级精炼定位局部证据，最终仍以片段返回保证连贯性。
- **实验严谨**：统一骨干、分阶段成本报告、严格 LLM-as-Judge 协议、跨数据集迁移（LongMemEval 训练的 segmenter 直接用于 PersonaMem）、跨模型族验证、详细的案例研究。
- **工程价值高**：构建与查询成本均低，易于部署到长时程对话系统。

## 8. 不足与局限

- **依赖分割质量**：分割错误会向下游传播；若相关证据被切分到不同片段边界，可能降低召回。论文自身在 Limitations 中承认这一点。
- **超大规模记忆的可扩展性**：未验证终身/极大规模交互历史下的存储与检索效率，缺乏记忆剪枝、压缩、分层索引机制。
- **长程依赖抽象能力有限**：Threader 刻意推迟抽象到查询时，对需要跨远距离片段整合的高层推理任务可能不利；偏好推断、偏好演化、新想法生成等任务上表现偏弱。
- **生成侧瓶颈**：偏好类任务的错误源于响应模型的综合能力而非检索，说明对强响应模型有依赖；换用更强模型才能释放原始证据的潜力。
- **成本对比不完整**：MemOS 因黑盒接口未纳入成本对比；未披露实验总开销与总计算量。
- **训练监督偏差风险**：分割器的软标签由 GPT-4.1-mini 生成，可能引入标注模型的偏好；训练数据来自 LongMemEval abstention 实例，域覆盖有限。
- **应用限制**：面向事实性记忆（factual memory），尚未扩展到体验性记忆、任务轨迹、工具调用等动作导向场景；隐私治理、用户可控的记忆编辑/遗忘机制仍属未来工作。
- **实验范围**：仅两个数据集，且均为英文基准；未涉及多语言、多模态或真实产品级部署验证。
