## 摘要
长期与用户交互的智能体必须从持续增长的交互历史中回忆事实、偏好、事件和变化。现有记忆系统通常将交互压缩为通用摘要，或检索匿名文本块，使智能体难以识别正确的实体、属性及支撑证据。我们提出 EnSIMem，一种面向智能体的实体结构化长期记忆架构。在离线构建阶段，系统将交互组织为主题连贯的情节，并构建以对话为依据的索引条目，其形式为 [实体][实体类型][属性: 值]。每个条目保留其源对话轮次、时间信息以及可用的多模态字段。在在线交互阶段，智能体的请求被分解为证据需求，其属性与记忆索引对齐。随后，实体-属性查找与自适应检索收集点式推理、时间推理、组合推理和聚合推理所需的证据。智能体基于保留的源证据而非有损的记忆摘要生成响应。在长期智能体记忆基准上，EnSIMem 在保持紧凑、以证据为中心的上下文的同时，实现了高答案准确率。这些结果表明，实体结构化索引与情节级溯源为智能体的长期记忆提供了可靠基础。我们模型的代码可在 https://github.com/RamonMeng/EnSIMem 获取。

## Abstract
An agent that interacts with users over long periods must recall facts, preferences, events, and changes from a continuously growing interaction history. Existing memory systems often compress interactions into generic summaries or retrieve anonymous text chunks, making it difficult for an agent to identify the correct entity, property, and supporting evidence. We present EnSIMem, an entity-structured long-term memory architecture for an agent. During offline construction, the system organizes interactions into theme-coherent episodes and builds dialogue-grounded index entries of the form [entity][entity_type][property: value]. Each entry preserves its source turns, temporal information, and available multimodal fields. During online interaction, the agent's request is decomposed into evidence requirements whose properties are aligned with the memory index. Entity-property lookup and adaptive retrieval then collect the evidence needed for point, temporal, compositional, and aggregation reasoning. The agent generates its response from the preserved source evidence rather than from lossy memory summaries. On long-term agent-memory benchmarks, EnSIMem achieves high answer accuracy while maintaining compact, evidence-focused contexts. These results show that entity-structured indexing and episode-level provenance provide a reliable foundation for long-term memory in agents. The code of our model is available at https://github.com/RamonMeng/EnSIMem.

## 1. 核心问题与整体含义（研究动机与背景）

- **核心问题**：长期运行的智能体需要从持续增长的交互历史中回忆事实、偏好、事件与变化，但现有记忆系统存在"可扩展性 vs. 具体性"的两难：
  - **完整上下文**：保留全部证据，但导致上下文膨胀、延迟升高、注意力被无关内容干扰（"lost in the middle"）。
  - **摘要压缩**：降低上下文长度，但会丢失细节、时间限定词和溯源信息。
  - **传统 RAG**：检索匿名文本块或向量近邻，虽紧凑但不显式指明"哪个实体、哪个属性、哪个事件"使记忆变得相关。
- **整体含义**：作者将长期对话记忆重构为一个"短上下文推理问题"——用结构作为记忆的**寻址系统**（address system），而非有损的替代品。结构决定"去哪里找"，原始对话证据决定"回答什么"。
- **关键洞察**：相关（relevance）不等于充分（sufficiency）。高相似度的片段可能回答点式问题，但对计数、比较、多实体组合类问题，停止规则会失效。

## 2. 方法论：核心思想与关键技术细节

**总体设计原则**：分离查询无关的记忆构建与查询相关的访问，即 `M = F_memory(D)`，`ŷ = G(q, R(q, M))`。

### 2.1 离线情节记忆构建（query-independent）

- **主题连贯的情节划分**：把每个会话切分为连续、主题连贯的情节（episode），邻近轮次只要围绕同一实体/事件/目标/未解决的指代就保持在一起，仅在持续的话题或任务转移处设边界。这是"中间粒度"，既能保留代词和局部上下文，又避免整段会话引入无关内容。该划分是无监督的，不要求唯一正确的边界。
- **实体-属性索引抽取**：对每个情节 e 抽取显式提及的实体和显著事件，表示为：
  - `r = ⟨x, t, P, e, π⟩`，其中 `P = {(p_i, v_i)}`，x 为实体，t 为类型，m 为属性数，π 指向支持该记录的源对话轮次。
  - 检索视图为：`[x][t][{p_i : v_i}] → episode id`。
- **属性粒度控制（关键设计）**：属性仅归一化到**中间语义层级**——宽到能对齐同义改写，细到能区分不同关系与事件。示例：
  - "took a helicopter to Chicago" → `{destination: Chicago, means of transport: helicopter}`
  - "traveled to Chicago" → `{destination: Chicago}`
  - 集合式表示让两种表述在共享的 destination 上对齐，同时只在显式陈述时保留额外交通方式信息，不把无关动作坍缩为"activity"这类通用标签。
- **情节与索引记录互补**：情节提供连贯证据单元（解决代词、省略、时间指代），索引只暴露定位该单元所需的实体与关系。二者缺一不可。

### 2.2 在线需求感知检索（query-dependent）

- **需求感知查询规划**：将请求 q 分解为原子证据需求 `H(q) = {h_1, ..., h_K}`，每个 `h_i = (x_i, t_i, p_i, v_i, c_i)` 指定目标实体、类型、兼容属性及可选值/条件；同时判定查询类型为 **point / temporal / compositional / aggregative**，并据此设定证据预算。
- **结构化匹配 + 稠密回退**：候选集为 `E(q) = Dedup(Structured(I, H(q)) ∪ Dense(T, H(q)))`，其中 I 为结构化索引，T 为其文本形式。按情节身份合并候选，**按需求覆盖率而非固定相似度阈值或通用 top-k 停止检索**。
- **证据预算的自适应性**：点式问题可能在一个被支持的需求后即停止；计数或比较问题则持续到所有必要情节被覆盖。

### 2.3 基于证据的响应生成

- 将选中情节展开为紧凑缓冲区 Γ(E(q))，包含原始轮次、说话人、时间戳和可用的多模态字段。
- 最终回答 `ŷ = G(q, H(q), Γ(E(q)))` 基于原始证据而非索引记录生成。
- 核心机制：**定位与解释分离**——紧凑结构化记录使相关证据可寻址，源情节保留推理正确所需的措辞与上下文。
- 全流程可审查：可从查询需求 → 实体-属性访问路径 → 支持答案的对话轮次与多模态观测逐层追溯。

## 7. 优点

- **设计理念清晰且有力**："结构用于寻址，原始证据用于解释"的分离原则，同时规避了全上下文噪声和摘要信息损失两类失败模式。
- **属性粒度控制精巧**：中间层级的集合式属性表示（如 `{destination, means of transport}`）能在不依赖固定数据集本体（ontology）的情况下对齐改写，同时保留事件特异性。
- **需求感知与自适应预算**：将检索从"选最相似的记忆"转变为"组装支持目标推理操作的最小证据集"，显式区分点式、时序、组合与聚合查询。
- **免训练、即插即用**：无需额外训练或监督，可复用离线表示服务多个未来查询，在线只消耗当前查询所需的计算。
- **可解释与可审查**：每条答案可追溯到"查询需求 → 实体-属性访问路径 → 支持对话轮次与多模态观测"。
- **实验严谨性**：双评估模型分别报告、本地复现 MEMORA 做协议校验、逐因素隔离的消融设计、以及评估模型一致性的量化分析。
- **案例研究有说服力**：三个案例分别暴露跨情节覆盖、相对时间归一化、多模态细粒度实体-属性定位三类机制，并清楚说明竞争系统的具体失败模式。

## 8. 不足与局限

- **在线延迟较高**：EnSIMem 14.4 秒 vs. MEMORA 5.70 秒，主要开销来自需求感知规划（10.3 秒）和检索（1.59 秒）。对交互式应用而言，逐查询重复分析可能过于昂贵。作者提出的优化方向（缓存查询模式、批量属性匹配、规划蒸馏到小模型、置信度感知早停）均属未来工作。
- **效率比较为方向性**：token 计账方式可能不同，作者自己也声明该比较只是 directional；MEMORA 的生成延迟未单独报告（表中为 N/A）。
- **范围仅限情节式对话记忆**：LoCoMo 与 LongMemEval 评估的是对话回忆，而非程序性技能执行或长期语义巩固。将"寻址 + 溯源"原则扩展到语义记忆和程序性记忆留作未来工作。
- **依赖 LLM 的中间环节**：情节切分、属性抽取、查询规划均由 LLM 完成，底层模型变化可能影响中间记忆表示，带来稳定性风险。

  - 使用 LLM 二值评判作为人类评估的可扩展代理，存在已知的评估器偏差；作者只做了聚合级一致性分析，未做逐查询配对分析（如 Cohen's κ、McNemar 检验、bootstrap 置信区间）。

- **消融实验规模有限**：消融在"固定的 LoCoMo 子集"上进行，未说明子集规模与抽样方式，可能影响结论的统计泛化性。
