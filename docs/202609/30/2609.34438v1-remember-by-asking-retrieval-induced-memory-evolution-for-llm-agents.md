## 摘要
长期记忆对于语言智能体在长时间、多会话交互中保持连贯且有效的行为至关重要。现有记忆系统主要在读取时使用检索，而写入时的记忆形成仍依赖直接抽取或压缩。然而，当未来信息需求未知时，一次性压缩整个交互可能忽略之后可能重要的局部细节。为此，我们提出 RIME，一种检索诱发的记忆框架，将记忆构建从整体式压缩转向以证据为中心的整合。RIME 使用通用自问问题来检索聚焦的对话证据，并将记忆形成同时建立在检索到的证据和相关历史记忆之上，这些信息被共同协调到一个带有时间和来源信息的演化记忆库中。在推理时，压缩记忆作为主要的而非唯一的证据来源：当它无法支持回答时，RIME 会检索相关源对话及其局部上下文，以恢复记忆形成过程中遗漏的信息，而无需诉诸全历史处理。在 LoCoMo 上使用 Qwen3-235B-A22B 和 GPT-5.6 Sol 进行的大量实验表明，RIME 在比较方法中于所有三个质量指标上持续取得最佳性能，同时所需查询时 LLM token 显著更少。

## Abstract
Long-term memory is essential for language agents to maintain coherent and effective behavior over extended, multi-session interactions. Existing memory systems mainly use retrieval at read time, while write-time memory formation still relies on direct extraction or compression. However, when future information needs are unknown, compressing an entire interaction in one pass can overlook locally important details that may matter later. To this end, we introduce RIME, a retrieval-induced memory framework that shifts memory construction from monolithic compression toward evidence-centered integration. RIME uses generic self-questions to retrieve focused dialogue evidence and grounds memory formation in both the retrieved evidence and relevant historical memories, which are jointly reconciled into an evolving memory bank with temporal and provenance information. At inference time, compressed memory serves as the primary rather than the sole source of evidence: when it cannot support an answer, RIME retrieves relevant source dialogue together with its local context to recover information omitted during memory formation, without resorting to full-history processing. Extensive experiments on LoCoMo with Qwen3-235B-A22B and GPT-5.6 Sol show that RIME consistently achieves the best performance across all three quality metrics among the compared methods, while requiring substantially fewer query-time LLM tokens.

## 1. 核心问题与研究动机

- **背景**：长期记忆是语言智能体在跨会话、长程交互中保持行为连贯的基础，缺少持久记忆会导致无法保留用户特定信息、无法跨会话关联事件、无法复用过往经验。已有工作发展出记忆流、记忆库及结构化/自适应记忆系统。
- **核心问题**：现有系统普遍**在读取时检索，而写入时仍依赖直接抽取或一次性压缩**整段交互。
- **关键矛盾**：
  - 未来信息需求未知，一次性压缩会**忽略当时看似次要、日后却重要的局部细节**；
  - 只依赖压缩记忆，被丢弃的信息**无法恢复**；
  - 若回退到全历史处理（如 D-Mem 的 Full Deliberation），则**推理成本显著上升**。
- **整体含义**：作者主张把"选择性访问源对话"同时引入**记忆形成**与**记忆使用**两个阶段，将记忆构建从"整体式压缩"转向"以证据为中心的整合"，在保证质量的同时控制查询时开销。

## 2. 方法论

### 2.1 核心思想
- 用一组**与下游查询无关的通用自问问题（generic self-questions）**作为检索线索，先在当前会话中"召回"聚焦证据，再基于证据做记忆整合，而非对整段会话做全局压缩。
- 推理时，压缩记忆是**主要但非唯一**的证据来源；当记忆不足以支撑回答时，才回取与查询相关的源对话轮次及其局部上下文。

### 2.2 关键技术细节

**（A）基于检索的记忆形成（Retrieval-based Memory Formation）**

- **固定问题集**：$Q=\{q_r\}_{r=1}^{R}$，实现中 $R=6$，覆盖人物与关系、事件、活动、计划、状态与偏好、具体事实细节；跨所有会话共享，不依赖下游查询。
- **相似度**：以余弦相似度 $s(a,b)=\frac{\phi(a)^\top\phi(b)}{\|\phi(a)\|_2\|\phi(b)\|_2}$ 度量（$\phi$ 为文本嵌入函数）。
- **问题引导的证据召回**：对每个问题 $q_r$，从当前会话 $S_t$ 中取 top-$k_f$ 相关对话轮，得到 $R_t^{(r)}$；合并所有问题召回结果为 $R_t=\bigcup_{r=1}^{R}R_t^{(r)}$。问题在此处充当**检索线索**而非摘要指令。
- **局部上下文扩展**：由于部分召回轮次依赖邻近上下文，进行**两轮**邻域扩展：$\tilde{R}_t^{(\ell+1)}=\tilde{R}_t^{(\ell)}\cup N_t(\tilde{R}_t^{(\ell)}),\ \ell=0,1$，最终证据集 $E_t=\tilde{R}_t^{(2)}$。
- **历史记忆锚定**：将问题与其召回证据拼接 $z_t^{(r)}=\text{Concat}(q_r, R_t^{(r)})$（对话轮按检索相似度降序拼接），在上一时刻记忆库 $M_{t-1}$ 中检索 top-$k_h$ 条历史记忆 $H_t^{(r)}$，并合并为 $H_t=\bigcup_{r=1}^{R}H_t^{(r)}$。
- **联合记忆形成与调和**：单次 LLM 调用 $O_t=F_{mem}(E_t,H_t)$ 同时完成事实抽取、会话内去重、指代消解与历史调和；每个操作 $o$ 属于 $\{ADD, UPDATE, DELETE, NOOP\}$（新增/更新或扩充同一事实/删除被明确否证者/无需操作）；每条记忆保留**时间信息与对话来源（provenance）**。最后 $M_t=\text{Apply}(M_{t-1},O_t)$。

**（B）选择性记忆使用（Selective Memory Use）**

- 先用检索到的语义记忆回答：$\tilde{y}_i=F_{ans}(q_i^{usr}, M_i)$。
- 若 $\tilde{y}_i=\text{NONE}$，用 **TF–IDF** 检索源对话：$R_i^{src}=\text{top-}k_s$ 相关轮次，并扩展上下文窗口 $E_i^{src}=R_i^{src}\cup Ctx_w(R_i^{src})$（前后各 $w$ 轮，同一会话内）。
- 最终答案：$\hat{y}_i=\tilde{y}_i$ 若 $\tilde{y}_i\neq\text{NONE}$，否则 $F_{ans}(q_i^{usr},E_i^{src})$。初始记忆式回答阶段**不提供任何原始对话**。

## 3. 实验设计

- **数据集 / Benchmark**：LoCoMo（超长期对话记忆基准），采用与原文可比的设置，使用 **1,540 道非对抗类问题**，覆盖四类：单跳（single-hop）、多跳（multi-hop）、时序（temporal）、开放域（open-domain），**排除 adversarial 类别**。
- **对比方法**：RAG、Mem0、A-MEM、Nemori、D-Mem，覆盖检索式、结构化、自适应与审议式（deliberative）长期记忆系统。
- **评测模型**：Qwen3-235B-A22B 与 GPT-5.6 Sol；同一 backbone 用于记忆构建与答案生成，并同时作为 LLM 评判器；答案与评判 prompt 沿用 D-Mem 与 Nemori 的协议。
- **指标**：LLM-Judge、F1、BLEU-1（越高越好）与推理 token 数（越低越好）。
- **配置**：6 个通用形成问题；每问题检索 top-10 对话轮、top-5 历史记忆；推理时用 OpenAI text-embedding-3-small 检索 top-30 语义记忆；触发回退时 TF–IDF 取 top-20 源对话轮，上下文窗口 15 轮；A-MEM 按官方配置保留 all-MiniLM-L6-v2。
- **消融实验**：
  - 记忆形成策略对比（同一记忆使用流程）：Direct Compression（Mem0 抽取 prompt 压全会话）、Question-Prompted Compression（把 6 个维度作为抽取指令但不做问题级检索）、RIME。
  - 选择性源检索消融（去掉后仅用语义记忆回答），在两种 backbone 上各一组。

## 6. 主要结论与发现

- **质量最优**：RIME 在两个 backbone 上**三项质量指标全部第一**。Qwen3-235B-A22B：Judge 81.82、F1 51.46、BLEU-1 44.22（对比 D-Mem 78.60 / 51.00 / 42.60，Nemori 77.34 / 46.01 / 39.88）；GPT-5.6 Sol：84.29 / 56.41 / 48.85。
- **效率显著更优**：查询时 token 仅 5.11K / 5.21K，远低于 A-MEM（63.19K / 52.14K）、Nemori（20.92K / 17.74K）与 D-Mem（15.57K），说明**选择性访问源对话是昂贵全历史审议的有效替代**。
- **问题引导的形成有效**：仅把 6 个维度加入压缩 prompt（Question-Prompted Compression）相对直接压缩**无一致增益**（Judge 72.66 vs 71.62，但 F1/BLEU-1 反而略降），而 RIME 用问题做检索线索则三项指标全面提升（81.82 / 51.46 / 44.22）——关键在"先检索再整合"，而非"把维度写进指令"。
- **选择性源检索不可或缺**：去掉后 Judge 在 Qwen 上下降 10.59 分、GPT-5.6 上下降 3.32 分；Qwen 触发回退更频繁（16.8% vs 6.0%），与其更大的性能跌幅一致。

## 7. 优点

- **切入视角新颖**：将检索前移到**写入阶段**（retrieval-induced memory formation），把"问题"用作检索线索而非摘要指令，直击一次性压缩丢失局部细节的痛点。
- **机制设计完整**：形成阶段包含问题召回→两轮局部上下文扩展→历史记忆锚定→单次 LLM 调用完成抽取/去重/指代消解/调和，并通过 ADD/UPDATE/DELETE/NOOP 形成**带时间与来源信息**的演化记忆库，可追溯、可演化。
- **两级证据策略优雅**：压缩记忆为"主"、源对话为"备"，用 NONE 判定作为触发条件，避免了全历史处理，兼顾质量与成本，token 效率提升非常可观。
- **消融设计有针对性**：特别设置 Question-Prompted Compression 这一"伪基线"，有效区分了"提示中加维度"与"检索式召回"两种机制，论证说服力较强。
- **跨模型验证**：在两个不同能力层级的 backbone 上结论一致，且触发率差异与性能差异相互印证，逻辑自洽。

## 8. 不足与局限

- **实验覆盖有限**：仅 LoCoMo 一个数据集、仅 1,540 题、排除 adversarial 类别；未验证多会话智能体执行类任务（如工具调用、规划）或真实产品场景。
- **基线可比性存疑**：D-Mem 未在本文环境下复现且 backbone 不同；A-MEM 嵌入模型不一致；缺少统一复现的公平对照。
- **超参数与鲁棒性未探索**：问题数、$k_f$、$k_h$、上下文窗口 $w$、top-30 记忆等关键参数均未做敏感性分析；TF–IDF 用于源对话检索可能在语义改写、跨语言或口语化表达下较为脆弱。
- **成本核算不完整**：只报告查询时 token，未给出记忆构建阶段的开销与总成本，也未说明形成阶段 LLM 调用次数随会话增长的变化，长期运行成本不明。
- **统计严谨性不足**：无多次运行方差、无显著性检验、无误差棒，单点结果的稳定性未知。
- **评估偏置风险**：用与生成模型相同的 backbone 作为 LLM-Judge，可能高估自身方法；三个指标中两个（F1、BLEU-1）为词面重叠指标，对语义等价的表述不友好。
