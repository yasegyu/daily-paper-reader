## 摘要
长时程任务要求 LLM 智能体持续利用先前交互中的信息。然而，保留完整历史会增加上下文成本，而压缩历史又可能丢失后续所需的细节，并且历史信息的相关性往往随着任务推进才逐渐显现。为应对这些挑战，我们提出 FlowState，它将执行状态视为可在不同请求之间保留和重访的记忆，从而统一当前决策与历史信息复用。FlowState 保留语义类型化的状态节点、其关系以及对原始工具观测的引用，将持久保留与按需访问分离。在单次执行循环中，增量状态更新（ISU）基于新输入和反馈维护当前状态，而渐进式状态访问（PSA）则在推理过程中按需逐步揭示历史状态及支持证据。这些机制共同使智能体能够根据新信息重新评估先前的决策，并指导后续行动。与使用相同 DeepSeek-V4-Flash 模型的全上下文基线相比，FlowState 在 MemoryArena 上的平均成功率以及在 $τ^3$-Bench 上的平均通过率分别提升了 4.55 和 13.95 个百分点，同时将总 token 消耗分别降低了 43.2% 和 40.6%。这些结果证明了 FlowState 在长时程任务上的性能与效率优势。

## Abstract
Long-horizon tasks require LLM agents to continually draw on information from earlier interactions. However, retaining the full history increases context costs, while compressing it risks losing details needed later, and the relevance of historical information often becomes apparent as the task progresses. To address these challenges, we propose FlowState, which treats execution state as memory that can be retained and revisited across requests, unifying current decision-making with the reuse of historical information. FlowState preserves semantically typed state nodes, their relations, and references to raw tool observations, separating persistent retention from on-demand access. Within a single execution loop, Incremental State Update (ISU) maintains the current state based on new inputs and feedback, while Progressive State Access (PSA) progressively reveals historical states and supporting evidence as needed during reasoning. Together, these mechanisms enable agents to reassess prior decisions in light of new information and guide subsequent actions. Compared with a full-context baseline using the same DeepSeek-V4-Flash model, FlowState improves the average success rate on MemoryArena and the average pass rate on $τ^3$-Bench by 4.55 and 13.95 percentage points, respectively, while reducing total token consumption by 43.2% and 40.6%. These results demonstrate the performance and efficiency advantages of FlowState on long-horizon tasks.

# FlowState 论文中文总结

## 1. 核心问题与研究动机

- **背景**：长时程任务（旅行规划、数学推导、多轮服务交互等）要求 LLM 智能体持续追踪执行进度，并反复调用早期交互中获得的约束、观测与中间结果；这些依赖往往跨子任务、跨请求持续存在。
- **现有方案的困境**：
  - **全上下文（Full Context）**：保留完整交互历史会推高上下文成本，且关键细节容易被长上下文淹没（如示例中取消政策 E4 被忽略）。
  - **历史压缩（如 ZipAct）**：反复压缩可能丢弃后续才需要的细节（E4 在压缩中丢失）。
  - **外部长期记忆 / RAG**：信息虽被存储，但"何时检索、检索什么"往往要到推理过程中才显现，相关证据可能根本没被检索到（E4 未被召回）。
- **关键洞察**：历史信息的相关性具有**滞后显现性**——新反馈或约束变化会让早期信息重新变得重要，而检索到的记录本身还可能需进一步追溯其关联状态或原始证据。
- **核心研究问题**：**执行状态本身能否作为统一表示，把当前决策与长期记忆连接起来？** 作者主张将执行状态既作为工作表示、又作为可复用的记忆单元，跨请求保留并按需重访，从而避免反复处理完整历史。

## 2. 方法论

### 2.1 核心思想：持久执行状态
FlowState 将用户需求、环境信息、智能体判断与执行产物表示为**语义类型化的状态节点**，保留节点间关系及对原始工具观测的引用，并把"持久保留"与"上下文可见性"分离：

- **Persistent State Repository（M_k）**：运行时维护的持久状态仓库，存储先前请求、状态节点及关系；每个节点记录来源请求、语义标识符、类别与完整内容；被新状态引用的原始工具结果也作为可访问节点保留。**不直接进入模型上下文**。
- **Historical State Index（G_k）**：请求 q_k 开始时构建的轻量索引，覆盖 q_1…q_{k−1}，每个状态条目只含语义标识符与简要摘要，**放入模型上下文**。
- **Active State（S_{k,t}）**：当前请求第 t 步可用的活跃状态，含当前请求新建状态 + 已披露的历史状态及其关系；未披露历史状态的完整内容被排除。

**五类状态分类（按来源与角色）**：
- 用户侧：`preferences`（偏好、约束、需求）
- 环境侧：`knowledge`（工具观测）、`attributes`（从观测中提炼的实体属性）
- 智能体侧：`judgements`（目标、计划、决策、风险评估）、`artifacts`（可复用产物、代码、工具）

### 2.2 两种互补的状态操作

**（1）增量状态更新 ISU**
- 模型基于当前上下文 C_{k,t} 产生候选状态增量 ΔS_{k,t}，含 **Add / Update / Remove** 三种操作。
- Add 创建当前请求状态；Update 与 Remove **只能作用于当前请求内创建的状态**（历史状态不可改，只能新建并链接）。
- 先经执行规则 P 校验，再提交：`Δ̂S_{k,t} = Validate_upd(ΔS_{k,t} | P, S_{k,t})`，`S⁺_{k,t} = Commit(S_{k,t}, Δ̂S_{k,t})`。
- 模型无需每步重生成整个状态，例如价格观测只更新住宿选择判断，不变的预算偏好保持原样。

**（2）渐进状态访问 PSA**
- 模型利用 G_k 中的标识符与摘要、以及 S_{k,t} 中已披露的关系，指定要访问的历史状态集合 R_{k,t}（不需要时为空集）。
- 校验后披露：`R̂_{k,t} = Validate_acc(R_{k,t} | P, G_k, S_{k,t})`，`S_{k,t+1} = S⁺_{k,t} ∪ Disclose(M_k, S_{k,t}, R̂_{k,t})`。
- 关系边只给出**类型 + 目标节点标识符**，**不揭示目标节点完整内容**，模型可在后续步骤决定是否继续访问，从而沿"关系链"逐步追踪到原始证据。
- 关系类型固定为四种有向边：`supports`、`derives`、`follows`、`supersedes`。

### 2.3 状态驱动执行循环（Algorithm 1）
- 每步输入序列化：`C_{k,t} = Serialize(q_k, O_{k,t}, G_k, S_{k,t})`。
- 模型单次输出三元组 `y_{k,t} = (ΔS_{k,t}, R_{k,t}, z_{k,t})`，分别对应状态增量、历史访问请求、执行决策；三者各自可为空，但**不可同时为空**。
- ISU 与 PSA 的效果合并得到 S_{k,t+1}；执行决策 z_{k,t} 决定执行环境动作、终止请求或继续下一步。
- **重要时序约束**：PSA 在第 t 步披露的信息只能从**下一次模型调用**开始使用；若动作依赖该信息，模型可令 z_{k,t} = ∅ 推迟决策。
- 请求结束时持久化：`M_{k+1} = Persist(M_k, q_k, S_{k,T_k+1}, O_k)`，`G_{k+1} = Index(M_{k+1})`；新状态记录来源请求 q_k，历史状态保留原始来源且**不可删除**。

## 6. 主要结论与发现

- **MemoryArena**：FlowState 在 9 项性能指标中 8 项领先。Shopping PS 42.89%（超最强记忆基线 11.78 pp）；Travel PS 12.57%（超最佳基线 5.61 pp）；Math 最佳 PS（55.53）与 SR（37.5）；Physics 最佳 SR（60.0）与 PS（73.96）。相对同基座 Full Context 平均成功率 +4.55 pp，token 消耗 −43.2%。
- **τ³-Bench**：Airline Pass Rate +20.0 pp、DB Accuracy +7.5 pp、token −61.2%；Retail Pass Rate +7.9 pp、DB Accuracy +5.3 pp、token −22.2%（Action Accuracy −4.9 pp）。平均通过率 +13.95 pp，token −40.6%。
- **直接拼接状态追踪与检索无效**：ZipAct+BM25 仅在 Math PS 上优于单一组件，而 FlowState 在全部 9 项指标上超过 ZipAct+BM25，说明"执行状态作为可重访记忆"的整合设计优于简单组合。
- **跨基座泛化**：在 Qwen3.5-397B-A17B、DeepSeek-V4-Flash、GPT-5.6-terra 上均提升 SR/PS，平均相对 token 降低 28.3%–56.3%；9 个模型–任务组合中 8 个提升 SR、1 个持平。
- **消融结论**：去掉 ISU 后两个环境 SR 均降为 0，说明执行中构建与更新状态比边界规则生成状态更关键；去掉 PSA（全量暴露历史）token 更高且 Travel 上所有性能指标下降，说明按需渐进披露在性能与效率之间取得更好平衡。
- **长时程保持**：在子

子任务深度分析（Web Shopping、Travel Planning、Formal Reasoning 三个领域）中，论文以归一化曲线面积 nAUC 与衰减率 DR 刻画"随子任务链变长性能如何变化"：FlowState 的 nAUC 更高、DR 更低，即随着子任务深度增加，其性能下降比各基线更平缓，说明持久执行状态确实缓解了长时程任务中的"信息漂移/遗忘"问题。这一结论与主实验中 token 显著下降但性能不降反升的结果相互印证——收益并非来自"喂入更多上下文"，而是来自"更精准地复用已有执行状态"。

- **机制互补性**：ISU 与 PSA 缺一不可且分工明确。ISU 负责"把执行过程沉淀为可复用结构"，PSA 负责"在需要时把正确的历史结构重新拉回工作上下文"。消融显示两者分别对应"有没有可复用的状态"和"能不能在正确时机取到它"两个独立失效点。

## 8. 对后续研究的启示

- **"状态"作为一等公民**：将执行状态同时视为工作表示与记忆单元，把"持久保留"与"上下文可见性"解耦，是区别于"压缩历史"和"外部检索"的第三条路线，对长时程智能体设计具有方法论价值。
- **关系边作为渐进式检索的骨架**：只暴露"关系类型 + 目标标识符"、按需逐步披露完整内容，为在有限上下文预算下进行可解释的多跳追溯提供了可借鉴的接口设计。
- **可组合的模块化思路**：ISU/PSA 与基座模型解耦，实验中跨三个基座均有效，暗示该框架可作为通用推理期插件接入不同模型。
- **待补的研究方向**：引入重复实验与显著性检验；开展组件级消融；量化延迟与调用轮次成本；研究状态仓库的压缩/归档与冲突消解；在更长的请求序列上验证状态规模的扩展性。

## 9. 总体评价

FlowState 针对长时程 LLM 智能体的一个真实且被现有方案反复暴露的痛点——"早期信息的相关性滞后显现，而全上下文、压缩、外部记忆都无法可靠地在正确时机把它带回来"——提出了简洁且有解释力的方案：把执行状态持久化并按需渐进披露。其核心贡献在于概念层面的重构（状态 = 记忆单元；持久保留 ≠ 上下文可见）与一套可落地的双操作机制（ISU + PSA）。实验上，它在 6 个环境、9 项指标中的多数取得领先，并在平均成功率提升约 4.6–14 pp 的同时将 token 消耗降低约 22%–61%，"更好且更省"的组合是其最有力的证据；ZipAct+BM25 的失败对照也支持"整合设计优于简单拼接"这一论断。但受限于单点结果、缺乏显著性检验、消融范围窄、部分环境绝对性能极低以及完全缺失算力与延迟报告，其收益的稳健性与工程可用性仍有待独立复现与更严格的实证检验。总体而言，这是一篇在问题选择与框架设计上具有较高参考价值、但在实证严谨性与成本透明度上留有明显改进空间的工作。
