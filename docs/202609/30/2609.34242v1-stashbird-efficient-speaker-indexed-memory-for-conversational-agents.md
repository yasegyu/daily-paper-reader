## 摘要
AI 智能体需要一种记忆，能够在用户-智能体交互、用户-用户对话，以及有或没有智能体参与的群组对话中保存信息，同时支持在证据发生变化或被删除时进行更新。我们提出 Stashbird，一种智能体记忆系统，它通过显式的溯源信息将源情节与派生记忆状态关联起来。Stashbird 将记忆组织为情节记录、语义关系、社区摘要和持久化图状态，并提供用于增量更新和情节级删除的生命周期操作。我们在四个长期记忆基准上评估问答准确率和面向模型的工作负载。在 LoCoMo 上，Stashbird 使用的摄入提示词 token 比 Graphiti 少 76.4 倍。在同一基准上，与复现的 Hindsight 相比，它使用的检索提示词 token 少 8.1 倍，准确率低 1.6 个百分点。在 LongMemEval-S 和 GroupMemBench 上，它比 Hindsight 取得更高的准确率，在 EverMemBench 上则准确率相当。

## Abstract
AI agents require memory that preserves information across user-agent exchanges, user-to-user conversations, and group conversations with or without agent participation, while supporting updates as evidence changes or is removed. We present Stashbird, an agent memory system that links source episodes to derived memory state through explicit provenance. Stashbird organizes memory into episodic records, semantic relations, community summaries, and persisted graph state, with lifecycle operations for incremental updates and episode-level deletion. We evaluate question-answering accuracy and model-facing workload across four long-term memory benchmarks. On LoCoMo, Stashbird uses 76.4x fewer ingestion prompt tokens than Graphiti. Compared with reproduced Hindsight on the same benchmark, it uses 8.1x fewer retrieval prompt tokens, with accuracy 1.6 percentage points lower. It achieves higher accuracy than Hindsight on LongMemEval-S and GroupMemBench and comparable accuracy on EverMemBench.

- **核心痛点**：这些系统在答案质量与构建/查询记忆所需的模型调用和 token 开销之间难以平衡；同时，记忆的**溯源（provenance）**——即源情节与派生记忆状态之间的链接——以及情节新增/删除时的**一致性调和（reconciliation）**，尚未得到充分解决。
- **论文定位**：提出 Stashbird，一种**以情节为锚（episode-grounded）**的智能体记忆系统，通过显式溯源将原始对话证据与派生语义状态绑定，支持增量更新、情节级删除和混合检索，并在多个长期记忆基准上评估问答准确率与面向模型的工作负载。

## 2. 方法论

### 2.1 核心思想
- 记忆被组织为多个**相互链接的视图**：情节记录（episodes）、实体（entities）、关系（relations）、偏好痕迹（preferences）、社区摘要（communities）以及持久化图状态。
- 与只存检索片段或抽取记忆项的系统不同，Stashbird 保留原始对话证据与派生语义状态之间的溯源链接，使记忆可被继承、修订、删除和查询。
- 检索时结合词汇-向量混合搜索、查询分解、融合与重排序。

### 2.2 关键技术细节

**（1）摄入与更新（Ingestion and Update）**
- 对话被切分为有序、带时间戳的情节序列 $E=\{e_1,\dots,e_T\}$，每个情节存储说话人、内容、消息时间、摄入时间。
- 为避免重复调用全历史 LLM：
  - 以 **15K token 窗口**构建全局摘要；
  - 以 **20K token 块、10% 重叠**处理情节；
  - 先用 NER 模型减少遗漏提及，再由骨干 LLM 从块文本、全局摘要和**滚动实体中心上下文**中抽取实体与关系。
- 滚动上下文上限 **4K token**，超限时压缩；仍过大则按支持度删除最弱实体。
- **实体调和**：当余弦相似度与 Levenshtein 比率**均 > 0.85** 时接受匹配；任一指标 > 0.75 的候选交由骨干 LLM 裁决。阈值在所有基准上固定。
- **关系调和**：在同一实体对内，重复关系扩展溯源，矛盾关系替换旧关系。
- **社区摘要**：启用时用标签传播算法对实体图聚类，每个簇生成社区节点并链接成员。
- **增量更新**：持久化检查点保存对话摘要、序列化滚动上下文、最后处理情节和当前实体数；更新时恢复检查点、追加新情节、复用已有实体与关系，新实体归入已有社区。

**（2）删除（Deletion）**
- 删除以**情节级**进行，输入情节标识 $d$ 与记忆状态 $M$，通过溯源集合 $P(x)$ 识别受影响实体、关系和社区。
- 算法流程（Algorithm 1）：
  - 对每个受影响关系 $r$：$P(r) \leftarrow P(r)\setminus\{d\}$；无剩余支持则从图与索引移除，否则仅更新溯源。
  - 对每个受影响实体 $e$：$P(e) \leftarrow P(e)\setminus\{d\}$；有剩余支持则仅更新溯源；无支持且无存活邻居则删除；无支持但有存活邻居则**清除情节派生元数据、保留为连接锚点**（Entity Meta-forgetting with Neighbor Adoption），并移除其过期搜索文档。
  - 移除情节本身，重连其前驱与后继；将受影响社区标记为 dirty，延迟重新摘要，并移除其过期社区文档。

**（3）检索（Retrieval）**
- 保留原始查询 $q_0$，由骨干 LLM 生成最多 4 个聚焦子查询 $Q=\{q_0,\dots,q_k\}$。
- 每个查询变体嵌入；若问题日期可用，则解析相对时间表达。
- 对话范围的混合搜索检索情节、实体、关系文档（启用时含社区文档）。
- 跨查询结果合并去重，使用**倒数排名融合（RRF，k=60）**融合不同来源证据。
- LLM 相关性打分器对融合候选评分，取 Top-K 形成最终证据集。
- 最终上下文与问题日期一并交给骨干模型，要求**仅基于检索证据作答**。

### 2.3 默认实现配置
- 文本嵌入：`text-embedding-3-large`，3072 维。
- 每类文档混合检索 Top-60，RRF k=60，重排候选 30，最终证据数 30。
- 实验中**禁用**：专用偏好检索、图扩展、二次覆盖扩展、可信度加权、反思。

## 6. 主要结论与发现

- **LongMemEval-S**：Stashbird 在 GPT-4o-mini 下 75.6%、GPT-4.1-mini 下 81.0%，均高于 Hindsight（74.8%、78.3%）；单会话偏好题差距最大（74.6%/88.4% vs. 53.7%/55.3%），且运行间方差更小。
- **LoCoMo**：GPT-4o-mini 下 80.4%，GPT-4.1-mini 下 87.5%，低于 Hindsight（85.9%/89.1%），但效率优势显著。
- **EverMemBench**：55.4%，与 Hindsight（54.8%）相当；在单跳回忆、约束意识、画像理解上更强，在多跳、时间回忆、主动性、知识更新上更弱。
- **GroupMemBench**：51.1% vs. Hindsight 24.9%，最大优势在时间推理（72.3% vs. 2.2%）和用户隐式问题（60.8% vs. 22.8%）。
- **效率**：
  - LoCoMo 摄入提示词 token 比 Graphiti 少 **76.4×**；
  - LoCoMo 检索提示词 token 比 Hindsight 少 **8.1×**，准确率仅低 1.6 个百分点；
  - LongMemEval-S 摄入 LLM 调用 29K vs. Hindsight 137K、Graphiti 1.28M；
  - Stashbird 以**更多检索调用换取大幅更少的提示词 token**。
- **骨干与 Top-K**：更强骨干在 LoCoMo 上持续提升（87.5% → 89.9% → 92.0%）；EverMemBench 对骨干不敏感（55.4% → 56.4% → 55.9%），提示其更受检索瓶颈限制。Top-K 在 10–50 间性能稳定，K=30 最佳。
- **总体判断**：Stashbird 在结构化、可追溯的对话记忆上实现了较强的**质量-成本权衡**。

## 7. 优点

- **溯源驱动的记忆设计**：显式链接源情节与派生记录，使记忆可继承、可修订、可删除，这是与多数现有系统的关键差异。
- **完整的情节级删除算法**：提出 Entity Meta-forgetting with Neighbor Adoption，保留无支持但有邻居的实体作为连接锚点，避免图结构断裂，并处理社区失效与索引清理。
- **高效的摄入流程**：通过分层摘要 + 20K 分块 + 10% 重叠 + 滚动实体上下文 + 固定阈值实体调和，显著降低 LLM 调用与 token。
- **说话人与时间保留**：在群组/多方对话的时间推理与用户隐式问题上优势明显，契合标题中“Speaker-Indexed”的定位。
- **评测覆盖较广**：跨用户-助手、双人、群组三类场景，四种基准，多骨干，多 Top-K，报告 5

次运行的均值与 95% 置信区间，结果可复现性说明较完整。

- **区分复现与引用**：明确标注哪些基线由本文统一框架复现、哪些沿用先前报告数字，避免将异构结果直接混为一谈。
- **成本可核算**：将 LLM 调用数、嵌入调用数、提示词与补全 token 分阶段（摄入/检索）报告，使质量-成本权衡可被第三方按自身定价重新估算。
- **说话人索引与时间解析**：情节存储保留说话人、消息时间与摄入时间，检索端解析相对时间表达，是群组场景优势的直接来源。

  - 溯源链接在长期运行中的存储开销是否随情节数线性增长，有无压缩或归档策略？
  - "无支持但有存活邻居"的实体保留为锚点后，其残留元数据是否会被后续检索误当作有效证据？
  - 社区摘要的 dirty 标记与延迟重摘要，在删除密集场景下是否会造成摘要长期滞后？
  - 若将禁用功能全部启用，准确率提升是否值得相应的 token 代价？

## 10. 总体评价

Stashbird 的贡献重心不在刷新单点准确率，而在于提出一条**可溯源、可删除、情节锚定**的记忆组织范式，并以工程化手段把摄入与检索的模型开销压到较低水平：LoCoMo 摄入提示词 token 比 Graphiti 少 76.4×、检索比 Hindsight 少 8.1× 而准确率仅差 1.6 个百分点，是其最具说服力的结果。它在群组与时间敏感场景上的大幅领先（GroupMemBench 51.1% vs. 24.9%）也印证了"说话人索引 + 时间解析 + 情节溯源"的设计取向确有实效。

但论文目前处于"设计完备、验证偏窄"的状态：最核心的溯源与删除机制没有独立实验支撑，关键阈值未做敏感性扫描，部分能力在评测中被关闭。若后续补齐组件消融、删除一致性实验与阈值扫描，Stashbird 有望从"一个有前景的系统设计"升级为"有实证支撑的记忆架构"。
