## 摘要
面向多模态智能体的记忆研究优化的是写入、更新和检索的内容。然而，在检索与答案之间还存在一个多模态记忆评测未能单独隔离的阶段：检索到的记忆中究竟有哪些、以何种形式到达模型。我们将其称为送达（delivery），而在 MemLens 上进行的一项受控分解表明，剩余提升空间正位于此。在检索到的证据集完全固定的情况下，与不提供这些证据相比，直接送达原始像素在 8B 骨干模型上将准确率提升 13.87 个百分点；而将同一批消息上的检索做到完美，仅带来 2.31 个百分点的提升。在三个 MemLens 骨干模型上，送达都是更大的增益项，并随骨干模型能力增强而增大；检索带来的增益同样增长，但并未弥合这一差距。我们提出 DeliverMem，将送达具体化为三项决策：保留原始模态、为每个条目赋予可读标识，并说明其被看到的时间；同时针对送达无法提供的一项属性，引入检索侧适配器。每一项决策都对照一个仅在自身变量上有所不同的送达匹配控制组进行评估。在 MemLens 的全部四种上下文长度下，DeliverMem 均领先于已发表的最强记忆智能体，并在两个骨干模型的所有设置上均优于 DMV-Bench 自身的最强方法。在 MemLens 上，它仅以十分之一到七十分之一的输入量实现了这一点。每一项决策仅在问题缺少其所提供的信息时带来帮助，在其他情况下则无效果。尽管如此，单一固定配置即可在两个基准上均取得领先，且无需训练任何组件或修改已存储的记录。项目页面：https://avalon-s.github.io/DeliverMem/

## Abstract
Work on memory for multimodal agents optimizes what is written, updated and retrieved. Between retrieval and the answer, however, is a stage that multimodal memory evaluations do not isolate: what of the retrieved memory reaches the model, and in what form. We call it delivery, and a controlled decomposition on MemLens locates the remaining room there. With the retrieved evidence set exactly fixed, delivering the original pixels instead of withholding them raises accuracy by 13.87 points on an 8B backbone, whereas making retrieval perfect on those same messages improves it by 2.31. Delivery is the larger term on all three MemLens backbones and grows with backbone strength; retrieval grows too, without closing the gap. We propose DeliverMem, an instantiation of delivery as three decisions: keep the original modality, give each item a readable identity, and state when it was seen, with a retrieval-side adapter for the one property delivery cannot supply. Each is measured against a delivery-matched control that alters only its own variable. DeliverMem leads the strongest published memory agent on MemLens at all four context lengths, and beats DMV-Bench's own strongest method at every setting on both backbones. On MemLens it does this on a tenth to a seventieth of the input. Each decision helps only where the question lacks what it supplies, and is null elsewhere. A single fixed configuration nonetheless leads both benchmarks, without training any component or modifying the stored records. Project page: https://avalon-s.github.io/DeliverMem/

# 《Retrieved but Not Delivered: Multimodal Memory Delivery for Long-Term Agents》论文总结

## 1. 核心问题与整体含义

- **研究动机**：多模态智能体的记忆研究长期聚焦于三个环节——写什么、如何更新、如何检索（S 与 R）。但在"检索"与"回答"之间还存在一个被评测忽略的阶段：检索到的记忆中，究竟**哪些内容、以何种形式**真正进入模型。
- **核心问题**：作者将这一阶段命名为 **delivery（送达）**，并将其形式化为 $a = M(q, D(R(q, S)))$，其中 D 决定把检索到的记录转换为提示词中的 token 与像素。
- **直觉示例**：用户发了一张柑橘腌三文鱼的照片并提问"小块三文鱼在主鱼片哪一侧"。检索器已正确找到该消息：
  - 不送达像素（文本式记忆）→ 模型答"在主鱼片上方"（自信的错误）；
  - 送达原始像素 → 答"在主鱼片右侧"（正确）。
- **整体含义**：送达不是简单的"格式化"，而是决定答案正确与否的独立变量；在 MemLens 上，其剩余提升空间显著大于检索本身。

## 2. 方法论

- **核心思想**：把送达显式拆成三项决策，全部只作用于"出站"的已送达上下文，**不训练任何组件、不修改存储记录**，可对任何保留原始媒体与时序的栈进行改造。
- **三项送达决策**：
  - **(D1) 原始模态保留**：检索到的条目连同其像素一并送达，而非文本代理（caption）。这是三文鱼问题中两种答案的唯一差别。
  - **(D2) 可寻址性**：每张送达的图像在左上角像素内渲染一个短可读标签（M1, M2, …），仿照 Set-of-Mark；提示词以标签而非序号引用条目。标签在嵌入之后写入，不触发重嵌入，也不影响检索排序。
  - **(D3) 时间位置**：每条送达条目标注其在记忆库中的位置，采用存储提供的最细时间索引——MemLens 记录时间戳（用日期），DMV-Bench 无时间戳（用追加序号 `[seen #k of N]`）。
- **检索侧适配器 (R1)**：区域多向量检索。每张图像编码为整图加 2×2 重叠网格，用 SigLIP 2 特征做区域 MaxSim 评分，针对仅占据画面小区域的证据。
- **配置选择**：两基准共用一套固定配置；另有一个基于 dev 划分的按题型选择规则（3 分阈值），但主结果不使用它。
- **对照原则**：每个决策都对照一个**送达匹配控制组**（仅改变该决策自身的变量），而非笼统的消融。

## 3. 实验设计

- **基准（Benchmark）**：
  - **MemLens**：长上下文多模态对话记忆基准，四种上下文长度（32K/64K/128K/256K），195 题规范子集，五类问题（信息抽取、知识更新、时序推理、多会话推理、拒答），使用基准自带的 235B 裁判（Qwen3-VL-235B-A22B）。
  - **DMV-Bench**：图像级视觉回忆交互基准，智能体浏览模拟店铺 J 个会话，需返回携带特定线索图像的商品页，精确评分（无裁判）。
- **骨干模型**：MemLens 用 Qwen3-VL-8B、Qwen3-VL-30B-A3B、Qwen3-VL-32B；DMV-Bench 用 Qwen2.5-VL-7B 与 Gemini 2.5 Flash。
- **对比方法**：
  - MemLens：7 个已发表记忆智能体（M2A、M3C、M3-Agent、Memory-T1、MemOS、Mem0、MemAgent-7B）、直接读全上下文的 LVLM 池（Qwen3.5-122B、Qwen3-VL-30B-A3B、Gemini-3.1-Pro、GPT-5.4、Qwen3-VL-8B/2B）。
  - DMV-Bench：基准自带池（NoMemory、TextOnly、Caption、WorldMM-lite、MMA-lite、M2A-lite、DualMem）。
- **检索器**：文本通道 bge-small-en-v1.5，图像通道 siglip2-base-patch16-384；DMV-Bench 沿用 DualMem 的 all-MiniLM-L6-v2 caption 通道。

## 4. 资源与算力

- **GPU**：单张 32 GB GPU，Python 3.10，PyTorch 2.11，Transformers 5.15。
- **部署方式**：Qwen3-VL-8B（MemLens）与 Qwen2.5-VL-7B（DMV-Bench）本地部署于 OpenAI 兼容端点之后；Gemini 2.5 Flash、两个更大骨干模型及 MemLens 裁判通过托管 API 调用。
- **索引开销**：图像编码为 5 个向量（整图 + 2×2 网格），编码成本约为整图编码的 1.9×（DMV-Bench）至 3.5×（MemLens）；128K 索引约 63–72 MB，构建 < 3 分钟，每查询评分约 2 ms。
- **训练时长**：论文未报告训练时长，因为**方法本身不含任何训练**。
- **未说明项**：论文未披露总 GPU 小时数或 API 调用总量。

## 5. 实验数量与充分性

- **实验规模**：
  - MemLens 四个上下文长度 × 多个骨干模型；
  - DMV-Bench 两个骨干 × J=5/10/15/50（含 exhaustive 与 Monte-Carlo 两种探针构造）；
  - 反事实图像阶梯（5 个条件，同批次配对）；
  - (D2) 的 2×2 身份通道实验（1,888 共享探针，J=10 与 J=5 两个工作点）；
  - 各组件对照实验（绑定、日期置换、标签乱序、常量标签、文本标签等）；
  - K 值扫描（K=3/5/10/20）、按题型拆分、按 gold 数量拆分、输入成本对比、失败审计等。
- **统计方法**：MemLens 用精确双侧符号检验（配对）；DMV-Bench 用精确聚类置换检验（链为独立单位），并给出种子方差分解。
- **充分性与公平性**：
  - 所有对比均为**配对**，共享模型、提示模板、裁判；
  - 采用送达匹配控制，排除"呈现混淆"；
  - 2×2 设计把编码器置于设计内部，避免检索/送达混淆；
  - 已发表数字标注为转述，配对检验使用同批次复现的 DualMem 运行。
  - 总体而言实验覆盖广、控制严格、统计规范，客观性较强。

## 6. 主要结论与发现

- **送达 > 检索（MemLens）**：固定检索集时，送达像素比不送达在 8B 上 +13.87；检索做到完美仅 +2.31。在三个骨干上送达均更大，并随骨干增强而增大（+13.87 → +15.61 → +17.92）；检索也从 +2.31 增至 +9.83/+11.56，比例由 6.00× 收窄至 1.55×。
- **送达依赖内容而非 token 数量**：真实但错误的照片对比无照片为 +0.00；正确图像的统计量（相位随机化、物体全毁）仅 +3.47；内容特定的送达价值为 +11.56。
- **效果高度集中**：信息抽取题上送达正确像素 +40.98，其余三类最多 +2.86。
- **系统级领先**：
  - MemLens 四种长度全部领先最强已发表智能体（32K：51.28 vs 32.82，+18.46），输入仅为全上下文的 1/10 至 1/70；
  - 32K 下以十分之一输入追平 GPT-5.4；
  - DMV-Bench 两骨干所有设置全部领先 DualMem（+7.0 至 +23.5）。
- **组件生效规则**：一个送达决策只有在（i）信息在存储后存活并到达模型、（ii）问题需要该属性、（iii）送达上下文尚未携带该属性时才有效，否则为 null。
- **组件跨基准不通用**：(D2) 在 DMV-Bench 有效（+3.96）、MemLens null；(D3) 在 MemLens 时序题有效（+8.76）、DMV-Bench null；(R1) 在 DMV-Bench 有效（+8.83）、MemLens null。
- **绑定（binding）**：置换图像与消息的对应关系使准确率下降 6.36，说明配对本身有意义，但该决策未部署进接口。
- **失败审计**：DMV-Bench 上 98% 的失败是"正确项在上下文中却被选错"，而非检索失败；失败集中在首位项。

## 7. 优点

- **概念清晰**：把"检索"与"送达"严格分离，并用受控分解量化各自剩余空间，填补了评测空白。
- **控制严谨**：每个组件均配送达匹配对照（只改一个变量），并识别出"呈现混淆"这一常见陷阱。
- **零训练、零改写存储**：方法即插即用，可回接到任意保留原始媒体与时序的栈。
- **单一配置跨基准领先**：不依赖按题型选择，泛化性好。
- **效率突出**：以 1/10–1/70 的输入取得领先或持平，成本–精度曲线友好。
- **统计规范**：配对检验、聚类置换、方差分解、失败案例逐条引用，可复现性强。
- **诚实报告**：明确标注 null 结果、未达显著性的对比，以及组件跨基准不迁移的事实。

## 8. 不足与局限

- **送达粒度未测量**：是送裁剪区域、整帧还是两者兼送，这一自由度未被研究，需带区域标注的基准。
- **按题型效应基于全量 789 题**：因 195 题评估子集中知识更新仅 29 题，统计粒度受限。
- **仅限图像模态**：音频/视频会带来新决策（如"事件内何处"、时长粒度选择），论文未覆盖。
- **跨基准不迁移**：组件效果依赖基准与骨干特性（如 Gemini 上送达 null），说明方法并非普适。
- **部分对比未达显著**：n=173 时，更大骨干上送达与检索差距符号一致但 p=0.18/0.14。
- **绑定未部署**：+6.36 的绑定效应被明确排除在接口之外。
- **隐私影响**：送达原始像素意味着更多原始图像进入模型，对个人媒体场景需单独决定保留与再展示策略。
- **输入成本只计到达模型的部分**：离线索引成本（每存储项一次）被单列，但未纳入总体成本模型。
- **边界条件**：(R1) 仅在证据占据小区域（DMV-Bench 中位 1.7% 画面）时有效，对 MemLens 这类无明确相关区域的图像无效。
