## 摘要
语言代理在交互环境中仍然脆弱，成功需要长程状态跟踪、有效动作执行以及从失败步骤中恢复。我们扩展了SwiftSage——一种结合快速动作提议者与较慢规划者的双过程代理，使用两个模块化认知扩展：自适应记忆模块（AMM）用于显著性门控的情景存储和触发驱动的检索，以及自我反思模块（SRM）用于受限执行时间验证和纠正干预。两个模块均作为相同执行基底上的功能标记扩展实现，从而能够在ScienceWorld上进行受控消融。在四种配置——基线、基线+AMM、基线+SRM和完整系统——中，完整系统实现了最佳平均最终分数（64.62）、成功率（43.17%）和成功步骤效率（19.33步），而SRM是最强的独立贡献者。结果表明，执行时间控制是该场景中的主要瓶颈，而一旦运行时循环稳定，情景记忆才变得最为有用。

## Abstract
Language agents remain brittle in interactive environments, where success requires long-horizon state tracking, valid action execution, and recovery from failed steps. We extend SwiftSage, a dual-process agent that combines a fast action proposer with a slower planner, using two modular cognitive extensions: an Adaptive Memory Module (AMM) for salience-gated episodic storage and trigger-driven retrieval, and a Self-Reflection Module (SRM) for bounded execution-time validation and corrective intervention. Both modules are implemented as feature-flagged extensions over the same execution substrate, enabling controlled ablations on ScienceWorld. Across four configurations---baseline, baseline+AMM, baseline+SRM, and the full system---the full system achieves the best mean final score (64.62), success rate (43.17%), and successful-step efficiency (19.33 steps), while SRM is the strongest standalone contributor. The results suggest that execution-time control is the dominant bottleneck in this setting, while episodic memory becomes most useful once the runtime loop is stabilized.

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：大规模语言模型（LLM）具备流畅文本生成和短程推理能力，但这些能力并不能自动转化为可靠的智能体行为。在交互式环境中，代理需要持续维护状态、选择当前世界中有效的动作、将目标分解为可执行子目标、从意外观察中恢复，并避免局部看似合理但无产出的死循环。
- **关键痛点**：一种常见失败模式是——高层计划在**执行阶段**退化：代理重复陈旧动作、提出当前状态下不可用的动作，或无进展地持续导航。这些问题仅靠扩增提示词难以解决，因为失败发生在"语言生成"与"环境变迁"之间的界面上。
- **研究背景**：基于Kahneman的双过程理论（快速自动认知 vs. 缓慢深思推理），SwiftSage基线已实现了"快动作提议器（Swift）+ 慢规划器（Sage）"的架构，但存在两点不足：① 缺乏持久情景记忆，无法跨回合选择性地复用关键经验；② 缺乏执行前的即时校验和停滞时的有界干预机制。
- **整体思路**：作者提出不重新设计代理，而是在SwiftSage基底上以**模块化、有界、因果可解释**的方式插入两个认知扩展——自适应记忆模块（AMM）与自我反思模块（SRM），并系统性地回答"记忆与反思应放在什么位置才能真正改善双过程智能体的交互表现"。

### 2. 论文提出的方法论：核心思想、关键技术细节

**总体架构**：保留SwiftSage控制循环，AMM与SRM插入在精确的运行时接口上。

#### （一）自适应记忆模块（AMM）——信息类扩展

- **目标**：解决持久经验复用缺失的问题。
- **写入钩子**（post-step）：在环境返回观察和分数转换后触发，构建候选情景记录；仅当**显著性门控**检测到信息丰富过渡时才入库（如：终端成功、正分数变化、接近成功、显式无效动作反馈、值得避免的失败）。
- **记忆表征**：紧凑半结构化记录，包含任务、局部状态、近期上下文、执行动作、结果观察、分数转换、类型标签（success / near-miss / avoidance），而非原始文本转录。
- **检索策略**：触发驱动而非持续注入。
  - T1：Swift失败（无法产出有效动作）→ 检索相关记忆 → 带记忆上下文重试Swift；
  - T4：Sage规划 → 检索成功/接近成功记忆辅助慢规划；
  - T2/T3：停滞与重复无效动作的检索/缓存钩子，但在AMM-only配置中不直接修改模型输入（保守设计，避免向快路径注入弱grounded的负证据）。
- **提示注入约束**：Swift只接收小块记忆块（3条），Sage可接收稍大块（5条）；模型被明确告知记忆仅为"提示"而非"权威"，当前观察、物品栏、合法动作与运行时约束始终优先。检索失败时回退到未修改的基线提示。

#### （二）自我反思模块（SRM）——控制类扩展

- **目标**：处理执行时失败（动作在语言上合理但环境中无效/陈旧/冗余）。
- **Gate–1 验证**：在动作到达环境前的最后一道检查。接收提议动作、当前合法动作集、近期状态描述与运行时约束；执行动作规范化、合法性检查、轻微不匹配时的确定性修复，不合法则丢弃（不消耗环境步）。
- **停滞检测**：每步后更新确定性诊断，跟踪重复观察、无效动作循环、无状态多样性的过度导航、动词级循环等信号；越阈时发出结构化停滞报告。
- **有界 Critic 干预**：仅在停滞被检测到且预算允许时调用；Critic输出短可执行动作列表，经解析过滤后插入与Sage共享的FIFO缓冲区（**不直接执行**，仍须过Gate–1）。调用受预算与冷却机制约束（默认每episode最多3次）。

#### （三）两者因果角色分离

- AMM是**信息性**的：改变控制器可记住和复用的证据，但从不选择最终动作；
- SRM是**控制导向**的：改变什么能到达环境、何时插入纠正动作。
- 这种分离使消融实验可解释为"证据与控制间的协作"，而非对基线的模糊重构。

### 6. 论文的主要结论与发现

- **核心结论一**：执行时控制是ScienceWorld场景中的**主导瓶颈**。Baseline+SRM分数（64.33）几乎追平完整系统（64.62），而且绝大多数成功率和效率改进由SRM贡献（成功率从23.99%提升至41.33%）。
- **核心结论二**：记忆有用但**有条件**。AMM单独仅提升4.1%的分数；但当SRM稳定执行循环后，AMM在更长轨迹上的恢复与规划中展现出更清晰的协同价值（完整系统Long组达61.69）。
- **核心结论三**：更多反思**不等于更好**。Critic预算从3增至6后，性能反而从64.33暴跌至52.95，验证了"反思必须有界"的设计原则。
- **机制归因**：性能提升不是靠更多的慢速推理（System 2调用从24.6降至14.1/集），而是让快路径更安全（Gate–1过滤无效动作）、慢路径更精准（更少的触发与干预需求）。
- **总体主张**：在交互环境中，稳健行为来自有纪律的模块化组合——**记忆提供证据，反思控制执行，基线快/慢控制器保持共享基底**。

### 7. 优点（方法与实验设计的亮点）

- **因果接口分离设计**：AMM（信息）与SRM（控制）占据不同因果位置，使消融归因明确、可解释性强，避免"黑箱式整体重构"。
- **有界设计原则**：Gate–1始终在线但代价极低，Critic仅在停滞时触发且受预算冷却约束——"廉价保护 + 昂贵修复"的分层思路具有工程可借鉴性。
- **机制级日志分析**：不仅报告最终分数，还记录写入/检索/丢弃/Critic调用等细粒度机制活动，能在分数之外解释改进来源。
- **敏感性分析完备**：单独测试了记忆初始化、反思预算、T1注入功能，使设计决策有数据支撑。
- **诚实的实验态度**：明确声明不声称SOTA，澄清与SwiftSage原论文的差异（局部模型、内存预热协议），不夸大结果。

### 8. 不足与局限

- **记忆子系统仍偏简单**：记忆为紧凑半结构化记录，检索排序和向动作改进的转换机制相对原始；尚未实现跨episode的语义整合层（如从重复经验中抽象出可复用技能），从互补学习系统角度看只覆盖了"快速情景侧"而未成熟覆盖"慢速语义侧"。
- **SRM大量手工设定**：停滞阈值、动作过滤规则、Critic预算、修复策略等均为人工设计；Gate–1对不能规范化映射的无效动作修复能力有限。
- **评估范围狭窄**：仅在ScienceWorld文本环境验证；未扩展至多模态、真实机器人动作空间或不同模型骨干；迁移性未经验证。
- **冷启动问题未充分刻画**：AMM配置采用预热内存（每个任务2个变体作为warm-up），虽然符合"经验复用"视角，但未全面表征记忆老化、遗忘、压缩等动态过程。
- **Medium任务组结果不稳定**：AMM在部分Medium任务反而造成负收益（如8-2、10-2），完整系统在该组的成功率不升反降，提示记忆效果可能存在任务类型依赖。
- **提示层面归因仍偏相关性**：机制日志能显示何时触发干预，但不能完全孤立每个提示层面的因果因素。
